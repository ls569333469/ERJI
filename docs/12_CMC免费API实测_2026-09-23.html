CMC 免费 API 实测 · 2026-09-23

结论：用户提供的免费Key可调用本次代币级衍生品市场及清算接口。 BTC/HYPE/ASTER样本中同时有Aster和Hyperliquid的USD OI，RAVE有Aster。可纳入P0聚合补充，不必把CMC限定为市值工具。

这是8次只读请求的能力验证，不是全币种、长期稳定或正式服务验收。执行时间为2026-09-23 23:25–23:33（Asia/Shanghai）。Key仅从用户指定本地文件读取，没有写入响应证据或发布文档；本次没有交易或TG发送。

必须解决的数据问题

  1. 单页也有身份冲突。 BTC单页报告193行，实际193行、192个exchange_id+market_id。Kraken同一market_id=47233的两条XBT/USD记录有不同价格和OI，不能相加，也不能任取其中一条当正确。先隔离整组，核查原生线性/反向规格与供应商映射后再纳入。完全相同的重复才直接折叠。
  2. 分页不是一致快照。 早前BTC两页共194行、193个唯一ID；请求时间不同，且已发现单页冲突，不能将差异直接归因于排名漂移。优先在允许预算下完整单页，仍校验重复、总数和时间；必须分页时记录每页时间并显示非原子覆盖。
  3. 有更新延迟。 部分记录超过10小时，HTTP200和接口60秒缓存不保证市场字段实时。逐字段质量、源年龄和汇总排除理由必须显示。
  4. 无原始OI数量。 quotes[].open_interest与exchange_reported_quotes[].open_interest为同一市场的不同响应层，不是两个市场；USD请求下作为供应商报告USD名义OI保存。样本没有原生张数、乘数或base OI，不能直接按某个price反推新开仓数量。
  5. 费率没有实际周期/结算标记。 当前funding_rate只保存vendor状态，待原生历史核对后才进入已结算序列；不能假设所有平台8H或用最新费率乘次数。报告价与转换价可能不同，index_basis也不照搬为自定义perp/index−1。
  6. 质量标记要按字段解释。 exclusions的price/volume不能直接称OI虚假；反之无flag也不证明字段准确。供应商0值保存为报告值并带来源，空字段/未返回市场则是未知。

清算接口

返回BTC/HYPE/RAVE三币，total_size=3，has_more=false，均含1H/4H/24H总额、多头和空头金额，last_updated=2026-09-23T15:25:00Z。RAVE的1H字段为0，而4H/24H非0；只能解释为供应商当次窗口报告0，不能泛化成全市场没有清算。

本接口是代币窗口汇总，没有每笔成交、地址杠杆和未来清算价。不能拿它直接绘制完整历史清算tape或未来清算热力图。窗口汇总有重叠，不能将连续两次24H数字相加。也不能与已被其统计的原生清算金额再次合计。

接入决定与未验收项

原生Binance/Hyperliquid/Aster负责高频、持仓数量、真实结算周期、K线与可成交流动性。CMC低频补跨所美元OI和清算背景，自存历史，主表明确已覆盖范围。免费预算按实际credit_count累计，70%提醒、85%降频、95%暂停非必要请求。

尚未验收按所批量接口、账户套餐/剩余额度、全部资产/平台覆盖、供应市值端点、长期稳定性、原生逐字段数值一致性和历史OI/全量清算。免费Key成功不代表以上能力自动成功。新增测试应针对这些缺口，避免无目的重复消耗额度。

可复核证据

  • 请求manifest：实际URL、HTTP、时间、credits、响应文件SHA-256。
  • 覆盖摘要：按每次响应重新计算的年龄、冲突及平台记录。
  • BTC单页原始响应、清算原始响应。其余响应同目录保留。
  • 官方衍生品文档、官方套餐。官方快照保留在research目录；实测证据优先说明本账号当前可用范围。
