# 市场范围与图表技术方案 v0.7

状态：测试 MVP 选型已确认；容量待压测　日期：2026-09-23

本稿把市场范围拆成两条候选池，并把“妖币/逼空信号”“二级市场技术信号”“策略研究”分成三个引擎。三个引擎可以在页面交叉筛选，但首版不把它们压成一个未经验证的上涨概率。

## 1. 市场范围

### 1.1 Binance 生态资产池

这是第一条主池，数据质量和身份稳定性最高，但内部必须继续分三种市场：

| 子池 | 目录来源 | 首版字段 | 重要边界 |
|---|---|---|---|
| Binance Spot | Spot `exchangeInfo`、REST/WebSocket | 交易对、状态、K 线、成交、盘口、ticker | 是已上市现货市场；默认优先 USDT/USDC 计价 |
| Binance Futures | USDⓈ-M/COIN-M `exchangeInfo`、REST/WebSocket | 永续/交割合约、K 线、OI、funding、mark/index、盘口、可得清算 | 合约和现货分开建模；OI 只属于具体合约市场 |
| Binance Alpha | Alpha token list、Alpha REST/WebSocket | token ID、链、合约地址、K 线、ticker、depth、trades | 是发现/早期代币市场，不等于 Spot 上市；没有合约 OI 就标记 `unknown` |

Binance Alpha 目前是这条链上候选池的首选发现源之一：它有官方 token list 和市场数据 SDK，稳定性、字段定义和长期接入可控程度高于抓取某个热门网站。`fomo.family`、其他 FOMO 榜或社交热度榜可以作为第二级候选输入，但必须保存 `discovery_source`、抓取时间和授权状态，不能把热榜排名当成成交量或市值事实。

Binance Alpha 的官方 SDK 已确认有以下公共能力：`token_list`、`get_exchange_info`、`klines`、`ticker`、`full_depth` 和 `aggregated_trades`，REST namespace 为 `/bapi/defi/v1/*`。Alpha 资产主键使用 `chain_id + contract_address`，`symbol` 和 `token_id` 只作为辅助字段。

同一个项目如果同时存在 Spot、Futures、Alpha 和链上池子，页面显示一个 `Asset`，下面挂多个 `Instrument`/`Pool`；不能把不同市场的 K 线拼成一根 K 线。

### 1.2 Meme / FOMO 热门资产池

这是第二条主池，服务于尚未进入 Binance Spot/Futures、但链上已经出现真实交易和关注度的代币。首版候选发现统一采用 Binance Wallet Rising；Binance Alpha 归入第一条池并按身份去重。其他数据商按缺口补充，不要求用户串联多个热门榜；最终价格与流动性以具体链上池子和交易事件为准。 `fomo.family` 可以作为人工热度参考，但不作为首版核心 API：本轮读取其公开前端代码发现，热门榜、token details 和 OHLCV 请求走 `https://prod-api.fomo.family`，请求由 Privy access token 和 `X-Supported-Chains` 保护；未认证请求返回 unauthorized。因此除非取得明确授权或稳定的公开接口，否则不抓取其内部接口，也不把页面显示当作完整市场覆盖。

建议先采用以下默认门槛，全部做成可配置参数：

- **市值：** 默认 `circulating_market_cap >= 1,000,000 USD` 才进入正式信号扫描。若供应量或流通市值不可信，显示 `unknown`，不能用 FDV 代替。
- **池子流动性：** 默认要求至少一个主要池达到可评估深度，例如 `liquidity_usd >= 100,000`；这个值需要按链和池型回测调整。
- **成交活跃度：** 默认要求最近 24 小时有真实交易，并记录成交额、买卖笔数和价格更新时间；只有报价变化没有成交不能触发启动确认。
- **安全门槛：** 合约可交易性、买卖税费、黑名单/暂停交易、代理升级和池子锁定状态进入风险检查。安全检查失败或没有结果都标记出来，不当作安全通过。
- **身份门槛：** 必须保存 `chain_id`、完整合约地址、池地址、报价币和数据来源。相同 ticker 的不同链代币不能合并。

市值 1M 是初始过滤条件，不是“低于 1M 没有机会”的事实判断。可以保留一个“低于门槛观察区”，但默认不产生高等级妖币信号，以控制蜜罐、操纵和数据噪声。

### 1.3 页面和数据分区

首页提供三个可切换范围：

1. **Binance 生态：** Spot、Futures、Alpha 分标签展示；适合稳定的二级交易和合约数据扫描。
2. **Meme/FOMO：** 只显示达到市值、池子流动性和可交易性门槛的链上候选。
3. **交叉资产：** 同一 `Asset` 同时存在 Binance 市场和链上池子时，展示跨市场价格、流动性和时间差，不合并成交量或 OI。

资产状态至少有 `listed_spot`、`listed_perp`、`alpha`、`onchain_meme`、`delisted`、`unknown`。状态变化保存历史，避免今天的目录覆盖过去的可见范围。

### 1.4 首版数量与刷新分层

用户确认两类市场：Binance Spot/Futures/Alpha，以及 Binance Wallet Rising 发现的链上 Meme/FOMO。下列数量是建议的首轮容量，不是实际在线数量或已通过限频验证的承诺：

| 范围 | 目录层 | 基础扫描目标（按资产计数） | 深度跟踪建议 |
|---|---|---|---|
| Binance Spot/Futures | 活动目录全量维护，区分现货、合约和规格 | 150–200 个资产，包含仅有现货和有永续的资产；按流动性、成交额、数据质量与新上市观察选择 | 30–50 个 |
| Binance Alpha | token list 全量维护，归入 Binance 生态池 | 最多 100 个合格候选 | 20–30 个 |
| 链上 Meme/FOMO | 保存 Rising 当次可返回的名单与参数，起始容量目标 200 个候选，不宣称覆盖全链 | 50–100 个质量合格候选；优先市值至少 $1M | 20–30 个 |

三组去重前的名额约 300–400，实际总数按资产映射后的并集统计，不预设重合数量。所有深度跟踪共用最多 80 个资产的建议预算：优先未结束事件、用户观察和新触发，再分配一般热门候选。接口预算另按 Instrument/Pool 数计费和计权重，一个 Asset 的现货和永续是两条行情。

不足合格数量时不强行补齐。超过预算的候选保留排队或低频状态，页面区分目录数、已扫描数、深度数和数据缺失数；不能把它们当信号条数。对退榜但已有事件的资产保留跟踪，直至规则结束或明确数据终止，保存入池/退池历史。

Alpha 与 Rising 按链和完整合约地址去重，市场保留独立标识。动态切换主池或交易对时，旧信号保留原池、原市场和原点位。新币历史不足不能生成需要 20/60 根完整日线的突破；可在历史足够的 1H/4H 输出独立标签，不伪造日线。

免费接口采样按来源配额执行：目录/发现低频增量，基础 K 线按闭合周期评估，重点成交优先 WebSocket，OI/Funding/持币各自按能力采样。此前 15–60 秒或更高刷新频率均为候选目标，需按“标的 × 端点 × 周期 × 权重”验证，不能保证所有链上候选同时满足。

OI 缺失不阻断有合格 K 线的技术信号；数据缺失不填零，供应未知不以 FDV 替代流通市值，高等级合约组合必须满足其独立证据门槛。

## 2. 三个信号引擎

### 2.1 异常行情与合约压力引擎

保留趋势扩张与空头成本/流动性压力两条独立路径。先核对数量OI、美元OI、覆盖、实际资金费周期、现货主动成交与同市场价差，再输出事实标签、解释假设、反向证据和缺口。负费率不是上涨必要条件，上涨减仓不是强平证明。

生命周期与跨场口径以《08_跨平台OI与趋势信号实施方案_v0.1》为准。1H用于参与观察、4H结构阶段、1D独立长趋势；突破失败与箱体下沿失守分开。到达第一阻力后继续跟踪，不以OI下降或费率转正直接结束趋势。缺失OI不取消独立技术信号。

### 2.2 二级市场技术引擎

技术引擎可以独立运行，不要求 OI、持币或链上数据齐全。首版周期为 `1D` 结构扫描、`4H` 启动/回踩、`1H` 细化；`15m` 先用于详情和实验，不作为默认高等级预警。

基础扫描使用价格区间、已确认拐点、相对报价成交额、ATR14 和 EMA20/50 背景。圆弧底是实验候选；RSI、MACD、ADX、布林带、锚定 VWAP、Fibonacci、VPVR 先用于人工研究与对照，验证增量价值后才加入自动信号。

图表内置指标可自行添加；这与后台默认启用哪些正式信号是两件事。突破使用已闭合 K 线，需要右侧确认的极值必须记录发现延迟。

### 2.3 策略研究和回测引擎

我们可以实现一组明确、可回放的策略模板：

| 策略 | 入场示例 | 出场/风险示例 | 适用研究 |
|---|---|---|---|
| 区间突破 | 收盘突破 20/60 根高点 + ATR 缓冲 + 量比 | ATR 止损、箱体回踩失效、固定持有期 | 趋势启动 |
| 箱体突破回踩 | 突破箱体上沿，回踩不破后确认 | 跌回箱体、移动止损 | 横盘后扩张 |
| 布林带收缩扩张 | 带宽低分位后，收盘突破并放量 | ATR/中轨失守 | 波动扩张 |
| 趋势回踩 | EMA20/50 多头排列，回踩均线后重新收强 | 结构低点或 ATR 止损 | 趋势延续 |
| 区间均值回归 | 价格触及箱体边界，RSI/波动出现反向条件 | 中轨或另一边界 | 只作为对照，不与突破策略混用 |

回测必须加入手续费、滑点、资金费率、盘口可执行性、信号延迟、缺失数据和 delist 样本。报告显示净值曲线、最大回撤、收益分布、连续亏损、样本数量和时间切分，不只显示胜率。

## 3. 图表可视化方案

### 3.1 信号与 K 线联动：Charting Library 32.1.0

后台生成事件，图表展示同一事件的市场、时间和证据。事件绑定 `event_id`、`asset_id`、`price_instrument_id/pool_id`、`signal_timeframe`、`bar_open_time`、`bar_close_time`、`detected_at`、`confirmed_at`、原始证据及 `rule_version`。图表周期与事件原始周期分别保存。

1. 行情服务提供 Binance Spot/Futures/Alpha 或具体链上池的 OHLCV；一个图表对应一个市场。链上免费 K 线覆盖、历史长度和供应口径仍需逐端点实测，Rising 热榜不自动等于 K 线来源。
2. 指标服务使用已收到的已闭合 K 线计算量价结构；合约服务分别提供 OI、Funding、清算和流动性，所有证据保存来源及时间。
3. 规则满足时保存不可覆盖的事件快照：冻结区间、触发柱、确认时间和失效条件。原始行情修订使用独立修订版本，不静默改写过去的信号。
4. 点击信号卡后，图表定位到原始事件前后的一段 K 线。点击 1H/4H/1D 只改变查看尺度；4H 事件仍是 4H 事件，不会因切到 1D 被重新判为日线确认。
5. 信号标记使用 Datafeed `getMarks`，区间与点位通过 `createShape` / `createMultipointShape` 绘制。标记处显示原事件说明，信号卡展示支持/反向证据、缺失和失效条件；精确的标记点击回选卡片属于后续联动验收项，当前预览支持卡片到图表和事件时间定位。

图表 SDK 使用 `new TradingView.widget(...)`，加载本地 `charting_library.standalone.js`，配置 `library_path`、`datafeed`、`container`、中文语言和 UTC。周期使用其 resolution 编码：`60` 为 1H、`240` 为 4H、`1D` 为日线。

| 图表能力 | 实现方式 | 本 MVP 状态 |
|---|---|---|
| 历史 K 线与行情切换 | Datafeed `onReady/searchSymbols/resolveSymbol/getBars`；真实行情再实现 `subscribeBars/unsubscribeBars` | 合成 OHLCV 已接入；真实多源采集待接入 |
| 指标菜单、MA/RSI/MACD/布林带等 | 图表内置菜单和 `createStudy`；后台独立计算正式扫描指标 | 图表菜单可用；不等于全量扫描已实现 |
| 支撑/阻力、失效线 | 后台给出快照，图表 `createShape` 绘制水平线 | 演示区间上沿和失效线 |
| 箱体、斐波那契 | 图表绘图工具；自动叠加需版本化锚点和 `createMultipointShape` 适配 | 用户可试原生绘图；自动形态仍待实现和验证 |
| 信号与回放定位 | `getMarks` + `setVisibleRange`，保存精确事件时间和原始周期 | 演示事件标记、卡片切换和定位 |
| OI、Funding、清算 | 独立数据序列，可用旁置面板或自定义 study；不是把它们作为价格成交量 | 当前页面为合成旁置面板；随资产切换，原生自定义 study 待实现 |
| 收藏与布局 | 产品观察池和图表布局分开保存；布局通过 `save/load` 等 API | 观察池本机持久化；本轮不承诺布局恢复 |

一个资产可以同时显示现货主图和相关永续证据，但必须分别标注市场、报价币、时间和来源。OI 不填进现货 OHLCV，也不能把永续价格线直接当成现货成交点。无已映射合约的链上资产显示“不适用”；API 故障显示“数据缺失”，两者不同。

Lightweight Charts 保留为未来可替换图表选项。两者共用后台统一数据模型，各自需要不同的前端适配器；不能直接复用同一套图表 SDK 调用。

## 4. 可行性判断

| 能力 | 是否可完成 | 主要前提 |
|---|---|---|
| Binance Spot/Futures/Alpha 资产池 | 可以 | 三种市场独立目录和身份映射 |
| Meme/FOMO 市值 1M+ 池 | 可以 | 市值、池流动性、合约安全和价格来源可用 |
| 妖币/逼空分阶段信号 | 可以做研究版 | OI、成交、盘口、地址覆盖必须显示范围 |
| 1D/4H/1H 技术指标 | 可以 | 闭合 K 线、预热长度和参数固定 |
| 压力/支撑、箱体、斐波那契 | 可以 | 算法版本化，避免未来函数并接受误报 |
| 策略回测和前向观察 | 可以 | 自建策略执行模型，加入费用、滑点和 delist |
| 直接运行 TradingView 全部策略 | 不能直接承诺 | Charting Library 不包含 TradingView 网站的 Pine 执行与 Strategy Tester 服务 |

## 5. 建议实施顺序

1. **市场目录：** Binance Spot/Futures/Alpha 三个子池 + Meme/FOMO 链上候选，统一 Asset/Instrument/Pool。
2. **技术图表：** Charting Library 32.1.0 的 K 线、内置指标菜单、绘图交互和信号定位；自动结构识别按验证阶段接入。
3. **技术信号：** 1D 突破、4H 回踩、圆弧底候选/颈线确认，保存事件和失效条件。
4. **妖币引擎：** S1 结构和 S2 启动交叉筛选；链上低流动性资产先只做风险观察。
5. **策略实验：** 区间突破、箱体回踩、布林收缩扩张、趋势回踩四个模板，先做历史回放和前向观察。
6. **再扩展：** 公开地址池、Surf、更多链、15m 高频扫描和 S3 退潮模型。

本稿把“能不能做”与“算法是否有效”分开：图表和计算能力可以实现，压力位、箱体、斐波那契和策略的实际质量必须用固定历史样本、反例和前向数据验证，不能因为画出来就宣称有效。

## 6. v0.7 总览与证据层



默认浅色、全宽、一币一行。两视图共用筛选、收藏、事件与详情：

| 层次 | 展示 |
|---|---|
| 信号判断（默认） | 代币/当前价格、结构与阶段、已覆盖 OI 金额、数量变化4H、明确平台的费率与周期、合约判断、关注区、收盘确认条件、突破撤销线、图表入口 |
| 合约数据 | 已覆盖 OI、1H/4H/24H 数量变化、美元变化4H、OI/流通市值、主要持仓平台与占比、4H已结算空头支付项、已观测清算、数据覆盖 |
| 图表与证据 | 同一事件箱体、确认/撤销标记、回踩带、结构下沿；平台逐项 OI/占比/数量变化/费率/成本/基差/时间；现货接力、缺口、多周期后续与清算区状态 |

金额用 USD/M/B，但说明中文单位。涨价与减仓不统一涂成“利好”。总览筛选可看全部、技术、合约、风险、缺失数据，主表单行不塞长段落。每个字段有通俗说明，缺失不显示 0。

图表继续用已采用的 Charting Library 32.1.0；后台 TA-Lib/确定性规则负责指标与信号，Datafeed 负责送行情。图表、文字、点位与副图由同一事件快照驱动；查看周期变化不重新计算原事件。图表指标菜单不等于 Pine Script、会员策略或 Strategy Tester，选中的策略仍需本地实现与验证。

当前 HTML 实现表格视图、筛选排序、缺失/覆盖状态、平台明细、静态成本证据、事件点位与真实图表库加载；行情、OI、费率为明确标注的合成样本。OI 时间序列副图、真实清算地图、实时采集、自动信号与回测结果仍待实现，不将静态快照假装成序列。
