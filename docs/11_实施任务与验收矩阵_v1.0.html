ERJI 实施任务与验收矩阵 v1.0

实施基线：2026-09-23。配合最终PRD使用。表中是待开发工作，不是完成清单；本轮完成的是需求、API样本验证和文档。已有图表运行验证及v0.7演示作为输入。

开发顺序

先用少量真实币打通目录→K线/OI→计划→表格/图层→通知的完整路径，再扩容到300–400扫描名额、80深度资产。M1积累历史时可并行推进M2，但未经验证的字段不能靠合成值填进真实模式。

首个可运行交付

M0建立完整路由与模型，M1先接少量Binance+Hyperliquid+Aster市场及CMC；M2用已有fixture复算，再接真实采集。首个演示必须区分真实字段、历史回放和缺失，不将旧合成页面当实盘。CMC当前样本不必重复请求；新增探针只针对尚未验证的批量、供应和规格问题。

优先测试：数量恒定但价格变化、1000倍合约、同ID冲突、覆盖变更、结算周期改变、缺K线、箱体假突破、目标先被穿越、信号过期、进程重启、TG未知发送结果。测试验证业务语义，避免只断言代码自身常量。

阶段验收

27项验收定义以PRD §14为唯一原文；每次完成记录commit、配置版本、数据fixture/时间范围、实际结果及缺口。页面可用和接口200只能证明相应能力，不能代替信号收益验证。

M5先运行7天验收数据质量与故障恢复，再累计足够的行情/失败样本评估收益。7天不是策略盈利认证。免费额度不足先减频/减池，保留已有事件保护监测，不自动购买套餐。
