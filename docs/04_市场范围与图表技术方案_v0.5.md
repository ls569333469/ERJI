# 市场范围与图表技术方案 v0.5

状态：讨论稿　日期：2026-09-23

本稿把市场范围拆成两条候选池，并把“妖币/逼空信号”“二级市场技术信号”“策略研究”分成三个引擎。三个引擎可以在页面交叉筛选，但首版不把它们压成一个未经验证的上涨概率。

## 1. 市场范围

### 1.1 Binance 生态资产池

这是第一条主池，数据质量和身份稳定性最高，但内部必须继续分三种市场：

| 子池 | 目录来源 | 首版字段 | 重要边界 |
|---|---|---|---|
| Binance Spot | Spot `exchangeInfo`、REST/WebSocket | 交易对、状态、K 线、成交、盘口、ticker | 是已上市现货市场；默认优先 USDT/USDC 计价 |
| Binance Futures | USDⓈ-M/COIN-M `exchangeInfo`、REST/WebSocket | 永续/交割合约、K 线、OI、funding、mark/index、盘口、可得清算 | 合约和现货分开建模；OI 只属于具体合约市场 |
| Binance Alpha | Alpha token list、Alpha REST/WebSocket | token ID、链、合约地址、K 线、ticker、depth、trades | 是发现/早期代币市场，不等于 Spot 上市；没有合约 OI 就标记 `unknown` |

Binance Alpha 目前是这条链上候选池的首选发现源之一：它有官方 token list 和市场数据 SDK，稳定性、字段定义和长期接入可控程度高于抓取某个热门网站。`fomo.family`、其他 FOMO 榜或社交热度榜可以作为第二级候选输入，但必须保存 `discovery_source`、抓取时间和授权状态，不能把热榜排名当成成交量或市值事实。

Binance Alpha 的官方 SDK 已确认有以下公共能力：`token_list`、`get_exchange_info`、`klines`、`ticker`、`full_depth` 和 `aggregated_trades`，REST namespace 为 `/bapi/defi/v1/*`。Alpha 资产主键使用 `chain_id + contract_address`，`symbol` 和 `token_id` 只作为辅助字段。

同一个项目如果同时存在 Spot、Futures、Alpha 和链上池子，页面显示一个 `Asset`，下面挂多个 `Instrument`/`Pool`；不能把不同市场的 K 线拼成一根 K 线。

### 1.2 Meme / FOMO 热门资产池

这是第二条主池，服务于尚未进入 Binance Spot/Futures、但链上已经出现真实交易和关注度的代币。候选发现来源包括 Binance Alpha、DexScreener、GeckoTerminal、CMC、CoinGecko 和 Surf；最终价格与流动性以具体链上池子和交易事件为准。 `fomo.family` 可以作为人工热度参考，但不作为首版核心 API：本轮读取其公开前端代码发现，热门榜、token details 和 OHLCV 请求走 `https://prod-api.fomo.family`，请求由 Privy access token 和 `X-Supported-Chains` 保护；未认证请求返回 unauthorized。因此除非取得明确授权或稳定的公开接口，否则不抓取其内部接口，也不把页面显示当作完整市场覆盖。

建议先采用以下默认门槛，全部做成可配置参数：

- **市值：** 默认 `circulating_market_cap >= 1,000,000 USD` 才进入正式信号扫描。若供应量或流通市值不可信，显示 `unknown`，不能用 FDV 代替。
- **池子流动性：** 默认要求至少一个主要池达到可评估深度，例如 `liquidity_usd >= 100,000`；这个值需要按链和池型回测调整。
- **成交活跃度：** 默认要求最近 24 小时有真实交易，并记录成交额、买卖笔数和价格更新时间；只有报价变化没有成交不能触发启动确认。
- **安全门槛：** 合约可交易性、买卖税费、黑名单/暂停交易、代理升级和池子锁定状态进入风险检查。安全检查失败或没有结果都标记出来，不当作安全通过。
- **身份门槛：** 必须保存 `chain_id`、完整合约地址、池地址、报价币和数据来源。相同 ticker 的不同链代币不能合并。

市值 1M 是初始过滤条件，不是“低于 1M 没有机会”的事实判断。可以保留一个“低于门槛观察区”，但默认不产生高等级妖币信号，以控制蜜罐、操纵和数据噪声。

### 1.3 页面和数据分区

首页提供三个可切换范围：

1. **Binance 生态：** Spot、Futures、Alpha 分标签展示；适合稳定的二级交易和合约数据扫描。
2. **Meme/FOMO：** 只显示达到市值、池子流动性和可交易性门槛的链上候选。
3. **交叉资产：** 同一 `Asset` 同时存在 Binance 市场和链上池子时，展示跨市场价格、流动性和时间差，不合并成交量或 OI。

资产状态至少有 `listed_spot`、`listed_perp`、`alpha`、`onchain_meme`、`delisted`、`unknown`。状态变化保存历史，避免今天的目录覆盖过去的可见范围。

### 1.4 首版数量与刷新分层

数量按“目录、正式信号、深度跟踪”分开计算。目录用于发现和身份维护，正式信号才运行完整规则，深度跟踪才使用更高频的成交、盘口或地址数据：

| 范围 | 目录 | 正式信号 | 深度跟踪 |
|---|---:|---:|---:|
| Binance Spot/Futures | 活动交易对全量 | 150–200 个线性永续及对应现货 | 30–50 个资产 |
| Binance Alpha | 官方 token list 全量 | 约 100 个候选，质量过滤后触发信号 | 20–30 个 |
| Meme/FOMO 链上 | 每次快照最多约 200 个候选 | 50–100 个市值/流动性/交易/安全门槛通过者 | 20–30 个池 |

Alpha 与其他链上发现源按 `chain_id + contract_address` 合并；首版去重后约 200–300 个资产/市场组合进入正式规则，约 50–80 个进入深度跟踪。这个数量是容量起点，须以 7 天限频、延迟和缺失率观测调整。

## 2. 三个信号引擎

### 2.1 妖币/逼空引擎

目标是发现“供应约束、衍生品拥挤和流动性脆弱同时出现”的候选，而不是判断某个团队已经操盘。信号分三阶段：

- **S1 结构观察：** 持币/实体集中度、有效流通情景、OI 相对流通估值、负 funding 或贴水、卖盘深度和买入冲击成本。
- **S2 启动确认：** 收盘突破或真实成交、现货买压、跨市场跟随、盘口被成交消耗、可见空头减少或实际清算事件中至少两类独立证据同步。
- **S3 持续/退潮：** 新仓与回补、资金费率、现货承接、交易所流入、价差、盘口恢复和集中实体变化。

每个信号显示支持证据、反向证据、覆盖范围和缺失数据。没有完整地址覆盖时只能写“已观察地址集合”，不能写“全市场空头仓位”。

### 2.2 二级市场技术引擎

技术引擎可以独立运行，不要求 OI、持币或链上数据齐全。首版周期为 `1D` 结构扫描、`4H` 启动/回踩、`1H` 细化；`15m` 先用于详情和实验，不作为默认高等级预警。

首版指标和规则：

- EMA/SMA：20、50、200 趋势和均线排列。
- RSI、MACD、ATR、布林带宽度和量比。
- 20/60 根已闭合 K 线高低点突破。
- 横盘箱体：波动收缩、上下沿多次触及、区间宽度相对 ATR 稳定。
- 突破后回踩：保存原突破位，观察收回、守住或跌破。
- 圆弧底候选：左侧下跌放缓、宽底、右侧修复、靠近颈线；只有闭合 K 线越过颈线才确认。
- 斐波那契回撤/扩展：只使用已经确认的 swing high/swing low，显示锚点时间、方向和规则版本。

突破、形态和指标都使用已闭合 K 线；需要右侧 K 线确认的极值必须把发现时间延迟，不能用未来数据回填历史信号。

### 2.3 策略研究和回测引擎

我们可以实现一组明确、可回放的策略模板：

| 策略 | 入场示例 | 出场/风险示例 | 适用研究 |
|---|---|---|---|
| 区间突破 | 收盘突破 20/60 根高点 + ATR 缓冲 + 量比 | ATR 止损、箱体回踩失效、固定持有期 | 趋势启动 |
| 箱体突破回踩 | 突破箱体上沿，回踩不破后确认 | 跌回箱体、移动止损 | 横盘后扩张 |
| 布林带收缩扩张 | 带宽低分位后，收盘突破并放量 | ATR/中轨失守 | 波动扩张 |
| 趋势回踩 | EMA20/50 多头排列，回踩均线后重新收强 | 结构低点或 ATR 止损 | 趋势延续 |
| 区间均值回归 | 价格触及箱体边界，RSI/波动出现反向条件 | 中轨或另一边界 | 只作为对照，不与突破策略混用 |

回测必须加入手续费、滑点、资金费率、盘口可执行性、信号延迟、缺失数据和 delist 样本。报告显示净值曲线、最大回撤、收益分布、连续亏损、样本数量和时间切分，不只显示胜率。

## 3. 图表可视化方案

### 3.1 可以直接完成的图层

`TradingView Lightweight Charts` 可以承载 K 线、成交量、指标线、标记和自定义绘图。以下都可以在我们的应用中实现：

- **压力位/支撑位：** 基于确认 pivot、历史密集触及和 ATR 容差聚类，画水平线或带宽区域；显示来源、触及次数、首次发现时间和失效时间。
- **箱体：** 画矩形区域，标注箱体上沿、下沿、宽度、持续 K 数、触及次数和突破状态。
- **斐波那契：** 画 0、0.236、0.382、0.5、0.618、0.786 及 1.272/1.618 扩展线，显示两个锚点和计算方向。
- **均线和波动带：** EMA/SMA、布林带、ATR 通道、VWAP、Donchian 通道。
- **信号标记：** S1/S2/S3、技术突破、回踩、失效、清算事件和策略入场/出场点。
- **多面板：** 价格、成交量、OI、funding、主动买卖量、资金和数据质量分面板展示。

每个绘图对象保存为结构化 JSON，例如：

```json
{
  "type": "support_resistance_zone",
  "instrument_id": "binance:futures:XYZUSDT",
  "timeframe": "1d",
  "price_low": "0.95",
  "price_high": "1.02",
  "detected_at": "2026-09-23T00:00:00Z",
  "touch_count": 4,
  "rule_version": "sr-v1",
  "status": "active"
}
```

### 3.2 TradingView 的边界

我们核验过的 TradingView Advanced Charts/Charting Library GitHub 副本不能直接当作开源授权组件。当前工程基线是 Lightweight Charts，因此：

- 可以做 TradingView 风格的图表和叠加层；
- 可以自己实现指标、水平位、箱体、斐波那契、信号标记和回测结果；
- 不能直接把 TradingView 网站上的全部 Pine 策略、Strategy Tester 或 Auto Chart Patterns 当成可调用 API；
- 任意 Pine Script 自动导入和执行需要单独的语言兼容层与授权评估，不放入首版。

TradingView 可以作为人工对照和规则灵感来源，但信号在本系统中必须由我们保存的 K 线和明确规则重新计算。

## 4. 可行性判断

| 能力 | 是否可完成 | 主要前提 |
|---|---|---|
| Binance Spot/Futures/Alpha 资产池 | 可以 | 三种市场独立目录和身份映射 |
| Meme/FOMO 市值 1M+ 池 | 可以 | 市值、池流动性、合约安全和价格来源可用 |
| 妖币/逼空分阶段信号 | 可以做研究版 | OI、成交、盘口、地址覆盖必须显示范围 |
| 1D/4H/1H 技术指标 | 可以 | 闭合 K 线、预热长度和参数固定 |
| 压力/支撑、箱体、斐波那契 | 可以 | 算法版本化，避免未来函数并接受误报 |
| 策略回测和前向观察 | 可以 | 自建策略执行模型，加入费用、滑点和 delist |
| 直接运行 TradingView 全部策略 | 不能直接承诺 | Lightweight Charts 不含 Pine/Strategy Tester；需另做兼容层 |

## 5. 建议实施顺序

1. **市场目录：** Binance Spot/Futures/Alpha 三个子池 + Meme/FOMO 链上候选，统一 Asset/Instrument/Pool。
2. **技术图表：** K 线、EMA/RSI/MACD/ATR/布林带、支撑阻力和箱体；先加入手工锚点斐波那契，再做自动 swing 版本。
3. **技术信号：** 1D 突破、4H 回踩、圆弧底候选/颈线确认，保存事件和失效条件。
4. **妖币引擎：** S1 结构和 S2 启动交叉筛选；链上低流动性资产先只做风险观察。
5. **策略实验：** 区间突破、箱体回踩、布林收缩扩张、趋势回踩四个模板，先做历史回放和前向观察。
6. **再扩展：** 公开地址池、Surf、更多链、15m 高频扫描和 S3 退潮模型。

本稿把“能不能做”与“算法是否有效”分开：图表和计算能力可以实现，压力位、箱体、斐波那契和策略的实际质量必须用固定历史样本、反例和前向数据验证，不能因为画出来就宣称有效。
