1. 本次决定

保留两条独立路径：趋势扩张与空头成本／流动性压力。它们可叠加、可先后出现，不能要求所有上涨都先有深负费率。没有 OI 的币仍可生成合格技术信号。妖币是研究范围，页面使用可核对的事实标签，不使用竞品代号或“庄家已控盘”。

数据流程：资产与合约身份映射 → 采集及原始记录 → 时间、单位、覆盖检查 → 各市场独立计算 → 同资产跨场汇总 → 事实标签 → 价格触发 → 冻结事件快照 → 总览与图表 → 持续跟踪、失效与研究回放。

3. OI 统计与质量门槛

3.1 数量、金额和价格分开

每个 instrument 保留原始单位/张数、合约乘数、线性或反向、标准化 base 数量、美元名义持仓、mark/index/换算价格与时间。只统计一次未平仓合约，不能把多头加空头再乘二。OI 不是保证金、资金净流入或杠杆倍数。

线性合约 N = Q × P。同一市场集合两端对齐，显示数量变化 (Q1/Q0−1) 与美元变化 (N1/N0−1)。跨市场用 ΣQi 与 ΣNi；需同资产、合约规则兼容、时间误差门槛通过。反向合约不能简单以 USD/当前价变化判断新开仓，保留张数或固定参考价格敞口单列；无法等价比较时不合并数量变化标签。

对线性集合可解释名义变化：数量贡献 Σ[(Q1−Q0)×P0]，估值贡献 Σ[Q1×(P1−P0)]，两者合计名义变化。不是新增资金贡献，明确分解采用的先后约定。

支持 1H／4H／24H、起止时间与 freshness。当前总额与变化窗口的市场集合不同，必须分别展示；覆盖新增/丢失不能算增减仓。首版采取严格固定集合，覆盖变化时该窗口变化显示“覆盖变化，暂停比较”，金额保留合格已覆盖值与覆盖名单。

3.2 相对规模与异常程度

  • OI / 同期流通市值：名义持仓密度，显示美元分子、流通市值/供应量来源、对应价格与更新时间。没有可信流通量则为空，不以 FDV 替代。
  • 撤销 3%／10%／25% 等通用风险档。比例超过 100% 不自动等于刷量、控盘或必然轧空。
  • 历史分位：同币、同窗口、同覆盖，附基线区间、有效样本数、观察频率与缺口；同组分位须说明分组。第 95 分位不是 95% 上涨概率。
  • OI/成交额说明存量相对期间换手；成交不是资金净流入。OI/深度与冲击成本反映流动性敏感性，撤单与滑点会改变结果，不能推出涨幅上限。
  • 自由流通估值仅做有依据的多情景研究，不能简单“总量减 Top10”。数量 OI/供给与美元 OI/市值高度相关，不能重复计分。
  • 市场质量：单位错误、重复供应商、错币、时间错位、长时间不更新、单所突变与其他所不一致均先检查。成交量大或清算少不是 OI 造假比例的证明。

3.3 数据缺失语义

fresh 正常；stale 过期；missing 已映射但接口无值；unmapped 身份未确认；no_market_in_scope 当前已查目录无匹配；coverage_changed 集合改变；insufficient_history 历史不足。它们都不能显示为 0。“无匹配”只限定已查范围，不写“全球没有合约”。

4. 费用、成交和清算证据

资金费每平台分别显示最新已结算费率、实际周期、预测费率（独立字段）、连续负费率时长与结算次数。周期可能从 8H/4H 改成 1H。相同结算时间段可计算 1H／4H／24H 的已结算费率和、空头支付项之和与对侧收入；不以最近一期乘 24 补历史。观察期内没有结算记录不等于费率为零。

对固定美元名义本金的参考空头，负费率的支付项为 max(-r,0)；净费用还需抵扣正费率收入。实际固定币数持仓需逐次 数量×结算mark×费率 计算。标准化成本指数不是某用户真实亏损，也不是自动复利收益。总览展示明确平台的代表性费率，优先选择负费率成本最明显的合格样本；不将不同周期单次值混合平均。

价差分开显示合约成交价、现货成交价、mark、index；默认合约/index 基差为 (perp_last/index−1)，必须注明公式、同一时点和来源，不能混用 mark/index 的 premium。跨平台共振看方向和时间，先排除陈旧价格、孤立针与指数偏离。

主动成交：现货与永续分别统计同窗口的主动买额、卖额、差额及 CVD，标记重置点与覆盖；K 线 2×taker_buy_quote−quote_volume 是成交主动性差额，不是净流入。合约主动卖出、数量 OI 增而价格不跌，可以形成待验证压力假设，不能认定吸筹完成。

清算必须区分已观测事件与估算分布。记录方向、金额、窗口、来源、事件 ID、订单/成交/快照语义、重复消除及采样缺口。只出现上涨+数量 OI 下降，标签为“上涨伴随持仓减少，解除原因待核”；观察到部分空头清算也不能把全部减仓归因强平。OI 增加时仍可能同时发生清算，被新仓盖过。

账户多空比只表示统计样本内的账户数；大户持仓比也是特定样本，不当全市场金额比例。“大额爆仓少”也可能因为主动退出、低杠杆或漏报。主动平空、套保退出、费用挤压、强制清算是不同机制。

供应约束采用独立持币和实体标签，剔除/标注交易所、托管、LP、桥、销毁与锁仓等地址；标签有来源和已知时间。关联钱包转入所不等于已卖出，解锁不等于立即抛售。集中度与盘口稀薄可以放大双向波动，不证明具体操纵主体。

5. 信号规则与持续跟踪

路径 / 标签 必须可见的证据 下一步与反向证据
趋势扩张：整理突破 明确周期、冻结箱体、闭合 K 线与相对报价成交额 观察回踩；收盘重新跌回箱体则撤销该次突破；不要求负费率
现货需求增强 现货主动买额、价格响应、多个已覆盖市场佐证 关注买盘能否持续；成交差额非资金流入
持仓积累，方向待定 同覆盖数量 OI 增、历史罕见程度 无方向证据时不升级为多头/空头结论
空头持有成本升高 连续已结算负费率、实际周期、合约折价 需要价格仍强；负费率但继续下跌构成反向证据
向上突破，空头承压 有效价格触发 + 仍在的费用/成交压力证据 分别列出支持、反向和缺失；不输出轧空概率
上涨伴随持仓减少 同窗上涨与数量 OI 减 回补/解除原因待核，检查现货接力
已观测空头清算 有方向明确的真实公开清算事件 标采样覆盖；不等于所有空头已被清算
再次持仓积累 清算/减仓后再增仓，高位守住，偏空证据复现 新一轮压力候选；不是无限燃料
合约追涨拥挤 数量急增、正费率成本增加、现货弱、价格滞涨 多头解除/清算风险，仍需验证门槛
下行风险 跌破明确结构、现货卖压；可叠加已观测多头清算 与上涨规则对称，不因费率负而忽略下跌

每个组合都分别输出：可观测事实、规则是否满足、解释假设、反向证据、缺失项。阈值与权重未验证时仅研究态，不做神秘总分。

生命周期：候选 → 价格确认 → 持续跟踪 → 降级／结束／失效。事实标签与交易计划的状态分开。冻结 episode_id、原市场、原结构、周期、箱体上下沿、首次触发/失效规则；新结构产生新 episode，不复活失效事件。

两条失效线必须区分：突破后按规则收回箱体上沿下方，撤销该次突破；跌破箱体下沿，表示整个箱体做多结构失守。不能用“跌破下沿”掩盖已经发生的假突破。本轮预览采用一次完整 4H 收盘判断，属于研究参数；参与确认可采用 1H 回踩收回，但不能偷换原 4H 信号确认周期。

1H 负责参与观察，4H 负责结构阶段，1D 独立跟踪大趋势。到达下一阻力只是“检验观察区”；突破后按已确认新结构更新。历史新高时显示“价格发现，上方缺乏历史阻力”。旧 4H 信号失效不能临时改日线挽救；大周期趋势可独立仍在，并保留原失效记录。

不以到达第一目标、OI 下降、费率转正或清算减少自动判定见顶。后续监测现货需求接力、确认低点抬升、仓位重新积累、费用持续性与潜在供应增加。发行到峰值、首次可监测到峰值、首次有效信号后的可成交表现分别计算，不把 100X 事后涨幅当策略收益。

6. 清算集中区与上涨空间

永续合约没有可由总 OI 算出的唯一“最大痛点”。期权 Max Pain 不适用。产品可支持最近清算集中区、给定价格范围内最大集中区、到某价的累计潜在清算规模，但前提是有公开仓位集合或明确估算模型。

每区必带：市场及 mark 计价口径、可见地址/仓位覆盖、价格搜索范围、分箱宽度、估算时间、假设、数据来源与过期条件。Hyperliquid 可见清算价会随追加保证金、资金费、全仓其他仓位盈亏变化；CEX 总 OI 不能还原所有人的入场与杠杆。未获取时显示“暂无可验证清算区”，不造目标价或热力图。

技术阻力与清算区在图上使用不同图层。前高、箱体、成交分布可提供下一观察区；到该区的距离、到失效线的距离与成本后风险收益比可以显示，前提是同市场、同计划、可成交性明确。它们不是最终顶部或会涨多少倍的承诺。

对照实验：仅价格突破；加数量 OI；加费率/基差；加现货主动成交。报告指标增量价值、样本数、提前量、误报率、MFE/MAE、触发后1H/4H/24H表现、最大回撤、可执行容量、手续费/滑点/资金费后结果。先观察信号与历史回放，再前向纸上验证，通过后才升交易策略。不能照搬 X 文章的短期胜率、刷 OI 比例或操盘归因。

9. 验收

  1. 币数不变价格涨20%：数量变化0，美元变化20%；页面不称新增20%仓位。
  2. 1000倍、反向与线性单位正确；身份映射模糊时禁止合并。
  3. CMC与原生同 instrument 不双算；多空双方不双算；平台占比基于明确已覆盖分母。
  4. 新增/失去平台时暂停该窗口增长判读；stale排除当前合计并显示范围变化。
  5. 正确区分无匹配、缺失、过期、历史不足；OI缺失不取消技术信号。
  6. 1H/4H/8H与中途结算频率改变正确逐次累加；预测值不混入已结算成本。
  7. 上涨减仓但无清算tape，不显示已爆空；有清算而净OI增仍保留真实事件。
  8. 突破失败和箱体下沿失守分别标记；旧事件不复活，切图表周期不改冻结点位。
  9. 无清算分布数据不画虚构痛点；先前技术阻力不当上涨终点。
  10. 留出、负样本、成本和前向验证未通过，保持研究态，不显示未经校准概率。

完整历史讨论追踪见《09_OI讨论覆盖清单》，研发按条验收，避免只更新页面文案而丢掉数据语义。

7.2 K线口径、预热与扫描周期

P0扫描周期建议 1D、4H、1H，图表同时保留5m/15m。日K默认使用 UTC 00:00 开盘口径，UTC日线收盘对应北京时间次日08:00。1D代表一根自然日K线，不是滚动24小时。保留源端时间边界；不兼容来源需用同市场完整小周期数据重采样，或者明确标示不可比较。

现货日线用于现货结构，永续日线用于该合约结构，默认参考市场可切换。不同市场不拼成一条K线；CMC的聚合币价不能代替“某交易所某交易对的日线”。只能聚合同市场连续小周期K线，缺口不能填造OHLCV。

基础配置预热ATR14、EMA20/50和20根成交额基线；候选扩展另保存参数。递推指标需额外预热并验证收敛，不以刚达到指标周期长度视作稳定。扫描同一规则时固定数据起点策略、缺口处理和库版本；历史不足显示不可计算。

收盘型规则只使用截止评估时已经收盘且已收到的数据。跨周期信号也必须满足各自收盘时间，不能将当日尚未收盘的日线确认状态用于4H历史回放。每天扫描不需全天反复拉取完整历史，闭合时增量计算即可。

7.4 “某代币1D突破”的具体规则示例

“1D突破”必须说明突破对象。首版先提供“20日高点”“60日高点”和“经识别的平台上沿”三种，可选放量过滤。

以20日高点为例，令 t 为最新已收盘日K：

R_t = max(high[t-20], ..., high[t-1])
buffer_t = 0.25 × ATR14[t-1]
日线突破 = close[t] > R_t + buffer_t
放量倍数 = quote_volume[t] / median(quote_volume[t-20:t])
放量突破 = 日线突破 且 放量倍数 >= 1.5

20、0.25、14、1.5 均为演示配置，需回测与前向验证；历史20根必须已闭合且不包含 t。若量能缺失，可输出价格突破，但不能输出放量确认。可将“在均线上方”“跨市场跟随”作为可选筛选；OI不作为技术突破的必需字段。

示例：此前20日最高1.00 USDT、ATR14为0.08，确认门槛1.02；最新日K收1.04且成交额为历史中位数的1.8倍，则命中这条演示规则。盘中最高到1.08、最终收0.99，只能保留盘中预警及其撤销记录，不能确认日线突破。

生命周期：盘中预警（可选，允许撤回）→ 收盘确认 → 持续/回踩观察 → 失效/结束。确认后保存当时突破位、区间与缓冲，不能每日移动压力位来重写旧信号。新高持续期间不重复发送首次突破通知；重新形成独立区间或旧事件结束后才生成新事件。

7.5 圆弧底的识别方法

圆弧底是多根K线形成的结构，不能仅凭一条均线向上、一个二次函数拟合良好或MACD金叉判定。建议先在1D/4H上扫描40至120根已闭合K线的多个窗口，窗口长度仅作起始研究范围。

  1. 形状候选： 对数价格归一化后，检查左侧下行、底部变平、右侧上行；底部需要持续宽度，排除单根极端插针和V形急反弹。用稳健拟合及分段斜率辅助，保留拟合残差与原始图形。
  2. 结构约束： 底部深度、左右两侧持续时间、修复比例和中间反弹幅度需要在明确范围内；不强求完美左右对称。下跌中短暂反弹也可能呈U形，要用后续颈线状态区分。
  3. 颈线/压力区： 由截至发现时已经确认的左侧高点、历史密集阻力或箱体上沿定义；展示实际使用的边界和算法版本，禁止根据后续最高价倒推颈线。
  4. 量能证据： 左侧衰减、底部低量、右侧回升和突破放量分别标记，作为支持条件；缺量不能解释为已满足典型量价关系。
  5. 状态更新： 右侧尚未越过压力区只称“候选”；收盘越过颈线与缓冲后才标“圆弧底颈线突破”；随后跌破结构低点或满足预设失效条件时结束。

平滑、极值和支撑压力算法不得偷看未来。若高低点需要右侧k根确认，发现时间必须延迟k根；禁止用居中平滑或会回填历史转折的ZigZag结果冒充当时可见信号。保存 shape_start、shape_end、detected_at、confirmed_at、neckline、rule_version 和证据快照；回放中只能从 detected_at 起计告警表现。

形态候选可随新K线调整，但已发出的历史事件不覆盖。人工标注多种圆弧底和相似反例，分别评估“形状是否符合定义”和“突破后的价格表现”；形态匹配度不是上涨概率。

用户可选“技术独立”或“技术与资金交叉”。例如“1D平台突破 + 4H回踩守住”属于跨周期技术组合；“圆弧底颈线突破 + OI数量异常 + 持续负费率”属于技术与资金组合。每一项保留自己的状态、时间与来源，资金缺失不取消已满足的技术信号。

7.7 历史相似形态：独立P1功能

历史相似区间搜索可先支持 BTC 和 ETH 的1h/4h/1D，再扩展其他币种；不限制前述技术扫描的币种范围。用户选择回看20或40根、观察后续10或20根，输入可包含归一化路径、波动、量能和指标，返回相似区间、相似度定义及后续分布。

候选的完整匹配窗口与后续窗口必须早于当时决策时间，并设置间隔避免与查询窗口重叠。训练、调参和测试按时间切分，处理下架与幸存者偏差。不把相似度直接称上涨概率；如提供统计概率，需注明样本数、统计方法和验证区间。

7.8 指标与正式信号的边界

指标是数值；标签是规则对数值的描述；信号是带时间、条件、点位和失效逻辑的事件；策略还需定义仓位、执行、费用和退出。四者不得混为一谈。“规则已确认”只表示可复算条件满足，不等于收益已经确认。

7.9 科学验证与启用门槛

  1. 先写事件定义和评价期限。例如比较未来固定根数内是否先达到预定ATR目标还是失效线，同时报告最大有利/不利偏移。具体倍数和期限在实验前登记，不能在结果出来后换定义；同根K线同时触及目标和失效线时，用更细数据或保守记为顺序未知。
  2. 建立最简基线：仅价格区间突破。逐次加入量能、趋势、OI、费率/清算、流动性及候选指标，对照相同资产、相同可见数据和相同事件期限，报告加入后误报、漏报、提前量和不利波动的变化。
  3. 按时间做训练/调参/留出测试，重叠事件做隔离；覆盖震荡、涨跌、不同流动性及下架样本。不能用本轮Rising赢家的现有名单回测过去全市场，也不能用现在供应量解释过去OI比值。
  4. 报告全样本数量、数据缺失、结果区间及所尝试配置数；检查是否只在少数币上有效。提高筛选后命中率的同时要报告覆盖和漏报，多个相关指标不得当作独立样本。
  5. 独立测试后做连续前向观察，并保留失败样本；OI、盘口和清算没有历史就从现在记录，不能由K线编造历史。数据不足的扩展先停留在研究状态。
  6. 决定是否保留指标看预先约定的增量价值及稳定性，不按指标数量或漂亮分数决定。未完成以上步骤前，所有组合均称研究规则；若输出模拟策略收益，还要计入滑点、手续费、资金费率及实际可成交性。

“链上现货筹码”与“链上永续交易所”是两种数据维度。首版需要分析已上市合约资产的筹码，不等于首版必须扫描所有刚发射的 Meme。无合约的早期代币另走 FR10；不要求它们具备 OI。Aster 私密账户不得显示成公开巨鲸仓位，FR13 与 FR15 按平台能力分别验收。

12.1 观察池与告警

观察池保存收藏、备注、加入时价格和当时信号版本，可设置特定来源或任一来源触发提醒。告警中心区分首次触发、持续中、升级、风险加剧、恢复和结束，展示触发次数和首次触发位置。

推送至少包含资产、市场、来源、触发时间、关键数值、数据是否延迟及详情链接。通知授权由用户在产品内主动开启；Telegram、邮件或 Web Push 选一条先实现。静音与隐藏状态跨刷新保留，传输失败应重试并记录，不重复生成新的信号事件。

12.2 历史信号与表现

历史页可按触发日期、规则版本和交易所检索，默认展示所有已经产生的信号，不只展示盈利案例。展示首次信号后 15m、1h、4h、24h 的价格变化、最大有利偏移和最大不利偏移；到期、未到期、缺失和下架分别计数。

只有在展示的是实际或严格模拟交易时才使用“收益率”“胜率”字样。纯价格跟踪标注为“告警后价格表现”，不计入未发生的成交，也不把样本最高价视作可实现卖出价。

12.3 架构与内部接口

建议采用 Next.js 前端，Python 异步采集和规则服务，PostgreSQL 保存归一行情、信号和审计记录；Redis 在有队列、缓存或限流协调需求时加入。时间序列扩展在数据量证明需要后再启用。前端 K 线采用成熟组件，避免首版自研图表引擎。

数据链路为“交易所与数据商适配器 → 原始数据缓存 → 身份与单位标准化 → 质量检查 → 特征计算 → 信号事件 → REST 与推送 → 网页”。原始指标与衍生特征保留来源血缘。单个来源故障不使整个列表停摆，切源后不能延续不可比较的增幅曲线。

内部接口示例 用途
GET /v1/assets 资产目录、身份和可用市场
GET /v1/instruments 交易对和合约规格
GET /v1/radar 信号列表及分页筛选
GET /v1/candles 指定来源、市场、周期和时间范围的 OHLCV

GET /v1/chart-overlays 指定事件的支撑/阻力、箱体、斐波那契、标记和副图数据；与 event_id 绑定
GET /v1/signals/{id} 事件详情、规则版本和证据快照

12.4 非功能要求与成本控制

新鲜度目标为：K 线收盘后 90 秒内完成正常来源的信号评估；网页读取缓存的 P95 响应在目标部署环境下小于 1 秒。目标须通过真实部署测量，接口限流和来源中断期间展示降级状态，不假装满足 SLA。

价格与成交量优先批量或 WebSocket，按字段单独调度 OI、资金费率、身份元数据和 AI。采用每来源独立的权重预算、指数退避、抖动、失败隔离与恢复补数。先为观察池和高流动性标的分配刷新预算，不能为追求速度绕过上游限额。

敏感 API Key 仅在服务端管理，日志和浏览器响应不得包含密钥。读取公开行情与交易执行权限分离。用户可导出或删除自己的收藏、备注和通知设置。公开提供服务前核实行情再分发、缓存和商业展示许可。

预算模型至少包含行情请求与订阅、历史存储、计算服务、AI 查询、通知及运维。免费优先方案先使用 Binance/OKX/Gate/Bitget、Hyperliquid、Aster 的公共接口并自建历史快照，CMC免费Key衍生品做低频覆盖核对；其他可选服务按实际免费额度研究验证。每源按“标的数 × 端点数 × 刷新次数 × 权重”估算，不能用一个固定调用数覆盖所有接口。付费服务先做小额度试用和月度上限，再扩大覆盖；免费接口也必须记录共享配额、限流和再分发条款。
