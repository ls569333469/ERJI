# 指标与信号标签方案

版本 v0.1　日期：2026-09-23　状态：研究规则，未宣称已验证收益

本文件把指标、事实标签、信号事件和策略分开，作为 `01_产品需求文档_v0.5.md` 的可执行口径。所有规则都必须保存数据来源、时间窗口、参数、版本和缺失状态。任何“异常”“偏高”或组合规则，在通过时间切分的历史回放和前向观察前，只能显示为研究标签。

## 1. 基础指标层

P0 只保留有明确口径、可复算且信息重复较少的指标：

| 层 | 指标/规则 | 用途 | 边界 |
|---|---|---|---|
| 价格结构 | 20/60 根高低点、确认拐点、区间/平台 | 定义突破位置和失效位置 | 只用已闭合 K 线；当前柱不得进入基线 |
| 量能 | 报价成交额 ÷ 前 20 根同周期中位数 | 描述参与规模变化 | 不能单独推断买入、建仓或方向 |
| 波动 | ATR14、ATR/价格、区间宽度 | 比较波动和设定缓冲 | 不预测方向 |
| 趋势背景 | EMA20/50 位置与斜率 | 描述趋势背景 | 不把均线交叉自动当作机会 |
| 合约状态 | OI 数量、OI 名义值、Funding/基差、已观测清算 | 描述持仓和支付压力 | OI 增长不能判断开多或开空 |
| 流动性/筹码 | 固定价带深度、冲击成本、持币集中度 | 描述脆弱性与供应约束 | 覆盖不足显示 `unknown`，不填 0 |

RSI14、ADX14、MACD、布林带、锚定 VWAP、Fibonacci、VPVR 是 P1 候选。只有在同一留出样本中显示增量价值和稳定性后，才进入正式自动信号。

`TradingView Lightweight Charts` 只负责图表展示。后台用 Python + TA-Lib 或等价确定性实现计算指标，并保存 `source`、`event_time`、`received_at`、参数、库版本、预热长度和原始 K 线引用。

## 2. OI 与流通估值口径

主观察值为：

```text
已覆盖市场的单边 OI 名义金额合计 / 同期可核实流通市值
```

例如覆盖 OI 为 2,000 万美元、流通市值为 1 亿美元，显示 20%。这表示名义持仓密度，**不是空头占比、保证金比例、杠杆倍数，也不能证明庄家操盘或扎空概率**。一份未平仓合约同时有多方和空方，不能把多空两侧重复计入。

必须同时展示：

- 纳入的交易所、合约类型、合约乘数和币本位/线性换算；
- OI 原始数量、统一数量和美元名义值，区分数量变化与价格导致的名义值变化；
- 流通市值来源、时间、流通量和价格；FDV 不代替流通市值；
- 有效流通估值的情景区间（若有），不能用“总量减 Top10”代替；
- 数据覆盖、更新时间、历史分位和同组基线（样本充分时）。

撤下未经验证的 3%、10%、25% 统一风险档位。数据不足、映射不明、分母过期或跨源覆盖改变时，停止比例类判断并显示原因。OI/流通估值偏高只能作为结构背景，必须与费率、流动性、成交、清算或公开仓位等独立证据组合。

## 3. 自有事实标签

标签使用“周期/范围 + 可观测变化 + 状态”命名，避免使用“突破前夜”“静默建仓”等无法复核的竞品代号。

| 标签 | 触发依据 | 不能推出的结论 |
|---|---|---|
| 波动收缩 | ATR/价格或冻结区间宽度相对历史下降 | 没有方向或倒计时 |
| 区间收盘突破/跌破 | 已收盘价越过此前冻结边界及缓冲 | 不承诺后续趋势 |
| 成交额放大 | 已闭合报价成交额超过同周期基线 | 不证明净流入或建仓 |
| 回踩保持 | 突破后触及冻结边界带，收盘守住 | 必须等回踩发生，不能回填 |
| 结构失效 | 收盘跌破预设失效线或结构被破坏 | 数据断档不算结构失效 |
| 持仓扩张/收缩 | 同来源同窗口 OI 基础数量超过噪声变化 | 不判断多空方向或主体 |
| 名义持仓相对估值偏高 | OI/流通市值相对自身或同组偏高 | 不推算操盘主体或逼空概率 |
| 费率偏负/偏正 | 原始结算周期的已结算费率及偏离 | 不是空头持仓百分比，套保也会造成 |
| 空头/多头清算增加 | 来源明确的被清算方向、金额和窗口增加 | 只能称已观测事件，不称全市场爆仓 |
| 可见流动性下降 | 固定价带深度下降或冲击成本上升 | 撤单不等于成交，未覆盖不填零 |
| 持币集中度偏高/上升 | 带标签范围的持币快照及变化 | 不等于一个实体控盘 |

组合解释也必须保留各标签、时间和来源。例如“收盘突破 + 成交额放大 + OI 数量上升”只能说明三项同时成立；“上涨伴随空头清算”必须有可靠同窗口清算事件。只有价格上涨、OI 下跌时，使用“上涨伴随持仓收缩（原因待核）”，不能写成已发生清算。

## 4. 技术信号和图表点位

首版扫描周期为 `1D` 结构、`4H` 启动/回踩、`1H` 细化；`15m` 仅详情和实验。日线默认使用 UTC 00:00 边界，现货和永续分别计算。

“1D 突破”必须说明对象。演示规则如下，参数须回测登记：

```text
R_t = max(high[t-20], ..., high[t-1])
buffer_t = 0.25 × ATR14[t-1]
日线突破 = close[t] > R_t + buffer_t
放量倍数 = quote_volume[t] / median(quote_volume[t-20:t])
放量突破 = 日线突破 且 放量倍数 >= 1.5
```

盘中越过后收盘收回，只保留可撤回的盘中观察，不能确认日线突破。确认后冻结突破位、区间、缓冲、首次时间/价格和失效线。

TradingView 图表事件契约至少包含：

- 价格与成交量：K 线、成交额、量比、EMA、ATR；
- 结构：支撑/阻力区、箱体上下沿、触及次数、状态和失效时间；
- 点位：突破、回踩、失效、清算事件及首次告警标记；
- 斐波那契：两个已确认锚点、方向、计算时间和规则版本；
- 分面板：OI、Funding、主动买卖量和数据质量；
- 每个对象绑定 `instrument_id`、`timeframe`、检测时间和当时快照，不能用当前数据重写旧事件。

VPVR 只作可选人工研究叠加：POC、VAH、VAL 随固定可见窗口变化，不等于所有持仓成本，也不能识别庄家。若未来用于自动规则，必须冻结区间、分桶和价值区算法，并用当时可见数据回放。

## 5. 信号卡字段

标题使用事实组合，例如“1H 区间收盘突破｜4H 持仓扩张｜清算数据不足”。卡片必须能回答“发生了什么、凭什么、还缺什么、什么会失效”：

1. 身份与市场：代币、链/地址、交易所、现货/永续、计价币、规则版本。
2. 技术证据：周期、突破对象、冻结边界、收盘价、成交额倍数、ATR、支撑/阻力和失效线。
3. 合约证据：OI 数量及名义值、变化窗口、OI/流通市值及分母、费率周期、基差、主动买卖、已观测清算。
4. 链上与风险：流通市值口径、池流动性/冲击、持币集中度范围、合约风险、反向证据和缺失项。
5. 生命周期：候选、确认、持续、降级、结束、失效；首次时间/价格不表示建仓成本或预期倍数。

图表上的下一阻力是观察位置，不自动叫止盈或预期收益。没有可靠点位时显示未知。

## 6. TradingView 图表联动实现

图表页面不是第二套信号计算器，而是信号快照的可视化和复核界面。后台返回同一事件的 K 线来源、指标结果和 overlay 定义，前端用 `TradingView Lightweight Charts` 和自定义 Datafeed（REST + WebSocket）渲染：

```text
用户点击信号卡
  -> GET /v1/candles?instrument_id=...&timeframe=...&to=event_time
  -> GET /v1/technicals?instrument_id=...&timeframe=...&event_id=...
  -> GET /v1/chart-overlays?event_id=...
  -> 图表定位首次触发柱，显示确认/回踩/失效标记
  -> 点击标记回到同一信号卡
```

统一 overlay 至少包含 `event_id`、`instrument_id` 或 `pool_id`、`timeframe`、`source`、`detected_at`、`confirmed_at`、`invalidated_at`、价格点位、规则版本和状态。K 线、现货/永续、链上池的市场身份必须一致；不能用当前窗口重新计算旧点位。

- 主图：K 线、EMA、箱体、支撑/阻力区、突破和回踩标记；
- 副图：成交额、OI、Funding、主动成交、已观测清算和数据质量；
- 研究叠加：Fibonacci、锚定 VWAP、VPVR，默认手动或研究模式，不参与正式告警；
- 交互：卡片到图表、图表到卡片双向跳转，改变缩放只改变视窗，不改变信号状态。

`Lightweight Charts` 不提供行情、指标、Pine Script 或策略回测。TradingView 网站上的脚本只能作为人工研究参考；要自动化，必须把规则登记后用本地数据重算并回测。Advanced Charts/Charting Library 需要合法授权，不能用 GitHub 公开副本替代。

## 7. 验证和启用门槛

- 先登记事件定义、观察期限、目标/失效线和同根 K 线冲突处理；
- 以“仅价格区间突破”为基线，逐次加入量能、趋势、OI、费率/清算、流动性和候选指标；
- 按时间切分训练/调参/留出测试，纳入震荡、涨跌、不同流动性、失败启动和下架样本；
- 报告样本数、覆盖率、误报/日、漏报、领先时间、最大有利/不利偏移、数据缺失和成本；
- 没有历史 OI、盘口、清算或地址覆盖时，从现在开始积累，不能由 K 线编造历史；
- 未完成独立测试和前向观察前，保持“研究标签”，不输出实时概率、收益保证、“庄家控盘”或“必然逼空”。

指标是数值，标签是规则描述，信号是带时间和失效逻辑的事件，策略还需定义仓位、执行、费用和退出；四者不混用。
