2. 最新已核实记录是 binance:perp:CELOUSDT，时间 2026-10-05 18:00:13，当时market.price=0.10484467。当前文档不把它当作可执行建议。当时valid_until距as_of仅6.624秒，这是该次快照生成后剩余资格时间，不是整个信号存续时长。该值说明单纯15秒轮询可能错过短资格，但没有浏览器当时日志，不能断言用户页面一定漏报。

7. 现行小额测试也使用1000USD的probe_notional_usd作盘口成本研究情景，早期最小净盈亏比1.5、确认1.8。1000USD不是实际用户投入，也不是代码自动下单，但“小额”名称与该深度检查金额容易造成误解。是否分设小额测试的研究金额需决策与真实费用/滑点验证，不能为了出信号自动降低金额或门槛。

## 为什么现在看不出来

- 资格链：闭合策略触发 → 原生市场与完整计划 → 有效ask/last报价 → 依赖周期新鲜 → 参与区/保护/有效期 → 盘口、费用、近阻力和净盈亏比 → 动作 → 当前投影 → API动态安全检查 → 页面。
- 当前动作保留有效期，publish又取盘口年龄和入场期限的最小值；投影/API的时间和价格变化会把旧建议降为风险行，机会视图只保留l1/l2/l3。当前资格过期不应该继续显示可买，但历史建议必须留下。
- 本次实页买入机会0，雷达仍有123个资产、36个重点，许多显示等待分析/○数据不足。观察的早出现不代表已有完整入场计划，也说明等待分析不能归类为策略失败。
- 决策优先返回quote_stale时，entry_expired、entry_obstructed等reason_codes仍可能存在，但页面主提示只看报价延迟。应区分业务终态与数据问题，不通过延长新鲜度到半小时解决。
- 早期阻力判断代码保留entry_obstructions，实际触碰阻力会阻止入场。本轮未证明该规则错误；需对44个早期计划抽取形成时阻力、来源周期、现在是否已被闭合突破与冻结计划政策，检查“永久冻结旧阻力”是否错误挡住后来确认。作为待复现项，不自动清除阻力或放宽策略。

## T1 → T2 → T3：按链路解释页面

|级别与原页面|本级负责什么|进入下一步的条件|页面呈现|
|---|---|---|---|
|T1 异动发现（原异动雷达）|量价/OI等轻量异动证据与背景降噪，记录首次触发|有效异动达到基础规则即进入观察；人工关注可直接建立T2档案|首次原因、数值、首价后变化、源更新、该资产当前已到哪级；不把六周期分析塞进T1|
|T2 持续观察（原我的观察）|保留档案、持续采样、重点选择、补依赖窗口、趋势与结构分析|策略依赖窗口与触发依据就绪，形成入场计划；并非六周期全部同向或所有字段齐全|全部观察/我的重点/降频筛选，六周期依据、当前阶段、明确等待原因与下一步|
|T3 入场复核（原买入机会）|已有计划的参与区、保护、期限、报价/盘口、费用与净盈亏比复核|对应资格全部通过才授予参与建议；尚未通过则等待或暂停|现在可以买、可小额测试、等待价格、暂停原因；历史建议为内部页签|

T3不是“已经可以买”。现在可以买与可小额测试均为T3内部的资格结果，不能把小额测试写成T2。T2在资产进入T3后继续跟踪，并不删除档案。关注、降频和归档是观察管理属性，不是另一个分析级别。市场查询、系统状态和设置是辅助功能，不算T4。

每个代币详情增加T1触发证据 → T2分析依据 → T3当前复核的独立进度条。尚在T2的详情不展示虚构的参与区/保护价。T1列表可保留历史触发资产，同时标明其当前已到T2或T3；列表所在页面的职责与资产当前阶段分别展示。

实现边界：P38审计已指出代码尚无严格统一的T1/T2/T3状态机，旧入口仍可绕过T2名额。现有ObservationRow包含reasons、analysis_status、trade_status、next_task、plans等字段，但不存在可直接替换的统一stage枚举。正式前端阶段须由后端集中归纳当前有效证据与关联计划，并带等待原因；不能凭pinned、涨幅、绿色趋势或旧过期plan自动升到T3。本轮仅展示设计，不宣称后端逐级执行已经修复。
