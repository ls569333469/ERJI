## 4. 大周期定背景，小周期找触发

### 4.1 推荐流程，交由用户审定

1. 全资产低成本扫描：复用批量报价/成交量和已有推送，记录各资产状态；不要求每轮重拉所有周期和全部 OI。
2. 周线/日线背景：缓存已收盘结果，区分顺势、底部修复、逆势反弹和数据不足。周线偏空不自动淘汰底部修复；新币周线不足不伪造周线趋势。
3. 候选入池：符合已有价格模板的结构，或出现值得进一步检查的量价/OI异动后进入候选。必须留存入池理由，不把“异动”直接升级为买入。
4. 4H/1H 触发：仅按模板要求下载连续窗口、预热和需要的合约数据，形成明确价格/收盘/量能条件。
5. 计划与追踪：判断当前价格是否还在参与带、计划是否失效、数据是否可用、执行成本是否满足用户确认的规则；持久追踪，不依赖打开详情页。

12H 可用于日线与 4H 分歧的补充分析，不作为所有策略必需的一关。若最终采用，必须核对原生 12H 或严格对齐的完整聚合、闭合标记、调度/存储/分析/图表；缺下级柱不合成完整 12H。

## 5. 采集慢与历史积压怎么处理

### 5.1 已知事实，不把时间网格当作上游必然存在的数据

2026-10-03 16:17 左右的只读查询：563 个币安合约市场的 4H 深历史，33 个游标为 complete，127 个 progress，11 个 check_internal_gaps，43 个 gap，349 个尚无补齐游标。约162万根前段与79万根内部缺格是按时间网格估算，可能包含实际上未开盘/无可比数据的时段，不能宣称这些都能从 API 下载。

同一次查询全来源基础历史门槛是 1,877 市场中 1,345 就绪、532 不足；这是最低分析窗口，不是全历史连续性。563 个合约最新日线补齐也只表示最新已收盘柱已到，不代表所有策略必需数据已齐。12:53 页面曾有4个 OI/市值，之后降为1–3个，说明持续可用性未解决。

### 5.2 资源顺序与预算

| 队列 | 服务对象 | 运行规则 |
| --- | --- | --- |
| 当前事件/候选 | 已显示机会、临近触发、活动追踪 | 优先保证近期 K 线、报价、必需 OI/费率端点；保留公平轮转，不能只照顾少数币 |
| 大周期与普通扫描 | 全资产背景与新机会发现 | 收盘后增量更新；复用批量结果；异动升优先级，无意义数据不进入机会主表 |
| 冷历史 | ATH、历史案例和确需长历史的计算 | 使用独立子配额和剩余预算；实时队列积压时让出资源；优先官方静态归档的可验证数据 |

“独立子配额”不代表绕过共享上限。维持现有总预算，按供应商实际端点权重、同出口总量和429/418/Retry-After退避；先列需求容量表再确定批次，不在方案里拍脑袋承诺几秒全币完成。已知每页后固定90秒的深历史节奏应改为预算与积压驱动，而不是无条件提高并发。

容量表必须列：来源、端点、单次权重、批量能力、活跃市场数、预计频率、每分钟需求、实际排队时间、可用预算和降载方式。若全资产 OI 在当前预算内无法满足统一6分钟时限，应明确普通参考与候选实时的产品服务范围，由用户审定；不能宣称全覆盖新鲜。

### 5.3 处理无法补齐的历史
