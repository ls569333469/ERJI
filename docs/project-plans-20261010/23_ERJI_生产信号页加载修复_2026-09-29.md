## 2. 根因和已纠正的判断

服务器存在市场状态、K 线、OI 和阶段事件。Binance REST HTTP 451 是一个独立的数据源限制，不能解释其他来源的数据也无法显示。

实时解读和阶段信号原逻辑在每次定时刷新或 SSE 事件时递增请求序号；旧请求即使成功返回也被丢弃。请求超过 15 秒或事件频繁时，页面可能一直等待，没有任何成功结果被接受。

`plan_pending` 不会把实时观察列表过滤为空。此前将实时观察 0 归因于该动作不准确。未登录访问数据 API 返回 401 属于正常认证保护，不能据此判断用户截图中的会话失效。

市场列表原查询在单次请求内执行 502 次 SQL，其中大量为逐币重复或不存在的身份/估值查询。生产测量约 11.1 秒。

## 3. 代码修复

1. 使用统一的串行刷新控制器。同一页面同时最多一个请求，收到新事件不会作废当前请求；下一轮轮询从当前请求结束后计时，SSE 刷新有最小间隔。
2. 切换周期、分页、查询或卸载页面时取消旧生命周期；旧返回值不能覆盖新查询。
3. 网络读取最多等待 45 秒，超时给出明确提示并保留上一轮结果，随后自动重试。
4. 初次加载显示“—”而不是 0；显示已读取的代币数量和报价有效数量。币种搜索兼容资产 ID 和显示符号。
5. CMC 身份、流通量和汇率按快照批量读取，包含未知身份的空结果；保持原有时效、乘数、市值与 OI 比例算法。
6. 不放松建议参与规则，不伪造数据，不修改交易开关，不改变数据库 schema。
