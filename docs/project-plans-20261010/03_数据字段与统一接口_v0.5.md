# 数据字段与统一接口

版本 v0.5　日期 2026-09-23

本文把 Binance、Hyperliquid、Aster、OKX 等来源的原始响应转换为统一的内部数据契约。统一的是字段语义，不是强行把不同市场拼成同一条 K 线。所有原始值都保留，归一字段必须能够回溯到来源和转换方法。

## 1. 统一对象

| 对象 | 标识 | 示例 | 说明 |
|---|---|---|---|
| `Asset` | `asset_id` | `asset:BTC` | 经济资产；不能只凭 ticker 合并 |
| `Instrument` | `instrument_id` | `binance:futures:BTCUSDT` | 交易所上的具体现货/永续/交割合约 |
| `Venue` | `venue_id` | `binance`, `hyperliquid`, `aster` | 数据和交易场所 |
| `Pool` | `pool_id` | `ethereum:uniswapv3:0x...` | 链上流动性池；与 CEX Instrument 分开 |
| `Address` | `chain_id:address` | `1:0x...` | 地址观察对象；带标签来源和覆盖范围 |
| `Signal` | `signal_id` | 规则版本 + episode | 可复算的规则事件，不是订单 |

`Asset`、`Instrument`、`Pool` 三种对象不跨层混用。封装币、桥接币、币本位合约、指数和 1000 倍面值合约都必须显式保存。

## 2. 原始事件必备字段

所有 REST 快照和 WebSocket 事件最少保存：

```json
{
  "source": "binance_futures",
  "native_instrument_id": "BTCUSDT",
  "market_type": "perpetual",
  "event_time": "2026-09-23T00:00:00.123Z",
  "received_at": "2026-09-23T00:00:00.245Z",
  "sequence": null,
  "payload_sha256": "...",
  "payload_json": {},
  "quality_status": "fresh"
}
```

`event_time` 是交易所/链上数据发生时间，`received_at` 是我们收到的时间；不能用抓取时间覆盖事件时间。原始响应可以落对象存储或压缩 JSONL，数据库保存引用和校验值。

## 3. K 线规范

```json
{
  "instrument_id": "binance:futures:BTCUSDT",
  "period": "1h",
  "open_time": "2026-09-23T00:00:00Z",
  "close_time": "2026-09-23T00:59:59.999Z",
  "open": "100.00",
  "high": "101.20",
  "low": "99.80",
  "close": "100.90",
  "base_volume": "123.45",
  "quote_volume": "12456.78",
  "trade_count": 321,
  "is_closed": true,
  "source": "binance_futures",
  "quality_status": "complete"
}
```

- 指标和突破只使用 `is_closed=true` 的 K 线；当前未闭合 K 线只能作为实时预览。
- `base_volume` 和 `quote_volume` 不混用。成交量倍数默认使用同来源、同周期的 `quote_volume`。
- 缺 K 线、重复 K 线、时间倒退、异常高低价要进入质量表，不用 0 补齐。
- 不把 Binance Spot、Binance Futures、Hyperliquid 和 Aster 的 K 线拼成一条“聚合 K 线”；跨市场只做对照面板。

## 4. 衍生品统一字段

| 统一字段 | 原始字段保留 | 口径 |
|---|---|---|
| `open_interest_native` | 张数/币数/原始单位 | 原样保存 |
| `open_interest_base` | 计算方法 | 能换算时才填写 |
| `open_interest_usd` | 价格和合约乘数 | 使用 mark 或来源规定价格，并保存 `conversion_method` |
| `funding_rate` | 原始费率、下一次结算时间 | 不能抹掉 1h/4h/8h 等周期 |
| `mark_price` | mark/oracle/index 原始值 | 标记价和指数价分别保存 |
| `bid_ask_depth` | 档位、数量、时间戳 | 指明快照还是增量，标明档位上限 |
| `liquidation_event` | 订单/成交/推送类型 | `actual_or_estimated`、`snapshot_or_complete`、`side_semantics` 必填 |

`OI` 同时有多空双方，不允许用总 OI 直接推导“空头更多”。`funding_rate` 是拥挤代理，不是方向结论。`价格上涨 + OI 下降` 只生成“可能存在回补/去杠杆”的候选解释，并显示其他可能性。

## 5. 来源适配器契约

每个来源实现同一组只读方法；返回统一模型和原始响应引用：

```text
list_instruments() -> Instrument[]
fetch_klines(instrument, period, start, end) -> Kline[]
subscribe_trades(instrument) -> EventStream
subscribe_order_book(instrument) -> EventStream
fetch_open_interest(instrument, at) -> OpenInterestSnapshot
fetch_funding(instrument, at) -> FundingSnapshot
fetch_mark_index(instrument, at) -> PriceReference
fetch_liquidations(instrument, start, end) -> LiquidationEvent[]
health() -> SourceHealth
```

首版适配器：

- **Binance Spot/Futures/Alpha：** Spot REST/WS、USDⓈ-M Futures REST/WS 和 Alpha REST/WS 分开；Futures 负责 OI/funding/mark/清算相关字段，Alpha 负责 token list、K 线、ticker、depth、trades，不把 Alpha 当作现货上市或合约市场。
- **Hyperliquid：** `POST https://api.hyperliquid.xyz/info` 和 `wss://api.hyperliquid.xyz/ws`；市场目录、K 线、L2、成交和资金字段走原生接口，地址仓位使用明确的地址集合。
- **Aster：** 基础地址 `https://fapi.asterdex.com`、WebSocket `wss://fstream.asterdex.com`；新集成固定 V3，市场公共数据与账户认证接口分开。2026-09-23复盘已获取8币历史K线及资金费，保留成功请求的实际路径；历史OI与清算覆盖需另验。
- **OKX：** REST + WebSocket 用于跨场价格、K 线、OI/funding 和合约规格复核。
- **Gate/Bitget：** P1 适配器，先实现目录、K 线和公共衍生品字段，再评估限频和覆盖。

CoinGecko、DexScreener、Surf 可按需实现低频 `EnrichmentProvider`；CMC另外增加经Key验收的 `DerivativesAggregationProvider`，不可再归为只补充市值：

```text
resolve_asset_identity() -> IdentityEvidence[]
fetch_market_metadata() -> MarketMetadata
fetch_token_holders() -> HolderSnapshot | Unknown
fetch_address_labels() -> AddressLabel[] | Unknown
```

## 6. 技术指标和形态接口

标准指标用 TA-Lib 或等价复算，必须固定 `period`、`input_price`、预热长度和数值容差。建议输出：

```json
{
  "indicator": "ema",
  "period": 20,
  "value": "101.234",
  "as_of_close": "2026-09-23T00:59:59.999Z",
  "implementation": "talib",
  "rule_version": "indicators-v1"
}
```

形态识别器不直接输出“准确率”或“必涨”：

```json
{
  "pattern": "arc_bottom_candidate",
  "state": "candidate",
  "window": {"start": "...", "end": "..."},
  "neckline": "105.00",
  "evidence": ["rounded_low", "volume_contraction", "right_side_recovery"],
  "confirm_when": ["closed_breakout", "quote_volume_ratio >= 1.5"],
  "invalidate_when": ["close_below_pattern_low"],
  "rule_version": "patterns-v1"
}
```

日线突破必须使用前一段已闭合窗口的最高价作为压力位；突破 K 线不能进入自己的基线。圆弧底先做候选和颈线突破两种状态，之后用人工标注和时间回放评估误报、漏报和延迟。

## 7. 质量状态

`quality_status` 允许值：

- `fresh`：在该源的目标延迟内收到。
- `stale`：超过目标延迟但仍可用于历史展示。
- `partial`：字段或时间段缺失。
- `conflict`：同一时点来源冲突或映射未决。
- `unknown`：来源没有提供，不能用 0 代替。
- `invalid`：格式、时间、顺序或校验失败。

告警规则必须声明依赖字段。依赖字段是 `unknown`、`partial` 或 `invalid` 时，信号最多降为观察，不得升级为资金结构确认。

## 8. 采集节奏和免费配额

| 任务 | 首版节奏 | 存储 |
|---|---:|---|
| WebSocket trades/盘口 | 持续订阅；断线重连 | 原始事件 + 1m 聚合 |
| 1m/5m K 线 | WS 为主，REST 对账 | 闭合 K 线长期保存 |
| OI/funding/mark | 30–60 秒 | 原始快照和统一值 |
| 1h/4h/1d 历史补齐 | 启动时 + 每小时对账 | 至少 30 天后再评估 |
| CMC/CoinGecko/DexScreener | 5–15 分钟 | 低频补充快照 |
| Surf 地址/持币/标签 | 15–30 分钟或按需 | 保存 credits、覆盖和缓存状态 |

实际间隔由响应头限频、订阅上限和服务器容量动态调整。采集器必须有指数退避、重复去重和来源健康状态，不能为了刷新频率打穿免费接口。

## 9. Signal 记录

```json
{
  "signal_id": "sig_01H...",
  "asset_id": "asset:XYZ",
  "instrument_id": "hyperliquid:perp:XYZ",
  "family": "squeeze_structure",
  "stage": "S1",
  "state": "candidate",
  "rule_version": "squeeze-v1",
  "triggered_at": "2026-09-23T01:00:00Z",
  "evidence": [{"field": "oi_usd", "value": "...", "source": "hyperliquid"}],
  "missing": ["complete_address_coverage"],
  "counter_evidence": ["spot_volume_not_confirmed"],
  "quality_status": "partial"
}
```

去重键：`asset_id + instrument_id + family + rule_version + episode_id`。信号解释必须能从快照重算，AI 只负责把结构化证据组织成文字。

## 10. 运行边界

本统一接口只覆盖公开读数据和研究补充。不得在这些适配器中加入下单、提现、私钥、钱包签名或自动跟单逻辑。若未来增加交易执行，必须建立独立服务、独立权限和单独的风险评审。

列表、详情、通知与图表 overlay 必须引用同一 `evidence_snapshot_id`；更新产生新快照而非改写原始事件。数量变化需要两端集合一致；覆盖改变时窗口字段为空、reason为coverage_changed。同一原生市场多供应商只选一个主版本，原始响应仍全部保存以复核。反向与面值合约按规格转换，不可默认乘当前价。

当前总额、可比较子集合总额与供应商全所总额分别命名，不能都称全网OI。流通量、地址标签的 `known_at` 参与回放，事后报告不能提前进入特征。

推荐新增只读接口：

```text
GET /v1/assets/{id}/derivatives?as_of=&window=4h
GET /v1/assets/{id}/venue-coverage?as_of=
GET /v1/assets/{id}/funding-cost?start=&end=
GET /v1/signals/{event_id}/evidence?snapshot_id=
GET /v1/signals/{event_id}/overlays?snapshot_id=
GET /v1/assets/{id}/liquidation-zones  # 无来源返回unknown，不能生成默认假图
```

这些是设计契约，当前HTML未实现实时接口。策略参数、样本质量与启用状态也应随事件返回；未知值使用null及reason，不用0或空字符串伪装。
