# ERJI 数据准确性与 K 线决策引擎优化方案

版本：v1.1  
日期：2026-09-30  
状态：实施前方案  
适用范围：本地版与 GitHub 主线；服务器版暂停迭代期间以本地版为准

## 1. 本轮结论

当前产品已经完成行情图表、基础技术计算、阶段信号列表和部分合约字段，但还没有形成“数据 -> 证据 -> 判断 -> 买入点 -> 目标位 -> 保护价 -> 持续追踪”的完整决策闭环。

需要明确区分三件事：

1. TradingView Charting Library 负责 K 线图、指标窗格和绘图交互，不负责自动判断买卖。
2. ERJI 当前已经计算 EMA、MACD、ATR、枢轴高低点、箱体等基础指标，但部分字段映射、目标层级和页面解释存在错误。
3. 此前登记或下载的 TradingView 社区指标仍属于研究材料，尚未作为可执行算法接入信号引擎，不能宣称已经参与买点、保护价或目标位计算。

本方案先修复数据准确性，再建设可解释的技术决策引擎，最后接入经过授权、复核和回测的社区指标方法。

## 3. 数据准确性契约

### 3.1 每个显示字段必须有证据

前端每个价格、比例和判断必须同时具备：

- `value`：原始值或计算值；
- `source`：Binance Spot、Binance Perpetual、Hyperliquid、Aster、CMC 等；
- `instrument`：具体交易对和市场类型；
- `as_of`：数据时间；
- `method`：原始接口、confirmed pivot、ATR、AVWAP 等；
- `timeframe`：1H、4H、1D 或 1W；
- `freshness`：fresh、delayed、stale、missing；
- `missing_reason`：无合约、身份未映射、历史不足、接口失败或数据过期。

禁止用另一个字段静默补位。任何回退必须在 API 中记录 `fallback_reason`，前端也必须能解释。

### 3.2 技术市场与衍生品市场分离

每个资产固定两个引用市场：

- `chart_reference_market`：K 线和技术结构使用的市场，优先选择流动性高、历史完整的 Binance 现货或永续。
- `derivatives_reference_market`：OI、资金费率、清算使用的最佳永续市场，优先 Binance；Aster、Hyperliquid 作为同资产补充。

图表使用现货时，不得导致同币永续 OI 消失。Aster 和 Hyperliquid 不生成重复资产行，只附加到统一资产身份。

### 3.3 OI 统一口径

系统同时保存：

- 数量 OI：合约标的数量，用于判断是否真的出现新开仓，避免价格上涨机械放大美元 OI；
- 名义 OI：数量 OI × 标记价格，用于衡量资金规模；
- OI / 流通市值：已覆盖平台名义 OI 合计 ÷ 同时点流通市值；
- OI 变化：1H、4H、1D；
- 价格变化：与 OI 使用相同起止时间；
- 资金费率：平台、结算周期、最近结算值和下一次结算时间。

页面必须标明是“Binance 永续 OI”还是“已覆盖平台 OI 合计”。没有数据时显示具体原因，不能统一写“待积累”。

## 4. 机会阶段与准确文案

### 4.1 统一阶段

| 阶段 | 用户含义 | 是否允许买入 | 必须提供的信息 |
| --- | --- | --- | --- |
| 观察 | 有结构但距离触发较远或证据不足 | 否 | 关注原因、触发条件、失效条件 |
| 等待买入 | 接近触发，尚缺收盘、量能或回踩确认 | 否 | 还差什么、预计触发价、预估保护位 |
| 买入机会 | 规则已经满足且盈亏比合格 | 是 | 参与区、仓位级别、目标、保护、有效期 |
| 持有追踪 | 已触发且结构仍有效 | 已有仓位继续管理 | 首次信号价、当前收益、保护上移、下一目标 |
| 退出/失效 | 结构破坏或风险条件触发 | 否 | 退出原因、失效价、发生时间 |

“结构待突破”“早期上行触发”等研究词不能单独作为结论。页面必须明确写“现在是否可以买”。

### 4.2 动态解释

候选箱体不再使用统一文案。示例：

> 现价 0.01349，距 4H 突破触发价 0.01374 还有 1.9%。需要 4H 收盘高于触发价，并且成交量达到此前 20 根 4H 成交量中位数的 1.5 倍。目前量能为 1.12 倍，尚不满足买入条件。

触发后示例：

> 4H 已收盘突破 0.01374，量能 1.83 倍，1H 与 4H 结构同步上行，日线未转弱。当前位于参与区 0.01370-0.01386，可参与；跌破 0.01310 退出。第一目标 0.01508，按参与区中值计算空间 9.4%，风险回报比 2.1。

所有百分比必须使用实际可执行参与价计算，等待突破信号不得使用尚不可买的当前价夸大空间。

## 5. K 线决策引擎

### 5.1 指标分工

不以单一金叉或单个社区指标直接决定买入。指标按功能分组：

| 功能 | 核心指标 | 用途 |
| --- | --- | --- |
| 趋势结构 | confirmed pivots、HH/HL、LH/LL、EMA20/50、ADX | 判断方向和趋势强度 |
| 动能 | MACD、RSI、ROC | 判断启动、延续或衰减 |
| 成交确认 | 成交量 / 20 根中位数、OBV 或等价累积量能 | 判断突破是否有真实交易支持 |
| 波动与风险 | ATR、Bollinger Band Width | 设置缓冲、保护距离和波动状态 |
| 关键点位 | 多周期 pivot、Anchored VWAP、成交密集区、箱体边界 | 生成参与区、阻力和支撑 |
| 扩展目标 | Fibonacci extension | 只在突破历史高点且上方缺少真实阻力时使用 |
| 合约确认 | 数量 OI、OI/市值、费率、清算 | 判断新增杠杆、拥挤度和挤仓可能 |

### 5.2 多周期判断

以大周期决定允许方向，小周期决定时机：

- 1W：市场位置和长期上方空间，不要求每次都已转强，但若明确下行必须降低等级；
- 1D：主要方向和关键结构，是买入资格的核心周期；
- 4H：确认突破、回踩和计划生成；
- 1H：提前观察和优化进入价格，不得单独推翻 1D/1W 风险。

允许两类买入机会：

1. **突破买入**：4H 收盘越过结构触发价，量能达标，1D 未处于明确破位状态，计划风险回报比达标。
2. **回踩买入**：已经确认突破，价格回踩箱体上沿、AVWAP、EMA 或已确认支撑并重新收回，量能和结构未恶化。

允许一个高风险提前布局等级：1H 与 4H 同步转强、1D 位于确认底部区域但尚未突破。必须标记“提前布局”，使用更小仓位和更近失效位，不能与正式突破机会混在一起。

### 5.3 买点生成

参与区由实际结构产生：

- 突破型：触发价至 `触发价 + 0.3 × ATR(4H)`；
- 回踩型：突破位、Anchored VWAP 或确认支撑附近的 ATR 容差区；
- 若当前价格已经超过参与区上沿，状态改为“已错过，等待回踩”，不得继续显示买入。

买入机会还必须通过：

- 数据新鲜度检查；
- 最低流动性检查；
- 第一目标前净空间检查；
- 风险回报比检查，默认最低 1.8，可在设置页调整；
- 重大多周期冲突检查。

### 5.4 保护价与失效价

候选阶段显示两个值：

- 触发前结构失效价：通常为箱体下沿或最近确认低点；
- 触发后初始保护参考：基于结构位与 ATR 缓冲的估算值。

正式触发后冻结保护价，原则为最近有效结构低点减 ATR 缓冲。保护价只能随结构抬高，不能向扩大亏损方向移动。

### 5.5 目标位方法论

目标必须按以下顺序搜索，禁止随意填写倍数：

1. 参与价上方最近的 4H 已确认 pivot high；
2. 日线已确认 pivot high；
3. 周线已确认 pivot high或历史密集成交阻力；
4. Anchored VWAP 偏离带或成交密集区边界；
5. 突破历史高点后，才使用 Fibonacci 1.272、1.618 等扩展目标。

输出必须保留 `method`、`timeframe`、`known_at`。若第一目标就是日线阻力，合并显示“第一目标（日线）”，不得复制成两个目标。

“最高条件目标”只表示在前置目标突破并确认承接后启用，不能写成必达价格。

## 6. TradingView 与社区指标的正确落实方式

### 6.1 TradingView 图表库的职责

当前 GitHub Charting Library 可以用于：

- 展示 ERJI 提供的 OHLCV；
- 切换 1H、4H、1D、1W；
- 绘制箱体、参与区、失效价、保护价和目标区；
- 展示 EMA、MACD、布林带等指标；
- 保存用户绘图。

它本身不会提供 TradingView 服务器端策略、会员指标或社区 Pine Script 执行环境。打开 TradingView 官网也不代表社区指标已经接入 ERJI。

### 6.2 社区指标接入流程

对此前下载或登记的每个社区指标建立清单：

| 字段 | 要求 |
| --- | --- |
| 名称与原始链接 | 可追溯到 TradingView 页面或源码仓库 |
| 作者与许可证 | 确认允许研究、修改和本地使用 |
| 源码状态 | open-source、protected、invite-only |
| 算法说明 | 输入、周期、公式、重绘风险 |
| ERJI 用途 | 趋势、买点、目标、保护或过滤 |
| 后端实现 | Python/TypeScript 对等计算 |
| 图表实现 | overlay、pane 或标记 |
| 验证状态 | 单元测试、样本对照、历史回测 |

只有公开源码且许可允许的指标才复刻算法。Protected 或 invite-only 指标不能通过 Charting Library 自动安装，也不能根据画面猜测公式。

### 6.3 推荐首批落实的社区方法

首批只落实对决策有直接作用的方法：

1. Anchored VWAP：锚定突破 K 线、阶段低点或事件起点，用于回踩参与和趋势保护；
2. 自动支撑阻力：confirmed pivots 聚类，生成真实结构区；
3. 成交量确认：相对中位成交量与累积量能，过滤假突破；
4. Fibonacci retracement/extension：用于回撤参与和历史高点上方条件目标；
5. 趋势跟踪保护：基于结构低点与 ATR，只用于持仓管理；
6. Squeeze/波动收缩：识别布林带收缩后的潜在启动，但不能单独成为买入信号。

这些方法在后端统一计算，前端 TradingView 只负责画出同一组结果。列表、详情页、Telegram 提醒和图表必须读取同一个决策快照，避免页面文案与图上点位不一致。

## 7. 图表必须完成的内容

详情页默认只显示决策必需图层：

- 真实 K 线和成交量；
- 当前阶段的有效箱体或结构区；
- 突破触发线；
- 参与区；
- 触发前失效线；
- 触发后保护线；
- 第一目标、日线目标和周线目标；
- Anchored VWAP；
- EMA20/50；
- MACD 独立窗格；
- 首次信号时间和价格标记。

可选图层只有在数据真实可用时启用：布林带、Fibonacci、已发生清算、Hyperliquid 可见仓位风险价、OI 曲线。开关不得先于数据能力上线。

图表上每条线都要显示名称、价格、周期和来源。例如“日线已确认前高阻力 0.01508”，不能只写“目标”。

## 8. 性能与采集计划

浏览器请求路径不得现场调用外部交易所。采集、指标计算和信号生成全部在后台完成，前端读取预生成的最新决策快照。

建议频率：

| 数据 | 建议频率 |
| --- | --- |
| Binance 全市场 ticker 批量快照 | 60 秒 |
| 1H/4H/1D/1W K 线 | 临近或完成收盘后更新，信号只使用闭合 K 线 |
| 活跃买入机会 OI | 2 分钟 |
| 等待买入候选 OI | 5 分钟 |
| 其余合约资产 OI | 15 分钟 |
| 资金费率 | 5 分钟，并按结算周期保存 |
| Hyperliquid/Aster 补充 | 仅对候选和活跃资产，2-5 分钟 |
| CMC 市值与流通量 | 30-60 分钟 |
| 资产范围与交易对目录 | 6 小时 |

页面接口目标：正常缓存命中 `p95 < 500ms`，最慢不得超过 2 秒。外部接口失败时继续提供最后成功快照，并明确标记数据时间和过期状态。

## 9. 实施顺序

### P0：先修正确性

- 删除第一目标到日线目标的静默回退；
- L2 目标空间改为使用计划参与价；
- 修复目标的 method、timeframe、known_at；
- 动态生成每个资产的触发说明；
- 候选阶段显示失效价与预估保护价；
- 所有缺失字段返回具体原因。

### P1：稳定合约数据

- 分离技术市场与衍生品市场；
- 统一资产身份并去除 Aster/Hyperliquid 重复行；
- 补齐数量 OI、名义 OI、OI/市值、1H/4H/1D 变化与资金费率；
- 为每项合约数据保存平台、时间和新鲜度。

### P2：完成 K 线决策引擎

- 实现突破、回踩和提前布局三套计划模板；
- 接入多周期结构、动能、成交量和风险回报过滤；
- 生成可解释参与区、失效价、保护价和分级目标；
- 让列表、详情图表和提醒读取同一决策快照。

### P3：落实社区指标

- 盘点已下载指标及许可证；
- 选择首批方法并在后端实现；
- 与 TradingView 原脚本进行样本对照；
- 完成历史回测和不重绘检查；
- 通过验收后才纳入买入判断。

### P4：持续追踪

- 保存信号首次价格、首次时间和每次阶段变化；
- 记录目标触达、保护上移、失效和退出；
- 页面展示完整时间线；
- Telegram 只推送阶段变化，避免重复提醒。

## 10. 验收标准

1. 任意页面价格和结论都能追溯到来源、时间、周期和算法。
2. 同一资产不会因 Binance、Aster、Hyperliquid 出现重复机会行。
3. 等待买入信号明确说明还差什么；买入机会明确说明现在可以买、怎么买、错在哪里。
4. 第一目标、日线目标和周线目标不再无意义重复。
5. 目标空间按实际参与价计算，图表与列表完全一致。
6. 图上的箱体、参与区、保护和目标均来自当前决策快照。
7. 社区指标只有经过源码核对、许可确认、对照测试和回测后才能标记“已接入”。
8. 信号列表 API 正常响应小于 2 秒，页面加载过程不调用外部交易所。
9. 无数据时展示明确原因，不使用“待接入”“待积累”等无法行动的占位词。
10. 在没有足够历史统计前，不输出伪造的上涨概率；使用证据等级和风险回报比表达可信度。

## 11. 本方案最终输出

系统最终不再只说“出现箱体”“MACD 金叉”或“可以关注”，而应输出完整决策：

> **结论：等待买入。** 当前 1H 与 4H 结构上行，日线处于底部修复，周线仍有上方阻力。4H 收盘突破 0.01374 且量能达到 1.5 倍后升级为买入机会，计划参与区 0.01374-0.01386。第一目标为 4H 已确认前高 0.01508，日线目标 0.01604；按参与区中值计算第一目标空间 9.4%。触发前跌破 0.01237 取消候选，触发后的初始保护参考约 0.01310。Binance 永续数量 OI 4H 增加 X%，价格同期上涨 Y%，资金费率 Z%，当前合约证据支持/不支持本次突破。

该结论中的每个数字都必须由同一时间点的真实数据和可复核规则生成。

## 12. 数据真实性分级与禁止事项

系统中的数据必须按性质标记，前端不得混淆：

| 类型 | 含义 | 是否可直接用于买入结论 |
| --- | --- | --- |
| `observed` | 从官方或明确第三方接口取得的原始行情、OI、费率、成交量 | 可以，但必须通过新鲜度检查 |
| `derived` | 使用可复核公式从原始数据计算的指标、结构、比例和目标 | 可以，必须携带公式版本和输入时间 |
| `estimated` | 清算热图、预估保护、缺少完整市场时的合约合计等模型估算 | 只能作为辅助，必须明确写“估算” |
| `missing` | 没有数据、接口失败、历史不足或无法映射 | 不可以，显示具体原因 |
| `demo` | 演示或测试数据 | 生产页面绝对禁止 |

生产页面禁止：

- 用演示值、默认值或另一个周期的数据填补缺失字段；
- 把估算清算价写成交易所公开的真实爆仓点；
- 把当前未闭合 K 线的临时金叉写成“已确认金叉”；
- 用现价计算尚未触发信号的计划收益空间；
- 把多个平台不同时间点的 OI 直接相加；
- 把美元 OI 上涨直接解释为新增仓位，必须同步检查数量 OI；
- 使用未来 K 线确认的 pivot 回填到历史时点，造成回看时完美的重绘信号；
- 因目标缺失而复制日线或周线目标；
- 在没有统计样本时输出虚构的“上涨概率”。

## 13. K 线真实性与连续性验收

### 13.1 原始 K 线字段

每根 K 线至少保存：

- `instrument_id`、交易所、现货/永续类型；
- `timeframe`；
- `open_time`、`close_time`、时区；
- `open`、`high`、`low`、`close`、`base_volume`、`quote_volume`；
- `is_closed`；
- 数据来源和采集时间。

所有技术指标、结构确认和正式信号只读取 `is_closed=true` 的 K 线。实时未闭合 K 线可以在图上显示，但只能标记为“进行中”，不得改变已经发布的正式信号。

### 13.2 连续性检查

每次计算前自动检查：

- 时间戳是否严格按周期递增；
- 是否存在重复 K 线；
- 是否缺少周期；
- OHLC 是否满足 `low <= open/close <= high`；
- 成交量是否非负；
- 拆分、换币、下架、合约迁移或极端异常值；
- REST 补历史与 WebSocket 增量是否形成同一根 K 线的重复记录。

存在缺口时先回补。无法回补时，该周期输出 `insufficient_history` 或 `data_gap`，不得继续生成正式买入信号。

### 13.3 外部交叉核验

上线前从资产池抽样至少 30 个资产，覆盖高市值、普通山寨、低价 Meme、仅现货、有永续和多平台合约资产。逐项比较：

- ERJI 最新闭合 K 线与交易所官方接口；
- ERJI 图表 OHLC 与同一交易对、同一周期的 TradingView；
- 成交量口径是 base volume 还是 quote volume；
- 时区和日线开盘边界；
- 现货与永续是否被错误混用。

价格允许误差来自市场不同，但同一来源同一交易对必须完全一致；时间边界和周期不得存在偏移。

## 14. 指标准确性验收

### 14.1 指标登记表

每个指标必须登记：

- 唯一 `indicator_id` 和版本；
- 数学公式与参数；
- 输入价格类型，例如 close、hlc3；
- warm-up 所需 K 线数量；
- 周期和闭合规则；
- 是否可能重绘；
- 参考实现和许可证；
- 后端字段与 TradingView 图层名称；
- 用于判断、过滤、目标或展示中的哪一项。

首批标准参数固定并允许设置页覆盖：

| 指标 | 默认参数 | 正式用途 |
| --- | --- | --- |
| EMA | 20、50 | 趋势排列和动态支撑，不单独触发买入 |
| MACD | 12、26、9 | 动能方向、交叉时间和柱体增强/衰减 |
| RSI | 14 | 动能位置和背离辅助，不用超买直接判跌 |
| ADX | 14 | 趋势强度过滤 |
| ATR | 14，Wilder | 参与区容差、保护缓冲和波动归一化 |
| Bollinger Bands | 20、2 | 波动收缩和扩张，不直接生成目标 |
| Relative Volume | 当前成交量 / 前 20 根同周期成交量中位数 | 突破成交确认 |
| Confirmed Pivot | 左右确认根数按周期固定 | 支撑、阻力和结构判断 |
| Anchored VWAP | 明确锚点、成交量加权 | 回踩承接和持仓保护辅助 |
| Fibonacci | 结构锚点确定后计算 | 历史高点上方的条件目标 |

### 14.2 对照测试

每个指标至少完成三类验证：

1. 使用固定 OHLCV 样本与成熟计算库对照；
2. 与 TradingView 同参数、同交易对、同周期逐点对照；
3. 检查前端图表值、API 值与后端数据库值一致。

差异必须有书面原因，例如初始化方式、Wilder 平滑或交易所日线边界不同。无法解释的指标不得上线。

### 14.3 防重绘测试

以逐根回放方式验证：第 N 根闭合时产生的信号，在加入 N+1 及后续 K 线后不得被提前移动或消失。Pivot 必须在右侧确认根数闭合后才记录 `known_at`，图上不得画到市场当时尚不知道的时间点。

社区指标若存在重绘、未来函数、动态回填或源码不完整，只能用于研究图层，不得参与正式买入判断。

## 15. 词条真实性与决策规则

### 15.1 词条必须由结构化事实生成

禁止在后端保存一段通用结论后给所有代币复用。系统先生成结构化证据，再由固定模板转成中文：

```text
stage=waiting_breakout
current_price=0.01349
trigger_price=0.01374
distance_to_trigger_pct=1.85
relative_volume=1.12
required_relative_volume=1.50
invalid_price=0.01237
```

由此生成：

> 等待买入。现价距 4H 突破价还有 1.85%；收盘和量能均未确认。目前量能 1.12 倍，规则要求至少 1.50 倍。4H 收盘跌破 0.01237 后取消候选。

页面文字中的价格和百分比必须直接引用同一结构化字段，禁止在前端再次独立计算。

### 15.2 术语字典

| 词条 | 必须满足的条件 |
| --- | --- |
| 结构上行 | 最近两个已确认高点和低点同时抬高 |
| 结构下行 | 最近两个已确认高点和低点同时降低 |
| 高低点冲突 | 高点与低点方向不一致 |
| 突破确认 | 指定周期闭合价超过触发价，且成交量条件满足 |
| 突破后回踩 | 之前已经确认突破，随后返回突破位容差区 |
| 回踩承接 | 回踩未触发失效，且闭合价格重新收回关键位并满足量能规则 |
| 买入机会 | 触发条件、数据新鲜度、流动性、周期过滤及风险回报全部通过 |
| 等待买入 | 接近触发，但仍缺少一个或多个明确条件 |
| 已错过 | 当前价超过参与区上沿，追入后的风险回报不足 |
| 上涨伴随增仓 | 同一时间窗口价格上涨且数量 OI 上涨；美元 OI 只作规模参考 |
| 空头清算已发生 | 已收到真实清算成交或可验证链上仓位清算事件 |
| 清算密集区 | 模型估算，必须同时标记来源和“估算”，不能写成确定爆仓点 |

每个词条都要有自动测试：规则不满足时不得出现该词条；词条出现时必须返回全部支持证据。

### 15.3 结论强度

结论由硬性规则决定，不能由文案模型自由发挥：

- `不可参与`：数据过期、结构失效、流动性不足或风险回报不合格；
- `观察`：存在结构，但离触发较远或证据不足；
- `等待买入`：接近参与条件，并明确列出尚缺条件；
- `提前布局`：1H/4H 转强且 1D 位于有效底部结构，按小仓位规则执行；
- `买入机会`：正式触发且所有硬性过滤通过；
- `持有/减仓/退出`：仅对已经触发并持续追踪的计划输出。

系统可给出积极建议，但不能把“可能上涨”包装成确定结果。目标是结构条件目标，必须同时提供失效路径。

## 16. 图表清晰度与数据一致性

### 16.1 默认标准图

默认图只保留当前决策所需内容：

- K 线与成交量；
- EMA20、EMA50；
- 当前唯一有效主结构区；
- 触发线、参与区、失效/保护线；
- T1、日线目标、周线条件目标；
- Anchored VWAP，仅在锚点有效时显示；
- MACD 独立窗格；
- 首次信号标记。

旧箱体、旧目标和历史信号默认隐藏到“历史追踪”。同类支撑阻力先聚类成价格区，避免多条相近水平线和标签互相覆盖。

### 16.2 图层状态

每个图层只有三种状态：

- `verified`：已计算、已验证，可默认显示；
- `experimental`：研究或回测中，只能在实验模式显示；
- `unavailable`：缺数据或未实现，不显示开关。

不得使用一个可勾选的空开关暗示功能已经接入。社区指标未通过第 14 节验收前全部标记为 `experimental`。

### 16.3 单一决策快照

信号列表、资产详情、TradingView 图层、Telegram 文案和历史追踪必须引用同一个 `decision_snapshot_id`。快照包含输入数据版本、指标版本、规则版本和生成时间。

如果图上价格线与文字不属于同一快照，页面直接显示“数据正在同步”，不得拼接展示。

## 17. 上线前审计与发布闸门

实施完成不等于可以发布。每个阶段必须通过以下闸门：

### 闸门 A：数据

- 生产数据中 `demo` 数量为 0；
- K 线缺口、重复和时间边界检查通过；
- 现货、永续及资产身份映射正确；
- 任意显示字段均可查询来源和时间。

### 闸门 B：指标

- 每个正式指标拥有登记表和版本；
- 固定样本、成熟库及 TradingView 对照通过；
- 逐根回放无未来数据和非预期重绘；
- 前后端显示一致。

### 闸门 C：词条与计划

- 每个词条有明确布尔规则和证据字段；
- 买入机会拥有参与区、目标、失效/保护、风险回报和有效期；
- 等待买入明确显示尚缺条件；
- 不存在目标重复、现价错算空间或缺失字段静默回退。

### 闸门 D：人工抽查

从每个阶段随机抽取至少 10 个资产，与官方行情和 TradingView 手工核对图、指标、点位和词条。发现一项系统性错误，整类规则退回修复，不以单币例外方式掩盖。

### 闸门 E：灰度

先在本地只读运行至少 7 天，记录信号首次出现、后续变化、目标触达和失效，不修改历史结论。通过后再同步 GitHub；服务器恢复外部数据访问并完成相同验收后才部署。

## 18. 最终实施清单

本方案最终按以下顺序执行，不并行堆叠未经验证的功能：

1. 建立数据真实性字段和生产环境禁用演示数据；
2. 修复目标重复、收益空间、动态词条和保护说明；
3. 完成 K 线连续性、闭合状态和数据来源审计；
4. 分离技术参考市场与衍生品参考市场；
5. 建立指标登记与对照测试框架；
6. 完成标准图表瘦身和单一决策快照；
7. 实现买入、等待、回踩、持有和失效状态机；
8. 逐个接入 Anchored VWAP、自动支撑阻力、量能确认、Squeeze、Fibonacci 和跟踪保护；
9. 完成逐根回放、历史样本和人工抽查；
10. 本地灰度通过后再进入 GitHub 和服务器发布流程。
