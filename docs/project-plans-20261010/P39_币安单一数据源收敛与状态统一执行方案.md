## 4. 数据从哪里到哪里

主链路保持：币安原生采集 → 分市场事实入库 → 数据完整性/补窗 → 结构与趋势分析 → 买入计划与入场复核 → 投影 → API/SSE → 前端。

同一字段应携带或可追溯value、unit、source、instrument_id、observed_at、raw_ref及状态原因。沿用现有表和契约，补必要元数据与公共判定函数；不要求另外建立一套复杂数据平台。不同字段保留自己的时钟，不把价格刷新时间拿来证明OI或结构刚更新。

SSE用于通知受影响数据更新，页面读取当前投影/观察事实，不在前端重复算策略、换算OI或猜身份。历史snapshot_id继续返回当时证据，不用当前数据替代。

## 6. 性能如何证明，多久跑完如何计算

在同一固定市场与输入集合上比较修改前后：结构/趋势首次完成的独立市场数、每分钟吞吐、两队列最老等待与P95、计算重复率、SQL数量/事务占用、API P95、入场/保护/投影延迟、各来源请求数和权重。

运行验收通过标准：符合身份和数据条件的未分析市场持续减少；结构/趋势互不占名额；快速通道不新增饥饿；有界队列可轮转；禁止来源访问归零。性能数值必须附样本大小、时间区间和输入条件，不能用组件提速替代全链路提速。

当前不承诺“90%性能”、整体完成小时数或必出买入信号。原排队方案的45–60分钟只是固定248个输入齐备市场、按旧耗时估算的首轮验证预期。执行后用“输入齐备且尚未完成的独立市场数 ÷ 实际独立市场完成速率”估计剩余时间；缺输入数量与原因单列，不计入纯计算估时。
