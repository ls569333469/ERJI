## 2. 已查明的不一致

- 空列表排查快照：current_signals共4176条，含1852条waiting、233条paused、2091条ended；waiting中28条opportunity_eligible=true，但28条结构有效期全部到期，报价均在6分钟内，接口归入risk后机会列表为0。该数字为排查时快照，后续截图已显示2条机会，不能当成恒定状态。
- 同快照waiting的资格原因：1645条market_data_stale、175条收益风险条件不足、28条合格、4条缺目标阻力；这些是记录数，不是唯一代币数。
- 普通结构扫描每批25个、优先扫描最多10个，按顺序等待完成；最近普通批次约25秒。“5秒”是后续调度间隔，不是每批完成时间。
- signals.scanned/matched沿用上一轮完整统计，却被页面标为“本批扫描”；必须拆开当前批次、本轮累计、上一完整轮次及各自时间。
- SSE绿点仅表示连接建立；需要另外显示行情、分析、页面结果的更新时间。连接正常不能显示为数据全部实时。
- coverage的history_ready_markets只检查四周期各至少50根已收盘记录；不能标成所有策略窗口连续、预热和时效都已就绪。
- 列表状态同时承担行情时效、计划阶段与展示资格，导致过期候选直接消失。运行故障、行情不足、未满足入场应独立表示。
- jobs曾报SQLAlchemy QueuePool size=5、overflow=5、30秒超时；这是每个进程自身的连接池，不是全系统只有10个连接。需测持有时间、泄漏、慢SQL和事务范围后处理，不能只增大连接数。
- 提示文案仍需扫全路径：机会列表native_oi stale分支仍有“合约OI已过期，显示最近记录”，不能以部分替换宣称全站统一。

## 3. 早期讨论方向（具体设计以第10节为准）

全市场轻量行情 → 有效异动事件 → 立即展示并建立观察档案 → 观察币优先补数据与分析 → 条件满足生成交易计划 → 持续跟踪/降频/重新激活。

异动发现必须使用自身足够且新鲜的数据；发现后不要求所有K线、OI、市值齐全。缺少某项只阻止依赖该项的进一步分析，不删除已经成立的异动。异动信号不等于买入建议。

第一期建议先明确覆盖币安USDT合约和现货，资产聚合展示但保留市场来源；其他来源保留现有页面能力，接入新雷达须分别验证数据口径。不能要求进入候选后才订阅发现所需的数据。

### 3.1 触发入口与参数待定项

|入口|必需数据|建议讨论参数|不依赖|
|---|---|---|---|
|短时价格异动|同市场连续短时价格、样本覆盖及流动性资料|1/5/15分钟；绝对涨跌幅与相对波动条件|OI、市值、周线|
|成交额放大|同市场真实成交额分桶、足够历史基准|短窗相对基准倍数及最低绝对成交额；此前3倍仅候选参数|完整多周期K线|
|持仓异动|同合约同单位两个有效OI观测点|5/15分钟；数量变化结合价格，此前5%仅候选参数|CMC市值|
|已有结构附近异动|未失效结构位置、当前有效价格|接近触发位或回踩位，防重复触发|重新扫描全市场|

任一经过质量校验的入口可进入观察；上涨和下跌分开标注。最低流动性、窗口、倍数、冷却、异常报价过滤必须可配置、附规则版本。新币或重启后基准不足显示预热中；不能把未知当成零。

现有WS已有aggTrade、部分全市场价格流和K线订阅，应复用并核对覆盖，不能另建重复采集器。24小时滚动成交额不是5分钟成交额，不能简单差分冒充；使用逐笔聚合/官方分钟K线等适配来源。断线、乱序、重复成交按市场与事件标识处理，缺口降级并修复。

### 3.2 观察档案与长期跟踪

- 资产档案、异动事件、交易计划分层关联；同一资产可有多次事件和多个市场来源。
- 冻结首次触发时间、价格、原因、市场和规则版本；新增触发补充末次时间、次数与证据，不覆盖首次值。
- 保存当前价、首次以来涨跌、可观测最高/最低、最大有利/不利变化及数据缺口；有缺口不能宣称完整极值。跨市场不混算价格基准。
- 状态建议：新发现、观察中、重点跟踪、降频观察、已归档；分析状态单独为排队、补数据、完成、更新延迟、失败。
- 单个计划失效不自动结束观察。降频不删除档案，再次有效异动重新激活；新事件切分间隔和归档期限待定。
- 高频名额建议首期50个可配置；持仓/活跃计划及用户重点关注优先，保留新事件服务机会。超额事件仍保存并展示，注明深度分析排队，不直接丢弃。

## 4. 数据与计算架构

1. 接收层更新有界内存短窗；异动检测不等待全量策略扫描，不逐tick查询数据库。
2. 首次有效触发事务提交后即发布观察事件；后续量价变化合并更新，保留关键转折。复用事件流，增加有版本的观察变更事件。
3. 深度分析按instrument_id去重，合并相同任务，进行中只安排一次必要补算。既有25币轮询退为低频补漏，独立保证新事件和活跃观察服务机会。
4. 依赖变化才重算：新收盘K线触发相关周期分析，OI成功更新触发相关证据，报价更新复核入场范围；不用每个tick重算全部指标。
5. 分离慢网络、CPU分析、数据库短事务；测出连接池争用来源，限制同时需要数据库的任务，不把排队等待包在事务内。
6. 增量投影按资产/事件upsert并检查版本，避免旧任务覆盖新数据。现有publish会删除不在keep内的记录，绝不能直接把单批传给它；全量清理仅在明确的完整快照路径执行。
7. 重启恢复观察和待处理任务，事件幂等、重复触发不重复首警。预算恢复等待单独标识，不能伪装成供应商超时。协调5分钟恢复窗与2分钟排队期限冲突。
8. API返回发现时间、源时间、分析时间、发布时间、数据状态、缺少字段、下一步任务和稳定排序版本。前后端共享schema并明确未知值，禁止用0补空数据。

## 10. ERJI 最终执行设计（v1.0，尚未实施）

### 10.1 产品定位和顺序

首先发现值得观察的异常，再描述趋势和形成交易计划。第一期重点覆盖币安USDT合约及USDT现货；现有其他市场数据保留查询，暂不宣称新雷达全覆盖。向上、向下异常都记录，首页默认上涨/放量，风险异动可切换查看。

链路：全市场轻量行情 → 有效触发立即进入观察 → 六周期趋势与OI按可用数据逐项补充 → 符合已有交易规则时关联买入计划 → 持续追踪。

下表是ERJI建议初值，不是行业统一阈值，也不是收益保证。当前阶段仅更新方案，不启用新规则。第3节候选参数如与本节不同，以本节的建议口径为准。

### 10.2 首期触发设置

|独立入口|建议默认条件|显示标签|
|---|---|---|
|短线价格变化|滚动5分钟涨跌达到3%|短线走强 / 短线走弱|
|持续价格变化|滚动15分钟涨跌达到5%|持续走强 / 持续走弱|
|成交额异动|5分钟成交额达到此前10个完整5分钟区间平均成交额的3倍，且该区间成交额至少10万USDT|明显放量；达到5倍标记强放量|
|OI变化|同合约原生持仓数量在15分钟内增减至少5%；两端数据和时间均有效|持仓增加 / 持仓减少|

任一入口成立即进入后台事件处理，不要求同时满足；纯价格触发经过10.9的市场同向降噪后再决定是否成为首页新观察。量能或OI有效触发独立保留。同市场多条件触发合并展示原因。价格及OI变化为当前值/窗口起点值−1，不能把美元名义OI因价格上涨而增加误判为新增持仓。

建议基础流动性为同一原生市场24小时成交额至少100万USDT；不相加现货与合约。该过滤不是买入许可。新上市不足24小时按实际上市时长标明累计成交额，未达基础条件进入独立新币待观察区，不冒充标准池触发。稳定币对、杠杆代币、停止交易市场依交易所元数据排除。

价格、量能、OI分别检查自身数据是否有效；CMC身份、市值、资金费率、周线不作为量价触发前提。缺某项不能阻断其他独立入口。未知流动性标为待核实，不按0或无限处理。

### 10.3 秒级反应与完整窗口

价格入口按实时消息滚动更新，计算节奏目标每币1秒最多一次；窗口是回看长度，不是等待时间。取窗口起点附近可验证的样本，首期价格样本最大偏差建议5秒；无法覆盖完整窗口时该入口预热，不用首个刚收到的价格假装5分钟前价格。

放量使用固定UTC对齐5分钟区间。前10个完整区间均值排除当前区间；当前区间累计成交额已达到3倍且超过绝对门槛时可以提前触发，标明“盘中触发”，收盘后补最终数值。由于是累计额直接超过完整区间基准，不按经过时间外推、不把1分钟成交额乘5冒充最终值。未满足时继续等待，不以盘中低倍数判定缩量。

取消1分钟异动入口，也不为新雷达新增全市场1分钟K线订阅或常驻存储。发现层复用实时价格流和有界5/15分钟窗口；放量历史直接使用5分钟K线。已有行情可复用，但不伪造精确滚动起点。放量基准采用前10个完整5分钟桶，至少需50分钟有效历史；REST能补则直接补，不要求用户挂机50分钟。

OI目标采集沿用60/15/10秒；15分钟变化起点允许偏差建议不超过60秒，终点建议不老于90秒，展示实际跨度。超出范围只暂停OI触发，不暂停量价观察。不能承诺OI秒级。

### 10.4 六周期趋势：观察辅助，不做入库六重门槛

采用5M、15M、30M、1H、4H、1D六周期。周线保留给原策略或深入分析，不放入首页矩阵。每格显示方向、更新时间和是否预热，缺一个格不清空一行。

默认规则：价格与EMA50、EMA100形成多头排列显示↑，空头排列显示↓，其他显示—，资料不足显示○。用于稳定方向的EMA和比较价格采用已收盘K线，当前实时价格另显示；不让当前价跨均线产生频繁历史改判。

趋势标签分层：5M/15M/30M至少两个上行为“短线转强”；1H/4H均上行为“中期向上”；同时满足且1D上行为“多周期向上”。下行对称，方向不一致为“周期分歧”。不把一项标签直接转成买入。

BTC比较只在后台参与10.9的同向普涨降噪，使用同市场类型和同一时间窗口。页面不设置“相对BTC”列，不展示涨幅差、独立分，也不增加“BTC带动N个币”的分组卡片。六周期矩阵继续展示该币自身的趋势。

深度指标复用MACD12/26/9、RSI14、BOLL20±2σ；详情量能使用前20根完整K线均值、2倍为放量提示。首页异动量能使用前10根、3倍触发，两处明确显示RVOL10和RVOL20及各自周期，不能混为同一数值。这些常见指标只是解释证据，不通过机械叠加制造胜率。

K线获取按观察币需求进行。可从有连续性证据的5分钟收盘K线聚合15M/30M/1H；4H/1D复用原生窗口，避免为300根日线下载全部5分钟历史。EMA100至少100根才有最低计算基础，建议目标300根用于预热；未满足预热标为暂定，缺口优先定向补。只有收盘或历史修订才重算相关周期。

### 10.5 长期观察与高频名额

自动观察档案保存全部有效触发；高频深度分析初始50个名额是资源调度上限，不是只保存50个币。

建议分配：活跃计划、用户重点关注先分配；普通名额中保留20%给新触发，剩余按最新有效触发时间、异常幅度及等待时间公平调度。关注/计划超过容量时明确排队并报警示，不能声称所有重点都已获得最高频率。

同市场同方向在30分钟内重复触发合并同一事件，保留多个原因及重复次数；超过30分钟没有新触发后再触发建立关联新事件。方向反转单独事件；冷却只影响重复通知，当前不启用任何外发提醒。

两小时无新触发且没有活跃计划/用户重点关注时降频；七天无新触发转归档，保留档案并允许再次激活。这些是建议业务初值，可配置，不等于删除七天以前数据。原数据保留周期另行决定。

首次时间、价格、来源和原因冻结。高低点只依据实际观测，缺口明确标记；首次以来涨幅不是预测收益。交易计划失效不删除观察档案。

### 10.7 实施拆分与前后端契约

第一步在现有服务内修复连接池争用、长事务和增量投影。把批次扫描降为补漏之前先保证发现覆盖，不能直接删除现有扫描造成空窗。

第二步一次打通价格/放量→持久化异动→前端观察行→单币分析队列；第三步加入OI入口、六周期矩阵和长期状态。最终按本节范围完整交付，不把阶段一当作全部完成。

后端分开提供observation_status、analysis_status、data_status、trade_status以及discovered_at、source_at、analyzed_at、published_at；字段具体命名可在实现中统一，语义不能混用。SSE只通知变更ID及版本，前端增量读取，断线补读；单币发布不能调用旧publish的全量删除语义。

持续采集复用现有WS、预算所有者和数据库，不增加Kafka或新的行情采集体系。短窗保存在有界内存，事件及关键状态持久化；不新增逐tick原始事件副本。原raw_events治理仍另行讨论。

验收看真实行为：符合规则的异动不等待25币扫描即可显示；缺OI或高周期K线仍有观察行；首警不被刷新覆盖；慢任务不堵住其他币；旧分析不能覆盖新分析；六周期缺口明确可见；页面计数和API一致。全流程延迟实测分段报告，不用HTTP200代表功能恢复。

### 10.9 BTC同向普涨后台降噪（用户本轮确认方向）

目的：减少BTC短时上涨伴随大量山寨币同涨时的重复价格信号。属于统计分流，不能证明上涨因果；内部原因使用market_comovement，不写成“确定由BTC导致”。不增加前端BTC对比数字、相对强度列或普涨分组。

**识别顺序：**

1. 仅处理新发现、纯价格触发的向上事件，窗口为5分钟或15分钟。放量、OI入口独立有效，不因BTC同涨被否决；它们是值得继续分析的异常，不代表因果上独立。
2. 先确认BTC该窗口明显上涨且广泛市场同向，再比较个币是否具有超出普涨的变化。不能仅因BTC涨了0.1%就屏蔽所有上涨币。
3. 初始市场环境参数：BTC同窗上涨≥1%（5分钟）或≥2%（15分钟）；基础市场池中有效资产至少30个、有效覆盖≥70%，其中≥60%资产同窗上涨≥0.5%（5分钟）或≥1%（15分钟）。资产去重，现货与合约环境分别计算，同类型BTC作基准。这些是ERJI可配置初值，不是行业统一标准。
4. 市场环境成立、个币仅价格触发、个币涨幅领先BTC不足2个百分点、并且有效量能与有效OI均无额外触发时，记为普涨噪声：只合并保存后台事件，不新建首页自动观察行、不挤占高频分析名额。
5. 领先至少2个百分点，或者任一量能/OI入口有效，则保留正常观察和分析。若同一事件5分钟与15分钟两个价格入口均触发，只要其中一个有效入口未被判为跟随，就保留，不让短窗口抑制更强的另一窗口。
6. 本过滤针对用户指出的同向上涨；下跌价格事件按原风险入口保留，暂不把暴跌风险静默抑制。

**数据不足与误判处理：** BTC、市场广度数据缺失时为无法判断，不能冒充已确认普涨；价格事件保留，但按普通优先级调度。对有合约的币，OI数据不足不能视作“没有OI异常”；对任何币，量能基准不足也不能视作“没有放量”。此时只合并重复价格提醒，保留普通观察资格，不提升全部币为重点。无合约市场的OI为不适用，不要求补OI。利用有界分析队列限制成本，不靠静默漏报解决数据不足。

**持续跟踪：** 已有观察、用户关注和活跃计划不因过滤器触发被删除或停止。被抑制的后台事件在新价格/量能/OI到达时重新判断，最长保留本事件活跃期内必要短窗；后续独立异常成立即可晋升到观察。保存首次原始触发时间与首次成为可见观察的时间及对应价格，页面首警后涨幅以首次可见观察为基准，避免把隐藏期间涨幅当作用户可见收益。

后台事件按市场/方向/窗口合并，记录规则版本、抑制原因、复核和晋升时间，不逐tick写库。页面观察数量只计可见观察，技术诊断可查被抑制事件；不恢复定时监控或外发通知。

**局限：** 首版同期涨幅差不能完整消除山寨币高波动带来的误判。先用可解释条件与历史普通行情、普涨、逆势、放量样本核对；不在首版引入高复杂度相关性或beta模型，也不宣称已识别真实因果。
