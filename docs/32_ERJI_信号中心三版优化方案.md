# 32 · ERJI 信号中心三版优化方案

状态：已选定 A「分级决策长表」作为正式优化方向；本次为 A 版丰富字段预览，未替换现有业务页面。

共同目标：尽快发现值得行动的代币，清楚说明买入条件、保护、目标与依据，并持续跟踪信号变化。

共同信息架构：顶部只保留「信号中心｜系统状态｜设置」。信号中心合并买入机会与有意义的市场异动；当前信号、我的跟踪、历史记录在页内切换。系统状态合并运行监控、数据健康与运行日志。设置收纳策略和 Telegram。

| 方案 | 优先解决的问题 | 主页面组织 | 取舍 |
|---|---|---|---|
| A 分级决策长表（推荐） | 多代币比较不方便、信息分散 | 可买入、等待买入分区；异动观察默认收起；证据按需展开 | 桌面信息密度最高，小屏需要横向滚动 |

## 推荐方向

以 A 为首页，沿用用户接受的长表。B 作为表达简洁程度的对照；C 的状态变更时间线可吸收进代币详情，不必再创建一级页面。不建议将三种布局全部同时上线。

## A 版主表字段（本次丰富）

主表保留对行动有直接影响的字段，避免把研究指标全部堆在首页：

- **现在怎么做 / 判断**：行动标签、触发原因和直白的执行动作，例如“现价在计划区，可按计划分批”或“等待 4H 收盘突破，现价不追”。
- **现价 / 首次信号价**：显示当前价格、首次发现价格和相对首次信号的变化，便于判断信号是否已经走远。
- **买入条件 / 保护**：价格区间或收盘确认条件、保护价、当前技术阶段（例如 4H 箱体突破确认、突破后等待回踩）。
- **第一 / 日线 / 周线目标**：三层目标分别显示；目标必须有对应周期和结构依据，数据不足时显示“待形成”，不推测数字。
- **1H / 4H / 1D / 1W**：四个周期同时显示方向与状态，例如上行、转强、突破确认、整理、待确认、历史不足。
- **合约 OI / 流通市值**：OI 名义金额、OI/流通市值比例、数量 OI 周期变化和参考费率；没有已核验合约时标记“不适用”。
- **证据入口**：点击后查看箱体上下沿、触发价、量能倍数、距触发/保护距离、清算观察、平台覆盖和完整失效条件。

### 仍然建议放在详情里的数据

清算热区、各平台 OI 明细、资金费率历史、订单簿深度、VPVR/Anchored VWAP、K 线指标参数、距 ATH 和完整事件时间线会增加主表宽度。它们作为点击后的证据层提供，只有在对应信号需要解释时加载。

## 颜色语义

A 版新增低饱和颜色提示：绿色表示可执行或正向变化，蓝色表示计划区和等待确认，橙色表示等待条件，红色表示保护、失效或下行，紫色表示目标位置，灰色表示数据不足或不适用。颜色只辅助扫描，文字、数值和数据状态仍是判断依据。

## 数据与决策边界

- 所有预览中的资产、价格、持仓和时间均为虚构示例，醒目标注；未读取实时 API、未降低真实信号门槛。
- 已确认买入和小仓提前布局放在同一区，明确执行强度差异。等待计划必须给出具体价格或确认条件。
- 上涨伴随增仓是判断依据，不自动推导可以买入或轧空概率。数量 OI、OI/流通市值和费率分别标注口径。
- 主池按币安及已确定链上池规则；辅助平台不独立扩池。身份核验后按资产归并，跨平台去重，不按同名直接相加。
- 没有合约时标记不适用；缺失数据、条件未成立和运行故障分开解释。
- 正式实现的价格、描述、K线标注、目标和失效规则必须来自同一决策快照。预览未伪造已实现的真实图表。
- 首次信号、升级、失效保留历史；本原型仅演示跟踪选择（浏览器 localStorage），不是后台持久化日志。

## 性能约束

- 当前信号读取精简预计算结果，分页；首屏不加载每个资产的K线、平台明细或完整分析。
- 点击查看证据后按需读取详情；系统状态只读本地统计，日志按需分页。
- SSE 与补偿轮询不并发重复；隐藏页面暂停刷新；页面访问不增加交易所采集频率。
- 正式版需分别验收首屏数据请求及详情请求在目标负载下的延迟；2 秒超时预算不能代替响应成功率与 P95 测量。
