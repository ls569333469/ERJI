## 2. 新的核心输出：结论、依据、可执行性

### 2.1 每个代币必须给出一份明确交易观点

核心输出升级为“现在怎么做、本轮主要看哪里、还有多大级别的机会、什么条件改变观点”。系统必须选定一条当前主判断，给用户可执行的方向；专业指标是形成判断的证据，不能让用户读完词条再自行决定。

1. **当前建议：** 建议现在布局、建议提前布局、等待具体价格、暂不追入、继续持有、按计划减仓或退出。说明使用进攻型还是确认型方案，区分新参与与已有计划。
2. **交易定性：** 当前更像短线反弹、日线趋势启动、多周期上涨展开、强势再突破、清算推动延续还是高位转弱；选一个主判断，附最有解释力的2–3项证据。
3. **主攻目标：** 给出本轮首选目标区、相对现价上涨百分比和价格倍数、来源/周期与前置关口。不能只展示最近阻力然后结束长期判断。
4. **更大空间：** 必须给出“日周条件成立后的本轮最高目标价”，并列美元价、上涨百分比与价格倍数；分开列日线、周线延伸目标与ATH参考；明确“具备倍数级结构空间 / 仅有远端历史空间 / 当前不支持倍数判断 / 历史不足”。有数据时必须做出选择，不仅说可能上涨。
5. **当前布局方式：** 参与区、当前是否在区内、已满足触发、未确认高周期条件、允许追加的条件、计划有效期与保护价。没有当前入场机会时仍给出方向与下一可执行门槛。
6. **推翻与持有管理：** 明确哪个价位/收盘条件会撤销主判断、哪个条件只取消周线延伸、何时减仓或继续管理余仓；不能用“注意风险”“保持关注”替代。
7. **判断质量：** 展示依据、反证、数据缺口及历史验证状态。规则观点可以明确；概率、预期收益和达标时间有各自数据门槛，未经验证不编数字。

**表达要求：主张先行，数字落地，条件具体。** 合格输出如“建议现在布局，按日线趋势启动交易；本轮主攻1.80–2.00，周线进一步转强后上看2.80–3.00；跌破0.90退出本计划”。正式价格必须来自同一计划及快照，示例不作为任何币的默认目标。

### 2.2 七个对象独立存储，联合展示

| 对象 | 示例 | 含义 |
|---|---|---|
| 行情事实 fact | 日线MACD金叉已收盘、4H数量OI增加 | 已观察事实及时间，不承担完整交易建议 |
| 行情阶段 phase | 日线趋势启动、周线转强预备、趋势延续 | 说明当前处于哪一段 |
| 交易观点 trade_thesis | 当前看多，建议布局；主攻日线目标，周线延伸待触发 | 必须给方向、主目标、理由、反证、升级/推翻条件和版本 |
| 证据等级 evidence_grade | 结构与成交支持、周线尚未确认、费用有分歧 | 解释观点强弱及缺口，不等于70%/90%胜率 |
| 参与行动 action | 建议现在布局、等待回到参与区、停止旧计划 | 结合现价、成本、时效、风险和执行能力 |
| 空间方案 opportunity_plan | 最近关口、主攻目标、周线延伸、ATH参考与价格倍数 | 包含本轮最高条件目标的明确美元价；主目标、延伸和历史参考各自标来源，不能拼成虚高净R |
| 验证统计 validation | 同类计划达标率、MFE/MAE、样本不足 | 统计适用目标、时域、样本和校准状态独立保存 |

技术条件与执行检查合格时，允许明确建议布局，即使没有辅助OI或清算图；缺失说明随观点展示。出现“看多但现在不追”时，必须同时给等待的价位与重新参与条件。缺少基础证据时应明确“当前不支持上涨判断”，并指出阻断项；这是一项完整判断，不用模糊词条占位。

### 2.3 一份主观点，两类条件延伸

每个事件只展示一份当前主观点：方向、交易定性、主攻目标、有效窗口和进攻/确认方案。次级区域作为沿途关口，较远周线/ATH区域作为条件延伸，不把所有相反方向并列后让用户自行选择。

“建议主攻2–3倍机会”必须有对应的目标价格与算法来源、当前结构依据、必要数据、沿途关口和执行计划；“距ATH有4倍空间”只有历史价格距离，尚不能自动入选倍数机会。证据足够时系统应明确选定倍数级主线；不够时明确降为短线/日线目标，而不是用固定模板对每币都显示大倍率。

目标区域被突破后继续更新更大周期观点；原Plan的T1、保护、入场时效与历史结果保持冻结。较近目标到达可以按已登记计划部分兑现并继续跟踪余仓，不能把第一阻力当成整个行情的终点。

## 3. 参与决策规则与禁止永久空转

### 3.1 决策优先级

| 优先级 | 条件 | 新参与行动 | 已有/纸上仓位口径 |
|---|---|---|---|
| 1 | 保护触及或事件已失效 | 停止旧计划，展示触发价/方式/时间 | 给出退出参考及记录，不伪称订单已成交 |
| 2 | 必需报价/盘口过期、身份冲突、必要链上交易性未验证 | 暂停参与，列具体缺口和最近有效时间 | 保留已知保护价，显示数据暂停 |
| 3 | 结构尚未触发 | 等待触发，明确收盘门槛、成交要求和周期 | 依已有独立计划管理，不创建新买入 |
| 4 | 入场窗口到期 | 等待新计划，原窗口不可续命 | 原趋势和保护管理可继续 |
| 5 | 现价超过原参与带或成本/净R不合格 | 不建议追入，列超价/空间/成本原因 | 持有管理独立判断 |
| 6 | 当前价格低于有效参与区，结构仍未撤销 | 等待到价，列区间与确认条件 | 按原保护/撤销规则继续 |
| 7 | 早期策略触发、位置与执行条件合格 | 建议试仓，明确4H未确认 | 采用该模板保护和风险预算 |
| 8 | 确认/回踩/再启动策略触发且条件合格 | 建议参与，说明具体模板 | 给出目标到达后的减仓/持有方案 |

到期、过期、超价等可以同时存在；主行动按优先级选择，全部原因保留。动作返回机器码、中文结论、主要理由、支持/反对/缺失、下一触发条件，不允许只返回“待核”而没有可理解原因。

### 3.2 可执行性与净R

继续采用PD1：试仓净R≥1.5、确认净R≥1.8，均为可配置研究初值。做多按冻结参与区上沿E、保护价S、第一有效目标区下沿T计算：

`净R = (T - E - 盈利路径每币费用) / (E - S + 止损路径每币费用)`

费用包括双边手续费、对应测试金额的预估滑点及计划持有情景的资金费用。未来资金费只能是标明假设的情景估计，不能当已结算事实。成本模型须记录fee schedule来源、档位假设、估算时间与规则版本；不能默认为零，也不必依赖连接用户真实交易账户。

- 采用明确的研究测试金额，默认$1,000，或用户配置的金额；报价/深度与该金额一致。未提供本金时不给虚构持仓数量，可展示该测试金额下的可成交性。
- 最佳买卖价/最新成交价格用于参与检查，mark用于其适用的保护/清算语义；不得把几分钟前的mark当当前可成交价格。
- 报价默认≤15秒、盘口≤10秒；实测无法满足时只暂停该市场的即时参与能力，保留结构和等待条件。
- T≤E、S≥E、成本未知或不可成交时不能生成净R。远周线目标不能绕过更近阻力放大收益比。
- 无上方历史阻力时，允许策略预先声明的箱高测算目标，明确标“测算”；没有可用目标的模板不能伪造净R。

### 3.3 四个模板必须真正产生计划

| 模板 | 触发 | 正式输出与数据需求 |
|---|---|---|
| early_breakout | 1H闭合突破冻结4H边界与缓冲，成交增强 | 有效位置与成本合格时建议试仓；保存提前触发时间，不能冒称4H确认 |
| confirmed_breakout | 4H闭合突破及成交规则 | 建议参与；冻结参与带、保护、撤销和第一目标 |
| retest_entry | 确认突破后实际回踩，1H收回边界并满足成交规则 | 独立回踩episode/plan，不能仅价格回到箱顶就建议购买 |
| trend_restart | 活动趋势内形成新有效结构并再次触发 | 新episode沿用campaign首报，原计划历史保留 |

窗口、ATR、回踩6根4H、参与有效期等继承PD1登记表，全部进入配置版本。不得只实现“触发事实”并永久统一返回execution_pending；W05交付需用受控行情证明四模板能产生、更新、撤销其应有行动。

### 3.4 进攻型方案：提前布局，确认后升级

新增analysis.style，默认展示用户偏好的进攻型研究方案，同时可切换确认型对照。进攻型允许更早参与已经触发的小周期/日线结构，并持续评估尚未闭合的高周期条件；确认型等待模板登记的更高确认门槛。两种方案都给明确目标和行动，不用“可以关注”作为最终建议。

| 当前条件 | 进攻型建议 | 后续升级或撤销 |
|---|---|---|
| 日线交叉/结构已确认，1H提前突破已成立，周线正在转强 | 建议提前布局；采用已验收early_breakout计划，标明4H/周线哪些仍待确认 | 按原4H规则确认后升级；保护触发退出，不等待周线 |
| 日线改善、4H确认突破成立，周线盘中接近或出现交叉 | 建议现在布局；按confirmed_breakout参与，周线作为更大空间的条件 | 周线收盘满足预先计算的条件后激活延伸；未满足时撤销该延伸，不伪造周线确认 |
| 日周趋势有效，短线回踩至预定参与带且retest_entry成立 | 建议回踩布局；给具体区间与原保护 | 回踩失败按原计划退出；未实际回踩不提前声称可成交 |
| 日线只发生金叉，结构仍未触发或目标/成本不合格 | 暂不买；明确差哪条规则和哪个价位触发 | 达到入场模板才变更行动，交叉本身不替代交易计划 |
| 上涨延续但当前超出原参与带 | 看多延续，等待新参与点；已有计划按登记方式持有/兑现 | 突破回踩或再启动形成新Plan，不能把原区间向上移动追价 |

保留四个P0入场模板及action机器码。trial可按上下文展示“建议提前布局（早期触发）”，participate展示“建议现在布局（结构确认）”；不能只换标签却隐去确认级别。analysis.style影响所选已验收模板、确认偏好及风险预算版本，不默认增加杠杆，也不降低数据真实性/身份/执行时效要求。

初始仍用早期净R≥1.5、确认净R≥1.8的研究门槛，最近有效目标参与计算；远周线目标不代替近期可实现收益。所有加仓建议需新的有效触发、剩余风险预算、流动性和合并后的风险检查，不能因为周线转强一句话就自动追加仓位。未配置仓位时给价位与条件，不编金额或仓位百分比。

周线尚未确认时可以提前交易日线/小周期计划，但系统同时明确“本轮先交易什么、周线成立后再升级什么”。周线未交叉不自动证明已经触发的日线计划失败；若原计划把周线确认登记为必需到期条件，则按该冻结条件处理。

## 4. 上涨依据与合约词条的正式解释

### 4.1 证据等级采用规则，不使用匿名总分

证据按组记录：结构、成交、日周背景、持仓数量、费用、实际清算、平台分布、身份/数据质量。每组有support/opposition/unknown/neutral及原始值、比较窗口、来源、known_at；同一原始数据的派生值不得重复计为多个独立确认。

| 等级 | 判定规则 | 页面含义 |
|---|---|---|
| 依据较充分 | 当前策略预先登记的必需方向条件均满足，必需数据有效，无该路径的关键反向条件；区分早期/4H/回踩确认级别 | 可以解释为何偏多；行动仍单独经过价格、成本、时效检查 |
| 依据有分歧 | 有偏多结构证据，同时存在当前规则定义的实质反向证据 | 列出分歧及其动作影响；硬否决转暂停/不追，软分歧不能被悄悄忽略 |
| 依据不足 | 尚无已触发结构，或所声明判断路径缺少关键证据 | 具体说明等待条件；不显示虚构概率 |

技术路径的必需条件为相应模板的结构、闭合柱与成交确认；日周趋势、OI和费用按模板配置分别列必需或辅助。日周历史不足不能自动取消可用短周期技术计划。压力路径声明为必需的数据不足时，降回技术路径评估，不能继续保留已确认合约压力标签。

### 4.2 词条必须完成判断，不能把问题留给用户

后台先把原始指标放进具体位置、成交、结构与费用环境，再输出交易观点。主行展示“判断＋行动＋目标/失效点”，原始词条进入依据详情。以下组合是必须实现的判定分支，所有边界与参数登记为规则版本；真实输出用具体价格替代文字占位。

| 已核验的组合条件 | 系统应给出的交易判断 | 当前行动 | 升级或推翻判断的具体条件 |
|---|---|---|---|
| 日线金叉确认、有效结构向上，周线接近交叉；入场模板已触发 | 日线趋势启动，周线有进一步展开条件；值得提前布局 | 建议提前/现在布局，给日线主目标和周线条件目标 | 展示周收盘交叉门槛；日线/执行计划保护被触发则退出，周线条件未成只撤销依赖它的延伸 |
| 多个周期结构同向、成交支持，现价仍在参与带 | 多周期上涨展开，适合按波段而非只按小时目标管理 | 建议现在布局，明确主攻周期及目标；已有计划保留趋势跟踪 | 具体主趋势保护被破坏才撤销该观点，短周期回调按原计划区分 |
| 上涨＋数量增仓＋确认突破＋成交承接 | 趋势扩张得到支持，本轮偏多 | 建议参与当前有效突破计划，目标来自日/周结构 | 指定周期收回箱内或保护触发改变行动 |
| 上涨＋数量减仓＋真实空头清算＋现货买盘继续 | 回补伴随新增买盘承接，上涨仍有延续依据 | 有有效新计划则建议参与；已有计划继续管理余仓 | 清算后推进停滞且具体结构转弱则减仓/退出，不把每次清算都加成收益目标 |
| 上涨＋数量减仓，但买盘不延续、触及前高后回落 | 本轮更偏回补反弹，当前不支持主攻大倍率 | 暂不追入；已有计划按目标兑现/保护退出 | 再次放量通过前高并形成新计划，才升级趋势观点 |
| 下跌＋数量增仓＋确认支撑失守 | 当前下行占优，缺少反转依据 | 不建议买入；已有多头触发原保护则退出 | 收回具体失守价并满足反转/回踩模板后重新评估 |
| 下跌＋数量减仓＋多头清算，价格仍未收回支撑 | 去杠杆正在发生，当前还不构成有效底部 | 暂不抄底，列出重新站回的价位 | 支撑收复、成交与有效入场模板成立后才建议布局 |
| 负费率持续＋数量异常扩张＋价格突破并保持强势 | 空头成本压力叠加向上结构，具备挤压延续的条件 | 合格计划建议布局；列最近清算区与日周主目标 | 真实清算后继续承接可升级；结构失效则退出，不以负费率对抗下跌 |
| 只有一次负费率，价格/结构未改善 | 暂无独立买入优势，付费现象不足以支持上涨观点 | 当前不因该词条买入，给缺少的结构门槛 | 达到具体结构条件后再联动费用判断 |
| 数量OI异常扩张但价格困在箱内 | 杠杆活动升温、方向尚未由价格确认 | 设定上破/下破价；达到上破早期模板即可提前布局 | 在冻结边界触发对应分支，不能仅凭OI扩张建议做多 |
| 高位整理后再次确认突破，费用与流动性未触发否决 | 上涨出现新的延续机会，原先涨幅不自动代表见顶 | 新建再启动Plan并建议参与，给新的入场和目标 | 新结构保护与撤销点独立登记，不沿用早期低价计划 |
| 跨平台OI集中于Aster/HL且同场结构、成交支持 | 该平台是主要合约活动来源，重点监控其价格与清算链路 | 对映射正确、可执行的计划明确布局与监控场所 | 集中度只描述已覆盖范围；身份/覆盖变化暂停相关推断 |
| 价格远离参与带＋持续正费用异常＋增仓拥挤＋突破失败 | 当前追价收益风险不合格，上冲延续观点转弱 | 不建议新增追入；已有计划按原规则减仓/退出 | 回到合理位置并形成独立新计划才重新建议 |

数据不够时也必须给可理解的结论，例如“技术上看多并可布局，但清算依据缺失”，或“缺少执行盘口，当前暂缓买入”。“检查成交”“依结构判断”“提高关注优先级”可以作为内部待办，不能作为面向用户的完整交易结论。

### 4.3 合约组合规则的首批落地

- 保留趋势扩张与空头成本压力两条路线，不能只筛深负费率。技术成交确认沿用相对报价成交额≥1.5，强成交2.0；所有数值为研究参数。
- 数量异常沿用同币可比基线：正变化≥P90/P97.5为异常/强增长，负变化≤P5为快速解除。基线不足显示幅度与样本数，不输出假分位。
- 费用异常沿用实际24H已结算费率和为负且≤自身P10。新增“连续负结算至少3次”作为持续费用标签的初始辅助门槛，显示各平台实际结算次数和持续小时，不能假设均为8H。
- 上述慢变量组合沿用3次、间隔5分钟的防抖；实际清算和保护退出立即处理。回放要包含负费率继续下跌的反例。
- 多头拥挤组合阈值必须与费用正向分位、数量异常、追价行为及失败样本一起发布；在未完成规则验收前只展示原始证据，不上线一个不可解释的“拥挤分数”。
- OI/市值是规模背景。不得将3%/10%/25%直接映射为“控盘程度”“庄家操盘”或“轧空概率”。

### 4.4 主行文案示例（仅表达规范）

以下数字为假设样例，正式输出必须来自当前真实计划与同一快照，不注入真实信号列表。

- 建议现在布局｜日线趋势启动、周线待确认｜参与$0.98–1.02｜日线主攻$1.80–2.00｜最高条件目标$3.00（+200%，3倍）｜保护$0.90。
- 建议提前布局｜1H触发、4H未确认｜给具体参与区/保护｜日线主目标与待激活周线最高目标并列。
- 看多延续，当前不追｜现价超原参与带｜列下一回踩价与触发条件｜最高条件目标仍显示；已有Plan按原保护管理。
- 当前只支持短线反弹｜日周下行未修复｜若短线模板合格则给短线参与价和目标｜不宣称已成立倍数趋势。

原始OI/金叉词条置于支持或反对证据中。主行不能只有依据较充分、可以关注等描述；要有系统选定的主观点、当前行动及最高条件目标的状态。

### 4.5 规则画像与反向证据的动作影响

| 画像 | 必需方向证据 | 辅助证据 | 不能自动推出 |
|---|---|---|---|
| 技术早期 | 合格冻结4H结构、1H闭合触发和规定成交条件 | 可用日周背景、OI/费用/现货证据 | 已经4H确认、空头即将强平 |
| 技术确认/回踩/再启动 | 各模板要求的闭合结构、实际回踩/新结构与成交条件 | 合约证据和更大周期背景 | 成交量大就必涨、T1是最终顶部 |
| 持仓扩张支持 | 已触发技术计划、同窗口正数量增长与合格可比基线 | 现货承接、费用、平台分布 | 增加的仓位都是多头或空头 |
| 空头成本压力支持 | 未失效的偏多技术计划、完整实际负费用序列及已登记异常/持续门槛 | 空头清算、现货承接、异常平台OI份额 | 必须发生强平、存在可精确计算的百倍终点 |

压力画像是对技术计划的附加解释。当前结构有效但辅助条件反向时标分歧；只有预先登记为硬否决的规则才能阻止该路径发布。费率为正、OI下降、缺少清算或缺少日周历史不能被通用地设成全部技术计划的否决条件。硬否决示例为必需触发被撤销、执行报价过期、身份冲突、不可成交、净R低于模板要求；软分歧必须有具体数据和规则依据。

每个画像登记rule_id、版本、适用策略/市场、必需与辅助字段、比较窗口、阈值、否决级别、动作映射、正反fixture。未经验证的软分歧不得通过前端自行扣分或偷偷把建议参与改成观察；如要降为试仓，必须使用已登记的独立行动规则和风险预算。


### 4.6 从指标事件到参与判断：日线金叉模板

本节落实新的核心要求：每次识别出金叉、突破、回踩或持仓异动，都必须继续判断其交易意义、延续证据、动能、位置和行动，不能用“出现信号，可以关注”结束分析。该要求适用于所有已支持的形态，不限定于金叉。

先明确金叉是哪一种：MACD DIF/DEA、EMA20/EMA60、SMA50/SMA200分别有不同含义与样本，不能统一叫“日线金叉”并共用成功率。保存indicator_id、参数、价格输入、日K边界、执行市场、触发K线与known_at。以下以日线MACD(12,26,9)为说明模板，不将其未经验证地新增为第五个P0独立入场策略；首批用于完善现有四模板的日线背景和参与解释，独立金叉交易策略另行回放验收。

| 判断层 | 系统需要回答 | 决策输出 |
|---|---|---|
| 1. 事实确认 | 昨日DIF≤DEA且最新已闭合日K的DIF>DEA是否成立？数据是否足够，是否使用未收盘值？ | 已收盘确认 / 盘中暂现 / 无金叉 / 数据不足；给发生时间，不把盘中交叉提前确认为日线 |
| 2. 所处环境 | 是上升趋势回调后的恢复、下跌趋势反弹，还是震荡区内反复交叉？价格与冻结结构、日周压力是什么关系？ | 趋势延续支持 / 反弹支持有限 / 震荡噪声风险 / 证据不足，附规则与反证 |
| 3. 后续延续证据 | 结构是否改善、成交是否承接、现货主动买入与合约增长是否相互支持？哪些是未知？ | 偏多支持程度及相反路径，不从交叉本身跳到“之后一定上涨” |
| 4. 动能状态 | 价格推进是否加快？动能差值是否扩大？成交承接是否持续？ | 增强 / 维持 / 减弱 / 分歧 / 未知，并提供对应原始指标与窗口 |
| 5. 位置与空间 | 从当前可执行价格到下一真实阻力还有多远？已涨多少、是否超参与带？ | 当前剩余空间、第一目标与条件性后续目标、成本后净R；不是从最低点算出来的虚高涨幅 |
| 6. 参与行动 | 匹配哪一个已验收入场模板？现价、盘口、成本、时效和保护是否合格？ | 建议参与 / 建议试仓 / 等待触发或到价 / 不建议追入 / 暂停，必须给具体原因 |
| 7. 持续更新 | 哪个条件改变原判断，什么时候重新评估？ | 盘中保护及时处理，1H/4H及下个日K分别更新其负责的条件；保留原版本 |

“有效”必须拆开记录：event_confirmed表示交叉事实已经成立；context_assessment表示当前趋势与成交证据是否支持其交易意义；predictive_validity表示该类条件在独立历史评估中是否具有预测/净收益增量。前两项成立不能自动证明第三项；第三项暂未成熟也不统一阻断已符合其他入场策略的建议。

零轴上下、DIF/DEA距离、价格位置可作为背景特征，不把“零轴上金叉必涨”“零轴下金叉无效”写成未经验证的通用规律。MACD金叉、柱值转正和快慢线差值同源，不能重复算三票支持。

### 4.7 动能必须有可复算的数值，空间必须有条件

主行给一个简洁动能判断与最有解释力的2–3项数据；详情查看其余证据。所有数值按相同执行市场、闭合窗口和known_at计算，未知不给0。以下为首批研究候选特征，启用组合阈值需登记规则和回放，不能凭多个指标“看起来不错”生成动力分数。

| 维度 | 可量化的证据 | 用途与限制 |
|---|---|---|
| 价格推进 | 已闭合日K的ROC3D、ROC7D及其变化；当前价距EMA20的ATR倍数 | 区分正在加速与已经追高。涨幅是历史事实，不是未来预期收益 |
| MACD变化 | 明确定义H=DIF−DEA；H/ATR14、(H本日−H前日)/ATR14本日 | 描述价格动能及变化，跨币比较需标准化；若图表柱为2H需标明倍数，不混用 |
| 成交承接 | 最新已闭合日K报价成交额 / 前20根已闭合日K报价成交额中位数，排除当前柱 | 显示具体成交倍数；缺20根则样本不足，不用未闭合全天量相比 |
| 买盘来源 | 同窗口现货/永续主动成交差额、价格推进与两侧可成交深度 | 区分现货承接、合约驱动或分歧；主动差额不是资金净流入，不能据此证明因果 |
| 合约支持或风险 | 数量OI4H/1D、主平台实际费用及异常平台、真实清算 | 解释增仓、成本压力和拥挤；不从OI净增推断新增仓位的单边方向 |
| 剩余空间 | (目标区下沿 / 当前可成交参考价 − 1)，并列距保护幅度、净R | 目标来源、周期、前置条件明确；第一目标先行，不把周线远目标视为必达 |

“动能增强”的可发布规则至少要明确比较窗口、变化方向/最低幅度、必要承接证据和冲突处理；首次实现时未完成某组合验证，先输出数值与“该动能组合尚未验证”，不能自造“动能85分”。价格派生指标属于同一证据组，不把ROC、MACD、EMA当三份独立验证。ATR衡量波动与距离，不直接决定涨跌或目标。

输出三条条件路径：基准路径（在已确认支撑上方测试下一阻力）、延续路径（突破并按原规则确认后更新更高目标）、失效路径（具体保护/收盘撤销）。每条有价位、条件和评估窗口；统计未验证时不编概率。目标距离表示空间，预期收益/未来MFE分位必须来自§5规定的适用样本或已验证模型，不能用“动能强”换算预计上涨30%。

### 4.8 用户最终看到的表达示例

以下全部是假设数据，用于展示产品应有的判断力度与算术，不对应任何实时币种，不写入真实信号。

**现价$1.00，建议现在布局；日线主攻$1.80–2.00。日周条件全部成立后，本轮最高目标$3.00（上涨200%，价格3倍）。**

现价1.00，参与区0.98–1.02，当前在区内；日线MACD金叉已收盘，4H结构突破及成交条件已成立。本轮日线目标相对现价约+80%～+100%；周线延伸约+180%～+200%，也就是价格达到现在的2.8～3倍。周线尚未收盘确认，先按有效日线/4H计划布局。

假设快照计算的周收盘交叉门槛为1.08：本周收盘高于该门槛只是完成MACD交叉这一项；激活周线延伸还需日线收盘突破示例关口1.80、该日成交额至少为前20个完整日中位数的1.5倍，且已登记日周结构有效。届时按同一规则重新评估，不提前写“周线已确认”。

先经过1.30这一关：它是近期兑现/再评估位置，不代表本轮最终顶部。计划保护0.90，触及则退出本次计划；另有4H收盘低于0.96时撤销突破计划的规则，哪个先触发就先处理。减仓比例与余仓保护由参与前保存的计划决定，不能临时改变来维持远目标。

假设已核验ATH=4.00：回到ATH的价格是当前4倍，需要上涨300%；目前仍比ATH低75%。**当前主判断是日线1.80–2.00，条件延伸为周线2.80–3.00；4.00是下一阶段的历史参考，尚未激活。** 这些目标假设各自有真实结构/测算来源，不能只因金叉或距ATH很远自动生成。

正式页面首先展示加粗的一句话与当前行动，展开再看参与区、沿途关口、周线门槛、ATH与反证。系统给出首选观点，用户不必自行把指标拼成交易判断。

### 4.9 可配置多周期判断与各周期剩余空间

新增核心要求：对同一资产同时分析配置中启用且数据合格的多个周期。1H、2H、4H、1D、1W为本次讨论示例和首批预设，不是硬编码上限；可按数据能力扩展更短、更长及中间周期。用户应能看懂“短线、中期、长线是否都支持上涨；各自还可看到哪里；现在如何参与或继续持有”。日/周目标保留为长趋势骨架，补齐1H/2H/4H目标和同向/冲突解释；不能只显示一个4H目标，也不能把第一阻力当成整轮行情终点。

#### 4.9.1 每个周期分别回答，不将金叉换算成固定涨幅

| 字段 | 输出要求 |
|---|---|
| 当前方向 | 偏多 / 偏空 / 震荡 / 待确认 / 数据不足；给已闭合K线截止时间、结构与反向证据 |
| 金叉状态 | 指标和参数、是否新触发、首次确认时间、触发至今涨幅、是否仍维持；不能要求五个周期在同一时刻新金叉 |
| 动能状态 | 增强 / 维持 / 减弱 / 分歧 / 未知；按本周期的价格推进、标准化指标和成交承接计算 |
| 周期目标 | 下一有效阻力区、依据类型、确认时间、数据长度、失效/更新条件；区分历史压力与策略预先定义的测算 |
| 剩余空间 | 以同一个当前可成交参考价P计算(目标区下沿/P−1)×100%；与首报至今已涨幅分列 |
| 参与或持有影响 | 当前入场角色、是否阻挡更大目标、是否需等待突破/回踩、对原计划的保护和减仓规则有什么影响 |
| 统计验证 | 有适用历史样本时给指定H窗口的目标到达率、最大有利/不利变动分布；无有效统计则明确未知 |

“金叉能量20%”拆成两个可核实的答案：其一是当前动能是否增强，其二是到本周期目标还剩20%的价格空间。后者来自结构或已登记测算，不由金叉角度、柱长、周期大小直接推算。模型预测的未来涨幅区间仅在本域独立验证通过时增加，不能把目标距离改名为预期涨幅。

高周期目标不保证比低周期更高，不强制目标价格随周期递增。若日线阻力比4H测算目标更近，应将该阻力列为先行障碍，不能忽略它提高净R。跨周期同价目标合并为同一价格区域并保留全部来源，不重复计算多份上涨空间。

#### 4.9.2 同向、冲突与参与判断

所有启用周期使用同一snapshot时点之前各自最新可知的已闭合数据。持续偏多状态与新金叉事件分开：日线可保持偏多多日，1H可能期间出现回调和再次金叉；不能因日线今天没有“新交叉”就判日线不支持。

- 以示例五周期为例，全部数据有效且方向偏多，可显示“1H到周线均支持上涨”；实际按已发布周期集合生成文案。这表示方向一致，不能将同一价格序列派生的多个周期当成多次独立概率验证。
- 只有部分周期可用时显示“已覆盖3个周期均偏多；日/周线历史不足”等实际覆盖。不得把3/3包装成5/5共振；各入场模板按其必需与辅助周期运行，不统一等周线后才能参与。
- 短周期偏多、日周偏空时，明确“短线反弹，尚未形成日周上涨趋势”；依已登记策略判断是否仍有短线机会，不能承诺长趋势目标。
- 日周偏多、1H/2H转弱时，明确“长趋势仍在，短线回落”；新买入按回踩/再启动模板评估，已有仓位按原保护计划处理。短周期转弱不自动判长期趋势结束，长期偏多也不能覆盖已触发的短线保护退出。
- 所有周期偏多，但现价超过参与区、近端阻力过近、成本/流动性不合格，仍应显示“不建议现在追入”，并保留长趋势判断。方向一致本身不是新增入场策略。

#### 4.9.3 面向用户的多周期空间示例

以下数字仅展示布局，全部为假设，不是市场预测、固定倍率或策略默认值。假设同一执行市场当前价为1.00：

| 周期 | 当前判断 | 该周期上方目标 | 距现价剩余空间 | 实现后续空间的条件 |
|---|---|---|---|---|
| 1H | 短线向上，动能增强 | 1.20 | +20% | 当前短线结构保持，先测试最近关口 |
| 2H | 短线趋势延续 | 1.30 | +30% | 1.20通过本计划的确认规则并保持承接 |
| 4H | 本轮上涨结构成立 | 1.40 | +40% | 前序阻力依次通过，4H结构未撤销 |
| 1D | 日线趋势向上 | 1.80 | +80% | 4H趋势继续推进，日线关键支撑保持 |
| 1W | 周线也支持上涨 | 2.50 | +150% | 日线前序目标通过，周线结构与承接继续有效 |

系统必须另存并展示表内条件对应的具体价格、收盘周期/次数、成交规则与时间，不在真实产品中止于“确认有效”“保持承接”这类泛化话术。例中20%、40%、80%、150%均从同一个1.00计算，不能相加；1H目标也不表示1小时内必达，1W目标不表示1周内必达。表中的方向来自该周期完整的结构、趋势、量价与合约证据组合，不要求它们都是“金叉信号”。

主行摘要可显示“短中长均向上｜短线看1.20（+20%）｜4H看1.40（+40%）｜日线看1.80（+80%）｜周线看2.50（+150%）”；点击展开完整1H/2H/4H/1D/1W矩阵。窄屏主行保留参与结论、最近关口和日周空间，完整矩阵进详情，不以多行卡片挤占总览。

已有仓位到达1.20时，系统同时评估“短线目标已到”和“大周期是否仍支持继续持有”，按原计划给出预设部分兑现、余仓保护、持有或退出的明确指令。兑现比例、余仓保护方式与可更新边界在参与前登记；未配置时不能临时编出比例或自动延长原交易。长期campaign可继续，即使当前短线Plan已经退出；新的买入需要新Plan。

#### 4.9.4 数据、回放与验收要求

- 增加2H标准周期。可用原生2H，但先核对边界；需要聚合时从完整的连续1H/更细K线构造，UTC 00:00、02:00等偶数小时为锚点。缺其中一段则不生成已闭合2H，不能把正在形成的柱当确认数据。周K延续UTC周一边界。
- 每周期独立满足指标预热、结构历史与来源完整性；指标有效最小历史由实现版本与误差验收确定，不能只取MACD慢线26根就声称预热已稳定。允许的历史回补上限按数据能力登记，不为周线填造历史。
- 所有目标绑定执行Instrument及价格口径；可参考其他市场时须经过已验收转换并披露，否则不跨场套用。保留target_id、timeframe、target_band、method、as_of、known_at、dependency、revision、data_quality；没有目标时区分历史不足与价格发现。
- 回放用当时已闭合的高周期柱和当时已确认的枢轴。周中信号不能引用本周最终周收盘；后续K线确认的枢轴不能回填当时目标。评估每周期同向/分歧是否增加实际净收益，而非只比较成功案例。
- K线周期与预测H窗口分别配置。初始24H/72H计划评估继续使用；如研究日周更长持有窗口，须预先新增独立H及到期/保护定义。周线统计不能仅凭90天覆盖或未成熟样本满足门槛，不给未验证的目标命中率。
- 原始T1仍用于原Plan的冻结结果评价。更大周期目标有各自独立outcome和时域；更新目标不能把已经失败的原计划改写成成功，不以切大周期等待翻本。

### 4.10 全部技术分析能力采用同一决策框架

金叉与五个周期仅是讨论例子。本产品需要“指标/形态 × 适用周期 × 当前市场环境”的通用分析能力，并把结果落实到参与与持有决定。PD1已明确选定基础指标、四个P0策略及研究候选；本次扩展分析框架，不将原来仅研究的指标无验证地全部升级为自动买入条件。

#### 4.10.1 指标与形态各有职责，逐项必须解释交易意义

| 分析组 | 纳入清单 | 主要回答什么 | 决策使用方式与当前范围 |
|---|---|---|---|
| 价格结构 | 区间高点突破、已确认箱体、拐点/前高低、突破回踩、趋势再启动、结构失守 | 价格是否真正越过关键位置，哪里买、哪里失效？ | P0核心触发和目标/保护依据；普通区间与合格箱体分别命名 |
| 趋势 | EMA20/50、均线排列/斜率、金叉死叉；其他参数按画像注册 | 上升、下降或震荡，趋势处在早期/延续/转弱哪一段？ | 基础趋势背景；更换均线参数是新版本，不将所有均线交叉当独立入场策略 |
| 动能 | MACD、RSI及经验证的背离/恢复规则 | 上涨是否加速、减速或出现分歧？ | 首批研究与解释增强；RSI高不自动卖、低不自动买，背离须有已确认锚点 |
| 趋势强度 | ADX及适用的DI/结构对照 | 是否有足够趋势强度，还是易反复的震荡？ | 研究过滤条件；ADX自身不提供上涨或下跌方向 |
| 波动与收缩 | ATR14、布林带宽度/扩张/收缩 | 整理是否收敛、波动是否放大、保护距离是否合理？ | ATR为P0风险尺度；布林带为研究条件，收缩不自动决定向上突破 |
| 成交与承接 | 相对报价成交额、成交主动性/CVD、现货与永续成交对照 | 价格推进有没有交易活动支持，是否出现冲突？ | 成交倍数为P0确认；主动性按来源能力验收，不能把主动成交差额叫净流入 |
| 位置与价格区域 | 已确认支撑/阻力、锚定VWAP、Fibonacci、VPVR/成交分布 | 上方阻力、下方支撑、当前是否追高？ | 历史结构为P0；其他为研究叠加，需明确锚点/覆盖/算法，不以斐波线或成交密集区证明未来必到或庄家成本 |
| 复杂形态 | 圆弧底、双底、三角形等 | 是否形成可定义、可复算、可交易的结构？ | 保留实验模板；有颈线/边界、确认规则、失败条件及回放后才进入正式行动 |
| 合约交叉证据 | OI数量/市值占比、费用、基差、清算、跨平台分布 | 技术上涨伴随什么持仓/费用变化，有无拥挤或挤压证据？ | 与技术独立记录后联合解释，不单独取代价格结构或把“高OI”认定控盘 |

不是每个指标都应该独立给“预计涨20%”。例如ATR负责风险距离、ADX负责趋势强度、MACD负责动能，目标来自有依据的价格区域或经过验证的预测模型。**系统按每个周期综合这些证据给出方向、动能、目标空间与行动；同时能解释每个指标为什么支持、反对、无关或暂时未知。**

图表上可以添加的指标不自动等于后端已经支持的正式分析能力。基础计算可采用TA-Lib等已选工具并与图表值对照；形态和参与规则仍需版本化实现。VPVR、VWAP及复杂形态的价格/成交口径必须验证，不能仅因图表能画出就宣称策略已接通。

#### 4.10.2 周期范围通过注册和能力校验扩展

周期注册需支持分钟、小时、日历日/周/月等类别；首批五周期预设可调整。候选选项例如5m、15m、30m、1H、2H、4H、6H、12H、1D、3D、1W、1M，逐项标明可用/可聚合/历史不足/不支持；该列表是扩展规划，不声称每个来源当前都有全部原生接口。

原生无某周期时，只有底层连续K线完整且已验证聚合边界才允许生成。日历月不能当固定30天，3D等跨日周期需显式epoch/锚点；不同平台的“同名周期”边界一致后才比较。不允许用1H数据编造15m，也不允许从一个代币不足一年的数据画出长期月线均线。

设置页分别配置分析周期、默认展示周期、策略必需周期、辅助周期、深采优先级与预算。新增周期优先复用已有较细行情聚合，不能按页面/指标重复请求相同K线。选项过多超出预算时先展示影响并按已发布优先级调度，不偷偷扩大请求、不挤掉活动保护。

#### 4.10.3 统一输出与冲突处理

每条指标或形态输出：analysis_id、family、role、params_version、timeframe、instrument、event_state、observed_value、comparison、support/opposition/neutral/unknown、evidence_refs、known_at、适用环境、触发/撤销条件，以及对参与结论的明确影响。role区分入场触发、环境过滤、动能、目标参考、风险保护和解释证据；不适用时说明原因，不为填满矩阵制造结论。

决策顺序为：身份与数据质量 → 每周期结构/趋势/动能/成交分析 → 周期间同向与冲突 → 合约支持或风险 → 目标与可执行计划 → 当前参与/持有行动。实现仍遵守§3的风险优先级，所有聚合都基于同一snapshot和规则版本。

- 同一个周期出现“MACD偏多、RSI高、布林扩张”时，按各自职责解释，不机械按两票对一票决定买入。强趋势中的高RSI可反映强势；只有具体已登记反向规则成立时才影响行动。
- EMA、MACD、RSI和价格涨幅高度相关，不能把它们叫四份独立上涨确认。不同周期同样存在嵌套相关性，统计评估需要消除样本泄漏与重复计数。
- 结构失效或执行条件不合格属于硬门槛，不能被十个辅助偏多指标抵消；相反，单个辅助指标未知也不能统一阻断合格主策略。
- 有多策略机会时允许保存多个Episode/Plan，主行按已登记行动优先级展示一份主计划，清楚显示备选；不得混用不同计划的买入价、最低保护与最高目标拼出虚高收益比。
- 案例和AI只用于解释/提出待验证假设。新增指标或组合须比较“基线策略”与“加入该指标后”的实际增量，无增量或重复的项目从默认解释中移除。

#### 4.10.4 页面表达与实施责任

总览仍一币一行，先显示行动、买入/保护、最近关口、日线主目标、本轮最高条件目标美元价及倍数、当前最关键的2–3条理由。详情采用“周期 × 分析组”矩阵，点击能看到具体指标及原始证据；默认不把几十个数值同时堆给用户。首屏必须给最高条件目标的美元价；数据不足则显示精确缺项，不能把可计算的目标藏在展开区域。每个周期最终有一条通俗总结，例如“短线买盘增强，4H突破成立，日线仍有空间；周线数据不足”，避免只列指标名。

后端建立Indicator/Pattern注册表和DecisionProfile：P0基础项先完成，研究项允许单独计算/展示，经过旁路对照和回放后按版本升级为正式条件。没有通过的项标明状态；不将本节全部研究项作为首版基础参与功能的前置依赖。

W04负责数据/特征与采样口径，W05负责结构与已验收策略，W06负责通用分析注册/证据融合/解释，W08负责多周期矩阵及图层，W09负责周期与画像配置，W11负责增量验证，W13承接复杂形态及可选扩展。新增analysis_registry与indicator_assessments契约须由W12统一生成，前端不得自行另算行动。

### 4.11 ATH、倍数空间与主攻目标

#### 4.11.1 三类目标必须给出明确定位

| 类型 | 系统如何表达 | 选择依据 |
|---|---|---|
| 本轮主攻目标 | 当前主攻T_low–T_high，约+X%～+Y%，价格M～N倍 | 适用的日/周结构、已确认阻力簇或预先登记的测算方法，加上当前趋势/成交条件 |
| 条件延伸目标 | 突破关口并满足指定规则后，上看更远区域 | 明确尚未满足的依赖、确认周期、量价门槛、保护及失效，不提前算已经成立 |
| ATH/历史参考 | 距经核验ATH还需上涨X%，对应M倍价格 | 历史记录本身只说明距离；须有当前结构路径才能升级为主目标 |

选择主目标时明确主交易周期与计划评估窗口：可以主攻日线并同时管理短线T1，不能只因远目标更大就选它。必须有方法、数据锚点、已知时点、前序阻力和反证；缺少长周期历史时明确“不具备周线倍数判断条件”，保留可用短周期观点。新币进入价格发现时可用原模板批准的箱高测算并标“测算”，不创造一个未知ATH。

#### 4.11.2 ATH与市值的可复算口径

以当前同身份、同单位参考价格P>0及经核验历史最高价A计算：ATH价格倍数=A/P；回到ATH需要涨幅=(A/P−1)×100%；相对ATH回撤=(P/A−1)×100%。例如P=1、A=4，分别为4倍、+300%、−75%；不能把“距离前高75%”误写成“涨75%回前高”。

ATH必须记录来源、市场/报价币、历史覆盖起止、首次上市/迁移/拆分调整、最高价时间、单笔/影线或收盘口径，以及异常尖峰核验。只拿到当前交易所上市以来K线或有限回补窗口时写“该市场/样本最高价”，不能写成全历史ATH；币安合约上市晚于代币现货时尤其需要分开。

原生K线历史和CMC经Key验证可取得的历史字段可作为候选；CMC免费市值接口可用不代表免费ATH字段已验证。跨源最高价不盲目取最大值，先校验资产身份、乘数、报价转换与异常交易。ATH缺失显示“ATH待核”，仍允许结构明确的交易观点。新高超过旧ATH时更新历史版本，防止显示过期负距离。

同步输出当前流通市值、目标价按当前流通量计算的静态市值及适用时间；有可靠解锁/供应计划时另算目标时点情景市值。回到同一历史价格可能需要更大当前市值，不能把旧市值或FDV直接当流通市值，也不能把市值增量称为需要流入的资金量。解锁未知则标缺失，不能假设未来流通量不变。

#### 4.11.3 倍数机会的判定与文案

先给目标价格，再算倍率。倍数空间成立的规则条件至少包括：目标对应有效且可追溯的结构/方法；当前主方向与必要成交条件成立；与执行Plan身份和价格单位一致；沿途关口、支撑/保护、成本和必要数据合格。价格接近2倍只是分类门槛，不是成功概率或自动买入阈值。

- 主目标区下沿≥2P且上述条件满足：可标“本轮具备倍数级结构空间”，直接给当前是否建议布局以及2–3倍等实际算出的区间。
- 只有尚未激活的周线延伸达到2P：标“周线有倍数延伸条件”，当前主目标仍单独显示，并给激活门槛。
- 只有ATH很远：明确“历史修复空间大，当前尚无对应倍数交易依据”，不放入已成立倍数机会列表。
- 目标区跨过2P：显示完整区间，如1.8–2.3倍，不能整段宣传为至少翻倍。回到旧ATH已无距离时，转入有依据的价格发现/延伸判断。
- 需要展示10倍或更高目标时沿用同样来源、供应、流动性和验证规则；不因目标大而回避展示，也不因想找妖币就外推没有依据的数字。

倍数机会筛选与“建议现在布局”分开：前者选有证据的长空间，后者还要求当前执行合格。主列表可组合两项筛出“现在可参与的倍数候选”；已经超价的长空间币显示等待位置。目标价格倍数、模型预测的未来收益和已校准达标概率使用不同字段与名称。

### 4.12 周线临近金叉的可检验条件

周线状态分为已收盘确认、盘中已交叉、接近交叉、当前不支持交叉判断、数据不足。必须注明MACD或均线类型、参数、时区、最后完整周与当前未闭合周，不能把“周线马上金叉”写成已经知道未来。

MACD(12,26,9)可以计算“假设本周收盘在什么价位，才会完成交叉”。令E12、E26、S分别为上一根完整周的EMA12、EMA26和DEA，a=2/13、b=2/27、c=2/10；假设本周最终收盘为P，则D(P)=(a−b)P+(1−a)E12−(1−b)E26，S_new(P)=cD(P)+(1−c)S。交叉边界为P_cross=[S−(1−a)E12+(1−b)E26]/(a−b)，还须上一完整周DIF≤DEA，且本周最终DIF>DEA才是新金叉。

边界价格、实际可用tick及最小确认差值分别存储；恰好相等不算已金叉。每次盘中测算都从上一完整周状态计算，不能把正在变化的一周反复更新成多根K线。该公式只适用于这里声明的EMA递推MACD实现，其他实现/指标参数应使用对应函数重算，不共用阈值。

页面可显示“周线尚未确认；以当前已知数据计算，本周收盘需高于X才完成MACD交叉；距现价约Y%”。下一周加入新柱后需要重新计算。“接近”的距离/归一化差值阈值由参数登记，属于规则初值；不能仅凭靠近就预测交叉发生的日期或给胜率。

进攻型可在日线与实际入场模板已经成立时提前布局，周线条件用于目标升级；等待周线不是所有计划的统一前置条件。周线趋势延伸仍需结构/量价组合，MACD单项交叉不自动激活全部远端目标。7D/30D/90D等可登记为独立研究评估窗口，但不代表保证在这些天数内达到目标。

### 4.13 1H / 4H / 1D / 1W 联合评估：形成一个当前主结论

默认主评估周期为1H、4H、1D、1W；2H及其他注册周期作为可选辅助。每个周期分析结构、趋势、动能、成交和位置，最后由同一个后端决策服务合成主观点、主目标、条件延伸和当前行动。不能只列“1H金叉、4H金叉”等指标清单，也不能简单按四个周期投票算上涨概率。

| 周期 | 在联合判断中的职责 | 必须评估的K线/指标证据 | 对最终建议的直接作用 |
|---|---|---|---|
| 1H | 当前入场时机与短线状态 | 触发/回踩结构、EMA方向、MACD/RSI变化、相对成交、距离参与带与ATR | 现在是否可进入、等回踩还是等新触发；给具体短线失效价 |
| 4H | 本轮交易结构是否成立 | 箱体/前高突破与收盘、回踩承接、趋势斜率、动能与成交、结构保护 | 区分早期和确认布局，确定最近目标与执行Plan |
| 1D | 波段主方向与主攻目标 | 趋势恢复/反弹环境、已确认金叉、日线结构/阻力、成交持续、动能及过热距离 | 判断值得做日线波段还是只做短反弹，选择主攻区间 |
| 1W | 大趋势状态与更大空间 | 完整周结构、周线趋势/动能、交叉确认或条件门槛、长周期阻力与历史覆盖 | 判断是否具备更大延伸/倍数结构空间；明确尚未确认的条件 |

上述指标按已注册实现与验证状态运行；EMA/MACD/RSI来自相关价格数据，不能重复视为独立上涨证据。ATR主要管波动和保护距离；它不产生上涨方向。只有收盘后的事实用于正式确认，周线盘中状态单列；成交比较使用同周期完整柱，并排除当前柱的基线。没有周线历史的币按可用周期输出，不能假称四周期共振。

| 多周期结果 | 系统必须给出的主判断 | 当前行动与目标安排 |
|---|---|---|
| 1H/4H触发，日线向上，周线也已确认向上 | 多周期上涨展开，当前具备持续做多依据 | 位置/执行合格则建议布局；给日线主目标、周线延伸，ATH另列 |
| 1H/4H触发，日线确认转强，周线未确认但条件正在接近 | 日线先启动，周线展开仍待验证，适合进攻型提前参与 | 用已触发Plan布局，周线目标标条件延伸，列周收盘门槛 |
| 1H/4H偏多，日/周仍在下行结构 | 本轮更偏短线反弹，当前不主攻倍数空间 | 仅在短线模板合格时给短线参与建议；目标落在近端关口，不包装成主升趋势 |
| 日/周向上，1H/4H正在回落 | 大方向偏多，当前入场节奏未转好 | 等具体回踩/再启动价位，不含糊写继续关注；已有Plan独立按保护管理 |
| 多周期方向向上，但价格已经超区或执行不合格 | 看多延续，当前价格不适合新增参与 | 给下一可参与区/触发，继续显示主目标，不把方向与入场混为一谈 |
| 周期数据缺失或存在未解释冲突 | 按已覆盖周期形成可核验观点，注明哪一级空间无法判断 | 必需周期/执行缺失暂停对应路径，辅助缺失不全部阻断 |

每周期输出事实、方向、阶段、动能、目标、失效条件、质量、原始证据和对主观点的贡献；合成时按预先登记的模板职责处理冲突。周线偏空可以限制长目标，并不必然否决所有1H短线策略；短线保护触发也不会被周线看多抵消。最终不能同时给同一主计划互相冲突的行动。

用户问“有多大概率上涨”时，必须先定义结果：例如在预先选择的H窗口内、扣除已登记成本后，先到该计划目标而非先到保护价的概率。K线周期不等于H；四周期同向也不等于80%或100%。规则阶段直接给上述明确主判断与行动，统计未成熟显示“达标概率尚未验证”；取得独立历史样本与校准后再显示具体概率、样本数、区间及适用目标。历史达标率与当前预测概率分别命名，不能靠调高词语强度填补概率。

该流程适用于全部已支持指标/形态与OI/清算交叉证据。按周期登记必需/辅助证据及已验收阈值，禁止只为日线金叉做一个特例；四周期结论、目标与动作一起进入SignalSnapshot，前端和TG直接读取。

### 4.14 必须给出本轮最高条件目标价

用户需要知道“现在1美元布局，如果日线和周线都成立，最高看多少美元”。因此新增首屏必需展示项：本轮最高条件目标价，定义为在当前已知数据与已登记情景中、有完整目标依据和可列明触发路径的最高目标价；不是所有未来行情的绝对天花板。目标生成、候选排序与依据展示遵循§4.15，不能在缺少计算链时直接填写最大价格。

输出顺序固定为：当前价 → 当前布局建议 → 日线目标 → 日周条件同时成立后的本轮最高目标 → 对应涨幅/价格倍数 → 激活条件 → 保护/推翻价格。不能只给1H/4H最近阻力或“周线有空间”，也不能只有目标百分比而没有美元价。

主展示必须选一个明确最高目标，例如“最高条件目标 $3.00（+200%，价格3倍）”。若来源提供的是目标区，展示区间及代表目标；只有目标区上沿在同一方法与情景中有依据时，才可用该上沿作为最高目标，不得给中枢再随意加一个百分比。当前已激活主攻目标与尚未激活的最高条件目标用不同状态表示。

最高目标的选择在有限、可审计的情景集合中进行：列出每个日线/周线结构目标或已登记测算、全部先行关口、各自确认要求、数据/方法来源、时域及失效规则。只有依赖完整且当前没有被明确反证排除的情景才能进入候选，再从候选目标选择最高条件价；不能从不同币、不同Plan或互相冲突的情景拼出最高数字。ATH只有满足同样的当前结构路径要求才可入选；单纯“以前涨到过”不能自动成为本轮最高目标。

现价为P、最高条件目标为T时，同时显示T美元、(T/P−1)×100%和T/P倍。示例现价$1、日线$1.80、最高条件目标$3.00对应+200%/3倍；ATH=$4.00仍可作为另列历史参考。如果当前目标已有可靠结构依据，但尚待日周确认，应明确写“条件未激活”，不能仅因未确认就省略这个价位。

只有现价$1而没有该币历史K线与结构，无法计算出真实$3或$4目标：显示“最高目标待评估—缺周线历史/目标锚点/身份映射”等具体原因，不编数字。日线有数据而周线不足时，仍给日线目标并标明最高目标只覆盖已知周期，不把它称为完整日周判断。

随着新周线/新结构成立，可以向上修订最高条件目标并保存target_revision；最高目标触及后继续评估价格发现或新的有效结构，不把旧目标当永久顶点。目标下调/撤销有事件、理由和时间，不能改写原目标与历史结果。阶段性兑现和原Plan的保护继续依冻结规则执行，不能为了等待最高目标放弃止损。

### 4.15 反弹位置与目标测算标准 v0.1

本节补齐目标价格的生成方法，适用于做多研究；状态为待实现、待验证的规则基线。规则能复算不等于已经证明有预测优势。§4.8的$1.80–2.00/$3.00仍是文案样例，不属于本方法的计算结果，严禁作为默认目标或固定倍率。

#### 4.15.1 同时回答在哪里反弹、反弹到哪里

每个计划输出五项：候选反弹区、实际参与触发、第一目标、条件延伸目标、失效价。候选反弹区表示历史结构支持的位置；到价本身不证明已经止跌。反弹目标表示准备测试的上方区域；不称确定顶部。最高条件目标沿用§4.14，但必须由本节允许的方法和完整路径生成。

| 周期 | 主要职责 | 不能替代什么 |
|---|---|---|
| 1W | 长周期结构、远端历史关口、日线延伸所需条件 | 未闭合周K不能证明周线反转 |
| 1D | 区分下跌反弹、趋势修复、上涨延续，给主要目标 | 日线金叉不能直接换算成涨幅 |
| 4H | 冻结正在交易的箱体或波段、参与区域、近期压力 | 不能把4H最近压力当整轮行情最高点 |
| 1H | 早期突破、回踩收复、具体入场与退出监控 | 短线触发不能冒称日周均已确认 |

已确认摆动高点、低点分别逐次抬高，记该周期结构上行；两者都下降记结构下行；混合记整理/分歧，点数不足记未知。至少比较最近两个同类高点和两个同类低点，方向差异须超过一个最小报价单位。实际跌破已登记结构时优先显示破坏状态，不因旧高低点仍向上而继续写结构有效。日线仍下行时，小周期合格计划只能先称下跌中的反弹；日线结构修复并满足对应规则后才能升级，周线单独评估。

#### 4.15.2 用真实结构产生价位，锚点选择必须固定

1. 输入采用同一执行市场、同价格单位的闭合OHLCV；规范化、缺口、异常尖峰、ATR14初始化与预热沿用PD1。日周边界见§9。历史扫描上限的研究初值为1H/4H/1D各200根、1W 156根；不足上限如实标覆盖，只要满足所选方法的必要锚点和预热仍可计算。缺周线不编周线目标。
2. 摆动高低点采用左右各2根的初始规则：中心高点为5根中的最大值，低点为最小值；并列极值取该窗口最后出现者。右侧2根全部闭合后才确认，known_at记录右侧第2根收盘时刻。图上可画在中心K，但回测与建议只能在known_at后使用，盘中候选不得提前进入正式目标。
3. 候选支撑来自已确认低点、已确认突破后的原箱顶；候选阻力来自已确认高点、已失守后的原箱底。箱体资格、窗口、突破/回踩门槛继承已登记模板，不把任意一段最高价/最低价直接称箱体。角色转换要有对应确认事件；被突破/失守且尚未完成新角色确认的旧区域不当有效支撑或阻力复用。
4. 单个结构锚点p生成价带[p−w,p+w]，w=max(2×tick_size,0.25×ATR14)。使用锚点所属周期、价位快照创建时最新已闭合的ATR，并冻结数值。0.25是待验证的容差初值，不是置信区间；箱体自身已有边界的，保留原边界与缓冲，不再额外重复扩带。过宽、历史孤立异常或小于等于0的价带按质量规则拒绝并给原因。
5. 不从所有价位中挑最有利的一个。对计划声明的周期集合，先列全有效候选；包含现价的区域标当前测试区，其下最近区域为下一候选反弹区，其上最近区域为近期压力。重叠区可以在UI合并说明，计算仍保留原锚点；T1使用最近阻力的下沿，不向更高的重叠区边缘挪动。排序以价格距离为先，同价并列保留全部来源。
6. 每个锚点和价带保存market、timeframe、source_bar_ids、pivot_time、known_at、ATR/tick、规则参数、选用/排除原因及当前有效状态。关键结构反证在每根所属周期收盘时更新；硬保护按执行规则及时监控。新确认点可创建revision，原Plan与当时可知数据不回写。

#### 4.15.3 目标采用明确优先级，不任意叠加指标

| 方法 | 计算与选用标准 | 产品状态 |
|---|---|---|
| 已观察到的结构阻力 | 对参与带上沿E，先检查是否处在/穿过阻力区；若是则等待突破或拒绝该Plan，不能跳过。其上按价格排序，最近有效区域下沿作T1，沿途其他区域保留 | 默认主方法；图上实线/区带，给原始K线 |
| 已确认箱体等幅测算 | 冻结箱底B、箱顶U，向上测算T=U+(U−B)。仅适用已登记有效箱体；突破前只能作为待激活情景 | 标测算、画虚线；有更近阻力时先用近阻力作T1，不覆盖它 |
| 已声明周线结构延伸 | 使用周线有效阻力或已登记周线箱体测算，列出全部中间关口、各自确认条件和失效规则 | 输出日线主目标与周线条件目标；最高价仅从同一有效路径的已登记目标选取 |
| 下跌段回撤比例 | 选最近一个已确认低点L及它之前最近已确认高点H，H>L；F(r)=L+r×(H−L)，r=0.382/0.5/0.618 | 只作辅助反弹关口；0.5为惯用中位回撤，非斐波那契数列比率；不能单独生成最高目标、参与建议或概率 |
| ATH、成交密集区、清算区 | ATH按§4.11核验；成交分布需覆盖/分箱/算法完整；清算区按实际仓位或供应商模型标来源 | 参考或补充证据；缺数据不造价，不能代替主方法或当吸引价格必到的磁铁 |

回撤比例中的H/L必须保存选点顺序与known_at；新低跌破L即撤销旧回撤测算，等待新低完成确认后生成新版本，不回溯选择“最好看的”波段。价格越过H后原下跌段修复结束，不继续用同一组回撤比例外推倍数。结构区与比例水平重合可称两种方法落在同一区域，但两者都来自价格，不能当独立证据叠加胜率。

目标价计算与当前价关系分开：先根据锚点计算T，再展示(T/P−1)×100%与T/P，不能先决定要展示涨200%再反推目标。原始T1用于净R/历史outcome，当前已越过的阻力按确认规则处理；远端目标不抬高原净R。没有结构锚点或已允许测算法时给具体缺项，不能填固定1.5倍/3倍。

#### 4.15.4 到价之后，按模板判定能否参与

候选区用于安排观察和提醒；入场继续复用early_breakout、confirmed_breakout、retest_entry、trend_restart四个P0模板，成交门槛/缓冲/有效期继承其版本。下跌中仅触碰前低、RSI超卖、单次金叉、单次负费率，都不能冒充已成立的模板。纯支撑触碰抄底策略不在本次悄悄新增；支撑附近若形成真实局部箱体并触发已有模板，可以给明确提前布局建议。

参与带、硬保护与收盘撤销线由触发模板生成，保护必须对应具体结构，例如箱底、回踩低点及登记ATR缓冲。不能统一给现价下方10%，也不能只为凑净R压窄保护。成本和当前价格检查沿用§3.2；即便目标明确，当前超出有效参与带仍应直接显示等待某价或暂不追入。

OI、费率、真实清算和主动成交用于解释承接与合约风险：上涨伴数量OI下降并出现空头清算，可支持回补正在发生；不能据此证明买盘会持续。上涨增仓结合成交可支持趋势扩张，不能识别所有新仓方向。没有OI的技术路径仍可按自身条件判断；合约辅助证据不能把目标从$1.4乘成$3，亦不能绕过已触发的保护。

#### 4.15.5 可复算示例：现价$1，反弹先看哪里

以下全是假设输入，用来验算方法，不是任何代币的行情，也未证明这些位置会反弹。设真实输入中已经识别到：日线下跌段H=$2.00、L=$0.80；4H有效结构锚点支撑p=$0.96、阻力p=$1.26，创建快照时4H ATR14=$0.08、tick=$0.001；日线上方另有有效阻力区$1.48–1.52。假设上述锚点均已确认、仍有效且期间不存在更近阻力。

| 输出 | 计算 | 交易含义 |
|---|---|---|
| 候选反弹区$0.94–0.98 | w=max(0.002,0.25×0.08)=0.02；0.96±0.02 | 价格回到这里时检查能否形成入场触发；不是提前保证止跌 |
| 第一目标$1.24–1.28 | 1.26±0.02；距现价$1约+24%～+28% | 4H真实结构压力；T1取下沿1.24 |
| 回撤参考$1.2584 | 0.80+0.382×(2.00−0.80) | 落在第一压力区，作为辅助说明，不把它称精确顶部 |
| 第二目标$1.48–1.52 | 来自已存在日线阻力，不由当前价乘固定倍数 | 第一压力有效突破后再评估，距$1约+48%～+52% |
| 其余回撤参考$1.40/$1.5416 | 分别为0.5/0.618回撤 | 途中参考；不自动取代结构目标，也不因尚未到就一直持有 |
| $2.00原波段高点 | 历史H参考，回到该价需要上涨100% | 未提供后续路径时不认定为本轮必达或最高目标 |

该示例没有提供已触发入场模板、执行成本或完整周线结构，因此能给出反弹位置与逐级目标，但不能补造“现在建议买入”、保护价或$3周线目标。正式主行在输入齐全后表达为：“建议[行动]｜反弹区A–B｜先看T1｜突破后看T2｜周线条件目标Tw/具体缺项｜失效S”，所有数字均来自同一快照。

#### 4.15.6 时间与检验：哪些位置真的有效

K线周期不等于目标达到时间。每个已发布目标都保存观察窗口、触发时刻、激活条件和到期处理。现有参与评估沿用24H/72H；额外研究日线14天、周线56天两种固定窗口，属于待验证初值，只在各自目标激活后起算。冻结条件目标的最长等待期，未激活单列并报告激活率；不能把没激活的目标无限延期。新窗口不能自动代替原24H/72H结果或伪装成预计必达日期。

除§5交易计划统计外，新增位置方法评估：

- 反弹区发布后，价格首次从上方向下触及或跳过该区作为事件，事件必须晚于区域known_at，同区域同episode不重复计数。令A为触碰前最后闭合4H的ATR14，冻结诊断失效价S_test=区域下沿−0.25×A、反弹阈值B_test=区域上沿+A，研究窗固定12根4H；S_test只用于位置检验，不替换任何Plan的交易保护。跳空越过S_test计失效，不能因没有在价带成交而剔除失败；S_test≤0或数据不足单列不可评估。统计先达到B_test、先失效、到期未反弹、顺序未知及缺数据。触碰柱内先触及哪个价位须用更细数据判断，无法确定则列顺序未知，不能把触碰前的最高价当反弹成功。该诊断只检验是否有可测反弹，不等于交易盈利或触发参与建议。
- 目标分层报告T1/T2/周线目标的先达率、达到耗时、MFE/MAE与成本后计划收益。条件目标既报告激活率，又报告激活后的达标率；评估最高目标时按事先冻结的完整路径，不从事后出现的目标里选赢家。
- 采用时间外留出、失败/横盘/退市资产与不同市场状态；包含当时可知的资产目录和数据覆盖，摆动点必须延迟确认。比较最近结构阻力基线、加入箱高测算、加入回撤参考、加入OI辅助的增量，不凭指标多或个别成功例子宣称更准。
- 参数在训练/验证阶段登记，评估集不反复择优。0.25 ATR容差、左右2根、200/156根历史、12根4H与14/56天窗口均为研究初值；未完成验证时明确方法状态，不发布伪胜率。

## 5. 可信度、历史达标率与概率验证

### 5.1 三层结果分别发布

| 层次 | 何时可显示 | 用户看到什么 |
|---|---|---|
| 规则证据等级 | 必需数据和已发布规则可复算 | “依据较充分 / 有分歧 / 不足”，列支持与反对；无概率数字 |

9个妖币案例是机制研究材料，不是成功率分母。指标数量、OI大小、负费率幅度、阶段确认级别均不得直接转成概率。历史达标率也不能自动命名为“本币现在上涨概率”。

### 5.2 先定义预测问题

首个研究目标：**计划按规定成交规则入场后，在固定H窗口内，先达到原始第一目标区下沿T1，而未先触发冻结保护价S的频率。** H作为模板配置，初始研究可使用24H和72H两个独立报告窗口；不能事后只展示表现较好的窗口。

- 入场：信号实际可知时间之后的可成交报价，包含模拟延迟、双向成本和可成交量；不得用触发K线开盘价回填成交。
- 成功：规定窗口内先达原T1且保护未先触发。止损、到期未达分别统计；T1是在发布计划时冻结的，不随之后目标更新改分母。
- 同一根K线同时越过目标和保护而缺少更细数据时记“顺序不明”，单列并给保守/乐观边界，不擅自按成功处理。
- 尚未走完H、数据缺失、未成交均单列。未成熟样本不进入成熟结果分母；未成交不混成交易亏损，但必须报告建议到成交的覆盖率。
- 同一campaign反复触发、同币多所重叠事件高度相关，按campaign/时间块分组做验证和不确定性估计，不能把每分钟快照当独立交易。
- 先达T1率、T1是否覆盖成本、全计划净收益是不同统计。另报MFE/MAE、最大回撤、净收益分布和可成交容量。

### 5.3 发布门槛与统计界面

PD2新增研究发布初值：独立评估集中同一口径至少200个成熟且可成交计划、至少30个资产、覆盖至少90天。三者都是数据治理起点，不保证统计有效；市场状态、样本依赖、子组数量和区间宽度仍须检查。窄范围策略无法满足时保持“该范围统计不足”，不得拼接不兼容策略或平台凑数。

同类子组不足时可以显示更宽策略组的历史统计，但必须明确范围放宽，不冒充本币专属统计。结果至少给95%不确定区间；优先用campaign/时间块bootstrap处理依赖，简单二项区间仅在独立性近似合理且明确标注时使用。不给小样本P97.5或精确到小数点后两位的成功率造成虚假精度。

概率模型另设发布报告：训练/验证按时间与资产隔离、无campaign泄漏、可靠性曲线、Brier score及相对基准表现、分市场状态表现、漂移监测。样本量过线不能自动发布模型概率。评估失败或漂移超限时降级到规则证据等级/历史统计，不抹去已发布记录。

首版规则建议可以先上线并前向记录，概率发布后置。设置页和API必须区分validation_status=unvalidated/historical_only/calibrated，不因未产生可信概率永久关闭所有研究参与建议。

沿用90日初始基线；1H/4H使用非重叠锚点且至少300个有效同口径样本后给分位。1D=滚动24H仅作背景，至少60个日样本并显示分辨率，不将分钟滚动值当独立日样本。重大覆盖变化重建可比基线，源的历史能力不足时持续积累，技术计划照其独立条件评估。

线性合约同集合的名义变化继续分解为数量贡献 Σ[(Q1−Q0)×P0] 与估值贡献 Σ[Q1×(P1−P0)]；它们不是流入资金。反向产品按合约规格单列；不能由价格变动产生的base换算变化推断开仓。自由流通仅保留有来源的情景，数量/供给与OI/市值不重复计为独立支持。

账户多空比、大户仓位比仅在详情展示具体样本定义，不承担全场多空持仓判断。链上地址集中度、实体归因、全站未来清算区保留P1门槛；已选来源全部可见仓位样本的接入与边界见§6.8–6.10：已知地址不等于全地址，Aster私密仓位不假设可枚举；追加保证金、费用与全仓盈亏使清算价动态变化。不得将永续清算区命名为期权Max Pain或最终顶部。

### 6.8 清算点位、实际爆空与上涨空间

本次新增要求：OI分析必须接到清算与价格判断，回答“哪里可能触发空头清算、是否已经清算、清算后买盘是否继续、到下一关还需涨多少”。先分别展示清算事实、可核验仓位的动态清算区、假设模型与未知范围；不从全场OI反推出全场空头开仓价/杠杆或一个精确爆仓价。

#### 6.8.1 三种价格与四种证据状态

| 对象 | 可以提供的结果 | 必需数据与限制 |
|---|---|---|
| 已发生清算 | 方向、发生窗口、已报告成交价/数量/名义金额及采样范围 | 以真实清算事件为据，清算成交价不等于触发标记价；订单量不等于成交量 |
| 仓位当前清算价 | 已知地址/账户在该快照条件下的liquidation price | 原生风险字段优先；需明确仓位/保证金模式、更新时刻和可见集合，会随补保证金、费用和其他仓位变化 |
| 未来清算区模型 | 在指定仓位、价格路径、保证金/杠杆假设下的潜在价格带 | 假设及误差需公开；由OI变化和假设杠杆构造的热图只能标模型，不能声称知道真实空头分布 |

证据状态分别为reported（源报告的仓位风险价或清算事件）、recomputed（完整规则和输入下重算）、modeled（缺真实仓位而采用假设）、unavailable（无法估计）。reported也不表示未来不会变化；0/null需按接口语义处理，不当成“不会爆仓”。

公开行情包含总OI、价格和费率时，通常缺少逐仓开仓价、实际保证金、仓位数量/方向、风险档位、保证金模式、跨仓资产和其他盈亏，不能唯一解出清算价格。负费率与多空账户比也不能补齐这些未知量。仓位多空两侧不因同一份OI而重复计数。

#### 6.8.2 首批来源与计算路径

已核对本地下载资料：Aster文档的GET /fapi/v3/positionRisk标为USER_DATA，返回liquidationPrice等账户字段，不能当作可遍历全站仓位的公共接口。其forceOrder流按每个symbol在1000ms内仅推最新清算订单快照，不能声称是全部逐笔清算；应验证订单/成交方向和状态，按可用标识及累计成交增量去重，不直接把原订单数量累加。

Hyperliquid路径优先对可核验的已知公开地址及namespace验证原生仓位风险字段；地址集合必须记录来源、更新与去重，不声称涵盖全场。Surf按用户要求排除，不进入实现。部分仓位清算价可能为空，应展示缺失原因和可用账户风险状态，不能把null填零。ByKaranteli大户样本已实测，具体范围与字段限制见§6.9。

CMC已讨论的清算窗口汇总用于已发生金额核对，不提供所需的全场未来仓位分布。跨源同市场去重，不能把CMC覆盖的清算再与原生金额相加。不同平台的清算区独立显示，可做明确换算后的比较，但不能把某所清算价直接当另一所的可成交目标。

**简化计算仅作公式校验。** 单一线性逐仓空头、数量Q>0、开仓价E、有效保证金M、已知费用净扣项C，假设固定维持保证金率m且无档位扣减/特殊缓冲时，权益为M+Q(E−P)−C。令其等于mQP，可得P_liq=(M+QE−C)/(Q(1+m))。真实平台需应用实际档位、费用、标记价和部分清算规则；反向、全仓、多资产组合不能套此式。优先使用经核验的原生风险计算结果，自算值不一致时显示差异并退出正式清算区，而非任取一方。

不能仅用“开仓价加1/杠杆”当正式爆仓价；初始杠杆也不代表后续实际风险。全仓计算还要指定其他资产价格路径，缺必要数据时仅给风险未知或条件情景。

#### 6.8.3 清算区与涨幅的输出口径

每个价格带保存venue/instrument、position_side、mark基准、价带、参考价格、可见地址/仓位集合、潜在名义规模及估值基准、计算/报告来源、as_of、过期规则、假设与排除原因。按适用范围输出最近区域、指定价格范围内规模最大区域及到某价的累计潜在规模；不命名为“必到价”“最高痛点”或最终顶部。

- 距触发空间：以同平台当前mark M计算(L/M−1)×100%，L为上方清算区边界。这是到潜在触发区域的标记价格距离。技术目标的可成交价距离仍按§4.9计算；mark与last不同时两者分列，不偷换分母。
- 潜在规模：把可见仓位按各自风险价分箱。区分当前价格估值与触发价格估值，累计区间使用同口径；记录去重后的仓位数。原生同口径OI可作为覆盖参照时，说明已知空头样本占所选OI的比例及单位，不把该比例叫全场空头捕获率。
- 已报告清算：按合格事件的实际成交语义计算，显示5m/1H等已登记窗口、样本和缺口；无完整事件流时写“已报告/已观测”，不写“全网全部”。订单方向需转成被平仓的仓位方向，买入清算单不误标多头爆仓。
- 触发状态：接近区域、标记价触及、已报告空头清算、清算后继续上涨/被卖盘吸收/结构转弱。价格触及只代表触及，不能自动改成已爆空；没有事件不证明没有清算，OI下降也不能单独证明强平。
- 动态失效：地址仓位关闭、追加保证金、清算价移动、账户抵押变化或源过期，原区域必须修订/撤销，保留旧版本。默认不在未知覆盖上绘制精确热图。

假设示例：同平台mark及可成交参考价均为1.00，已核验样本的空头风险价集中在1.10–1.12与1.20–1.24，则可显示“第一处潜在爆空区还需上涨10%–12%，第二处需20%–24%”。这只说明到达区域的距离，不表示清算将额外推动10%或20%，也不表示该市场必定能涨到这些价位。

#### 6.8.4 如果开始清算，还能推高多少

**不能用清算金额或OI规模直接换算未来涨幅。** 空头清算通常会形成减少空仓的买入需求，但部分清算、仓位转移、保险机制或ADL等处理因平台而异；不能将全部风险仓位的名义金额假设成即时扫单，更不能叫新增现货资金。

可增加两种独立研究结果：

1. **盘口冲击情景。** 在同一市场合格L2快照上，给定可能进入公开盘口的买入数量，逐档消耗卖单，计算预估均价、终端价和瞬时冲击区间。输入应来自可见仓位数量、经核验的清算机制及明确的执行比例假设；不将假设比例当真实概率。此结果命名“当前盘口下的假设冲击”，不是行情最终目标。盘口撤单/补单、套利、卖盘跟随会改变结果，超过可见深度直接标“深度不足”，不外推百倍涨幅。
2. **历史条件结果。** 对同类已发生清算事件及当时结构/费用/深度，评估预先固定H窗口的后续MFE、MAE、目标到达率和净收益分布；需要时间留出、失败样本与事件相关性处理。没有成熟样本时不输出所谓“爆空后一般还涨X%”。这是条件关联，不能自动解释为清算的因果效果。

要研究连续清算，必须单独建模初始外部价格推动、mark对交易价的响应、逐档触发、部分平仓/补保证金、流动性补充及跨市场约束。只在静态订单簿上自循环“涨价→清算→继续涨”会夸大链式效果。首版不把这种自循环模型当正式目标来源。

参与决策继续综合技术目标与清算证据：前方清算区可能是推动因素，但前面的强阻力仍要先通过；清算发生后若买盘继续、结构保持，可继续原计划的余仓跟踪；清算被卖盘吸收且结构转弱时，应按原规则减仓/退出，不能机械把清算金额加成多头分数。只根据事件与价格同时发生，不写“已证明清算导致上涨”。

#### 6.8.5 用户表达、图表与实施范围

主行使用“潜在爆空区1.10–1.12（距mark约+10%～+12%）｜近1H已报告空头清算X｜清算后：继续上涨/被吸收/证据不足”等可读字段。X必须来自实际有效数据，缺失写原因，不填0；展示样本覆盖与时间。详情并列技术目标、潜在清算区域和假设盘口冲击，颜色/线型/说明区分，用户能看到区域属于哪个平台、是报告值还是模型。

#### 6.10.2 无数据必须说明是什么原因

状态按“资产 × 市场 × 来源 × 能力/字段 × 周期”保存。来源支持但某字段为空，不能升级成整个代币不支持；被前N条截断或样本没有出现的币也不能直接判定无覆盖。

| 状态码 | 用户看到的文字 | 判定及处理 |
|---|---|---|
| available / partial | 数据可用 / 部分数据可用 | 有效字段照常使用；缺少的字段各自说明，不隐藏整币 |
| not_integrated / disabled | 尚未接入 / 来源未启用 | 是实施或设置状态，不能解释为市场没有数据 |
| unsupported / no_market | 来源不支持此数据 / 该平台无此合约 | 需明确能力目录、接口错误或市场目录证据，不能仅凭没出现在榜单判定 |
| missing / not_in_sample | 本次未返回 / 当前样本未覆盖 | 不填0；登记最近成功时间及下一次核验。HL样本、清算前60条适用 |
| warming_up / insufficient_history | 历史积累中 / 历史不足 | 显示已有时长、所需窗口与缺口；其他已满足周期继续 |
| stale | 数据已过期，最近更新X分钟前 | 旧值可灰显作历史参考，不能参与当前决策；图层标时间或退出当前叠加 |
| queued_budget / quota_exhausted | 排队刷新 / 本月额度不足 | 显示预计刷新或额度重置时间；支持能力不变，不能写成不支持 |
| rate_limited / upstream_error | 来源限流 / 来源暂时异常 | 退避、熔断、重试；最后成功值仅作带时间的历史参考 |
| auth_error / identity_conflict | 权限不足 / 资产映射待核 | 仅暂停受影响路径，给出具体来源与修复位置 |

源明确返回0，且覆盖、窗口、时间与语义有效时才显示0；例如“该来源本窗口已报告清算0”，仍不代表全网无人爆仓。null、空数组、无样本、榜单外、未扫描不能显示为0。

记录status、reason_code、source、scope、last_success_at、as_of、next_refresh_at、retry_after、coverage_version及affected_uses。可用性状态与reported/modeled等证据类型分开：模型可以是新鲜可用数据，但始终保留模型属性。

#### 6.10.3 信号不能因辅助缺失整币失效

技术路径、合约压力路径和清算增强路径分别声明必需与辅助数据。缺清算图、HL样本或辅助OI时，技术结构及执行条件齐备仍可给“建议参与/建议试仓”，同时标“清算依据暂缺”；缺少必要价格、K线、身份、执行盘口或模板硬性证据则暂停相应路径并说明原因。

缺少清算数据时不能给“已确认爆空”；价格触及模型区与观察到真实清算分别判定。旧计划保护继续由其必需的有效原生行情监控；若保护行情自身失效，明确告警“保护监控数据中断”，不能伪称保护仍正常。

来源恢复、新币加入或HL样本变化只触发能力更新与重新评估，不重置首报、不复活失效计划，也不单独推送买入提醒。达到原有参与规则后才升级行动。

## 7. 长期跟踪、目标管理及历史可追溯

### 7.1 原计划和最新状态

### 7.2 T1之后继续追踪

### 7.3 负样本与回放

用同一规则引擎按known_at顺序回放，纳入失败突破、负费率继续跌、只现货上涨、低流动性、退榜/退市、缺数据和长横盘。比较仅技术、+OI、+费用/基差、+现货流的增量；无增量或显著重复的指标不占主行。

示例文案仅用于规范：“建议参与｜4H突破成立，现价在参与区｜清算图：来源不支持，按技术路径判断”；“等待｜技术条件未确认｜HL样本：本次未覆盖”；“暂缓本路径｜执行盘口已过期｜清算模型可查看历史”。实际文案与价位必须来自正式规则及有效数据。

### 9.3 两套视图与无信号入口

- **技术分析：** K线＋EMA＋相关结构/计划，下面成交量和MACD；顶部多周期矩阵与当前行动。最近关键线默认展示，其余用图层面板展开。
- **合约分析：** 保留同一K线与计划，下面切到数量OI、费用，按需展开清算；成交量保持可访问，MACD可切回，不将所有副图挤成难辨的细条。
- **普通代币入口：** 即使没有episode也自动显示基础指标、可计算结构与多周期状态；没有符合条件的结构就显示具体空态。不能把“必须从信号页进入”作为基础指标缺失的理由。
- **信号入口：** 自动选原事件的市场/周期与范围，展开用到的结构、指标和点位；提供看首次触发、当前趋势、全追踪三个定位。
- **历史不足或无合约：** 保留可用技术图；副图显示未接入、不支持、历史积累中或过期的具体原因；不能把缺失OI画成0。

图例使用中文用途＋指标名，如“趋势参考 EMA20/50”“动能 MACD”“参与区”“当前保护价”“周线条件目标”。点击线或标记即可查看来源、公式、锚点、原始周期、确认时间和当前行动影响。长说明放详情，不挤占每根K线。

### 9.4 交互、刷新与历史冻结

1. 图层按instrument、episode、snapshot、layer_id管理；切代币/市场/周期时取消旧请求、清理旧图层，迟到响应不得画进新市场。不同市场价格不混用；用户手工绘图独立保存。
2. 行情更新当前K；signal_update/snapshot更新当前计划与图层。修订、更正和收盘事件重新对齐，禁止只在首次打开时画一次。历史快照保持冻结，明确“历史版本/当前版本”。
3. 历史压力/确认结构用实线，候选或结构测算用虚线，失效结构淡化并可查原因；不依赖红绿色才能辨认。未来确认的pivot不得回填成早已发出的信号。
4. 首报精确时间单独保存，不按4H取整后充当实际发生时间；切到1D/1W可落在所属K线上，详情保留原始时间、价格与known_at。4H事件不改名为日线事件。
5. OI/费用/清算与K线时间轴、光标联动，展示源时间、采样和缺口；盘中指标与已闭合值分开。UTC周一完整周统一，多周期按实际闭合时间判断。
6. 图层开关、预设、周期和布局偏好保存；重进不重复添加study。查看远端目标不改变原计划或将图自动缩到K线看不清。
7. 图表顶部主结论、总览行、详情与TG使用同一snapshot。原始失效、当前保护、计划撤销收盘条件必须写明，不能只写“原结构失效”。

### 9.5 可见功能的完成标准

至少验证普通入口和信号入口、首载和刷新、切周期/市场、历史模式和当前模式、失效事件、小数价格币与历史不足币。验收必须看到实际曲线、名称、对应K线和数值一致性；只有库文件、指标菜单、数据卡或一张静态示意图均不算指标接入完成。对应P2-AC15/16及63–70。

## 10. 技术架构与数据契约补全

### 10.1 模块职责

继续采用模块化单体。Next.js/TypeScript负责视图；FastAPI/Pydantic提供唯一结论接口；Python worker处理公共REST/WS、规范化、特征、策略、决策、回放及通知；PostgreSQL保存业务与时序，Alembic迁移。TA-Lib基础指标与自定义结构分别有规则版本，不复制多套含义不同的ATR/EMA而不做对照。

`发现/身份 → 原始行情 → 标准化/质量 → 特征 → 策略事件 → 参与决策 → 不可变快照 + 事件/outbox → UI/图表/TG → outcome/回放`

新增或完成模块：identity/valuation、coverage、feature snapshots、decision、cost model、validation/outcomes、target lifecycle、notification dispatcher。adapter声明能力，策略不通过散落的venue==binance写死适用来源。无某字段的源按能力降级，不假称等价覆盖。

### 10.2 持久化要求

### 10.4 指标计算、绘图与社区脚本的接入契约

继续以Python/TA-Lib和自定义结构为正式计算层，FastAPI输出结果，Charting Library负责显示。标准指标可使用内置createStudy；需要展示后端正式序列时，通过JavaScript自定义study或同步独立面板适配；结构、价带与事件用命名drawing API。价格图、指标图和信号输出必须引用同一来源与版本，不从TradingView网页抓值作为后台事实。

PineTS作为可选、隔离的研究worker/sidecar，不能替换Python核心或成为全池扫描的必需依赖。上轮核查页面版本v0.9.32，原生Pine v5/v6支持标注experimental，imports等覆盖不足；该项目声明AGPL-3.0/商业双许可。先锁定版本，以标准MACD、移动保护、收盘确认结构三个小试验检查数值和时序；未安装/未运行不能写兼容成功。复杂脚本按依赖能力定向移植或保持研究状态。

### 11.2 调度与质量

- 价格/深度/成交采用集中WS或经时效验证的替代；数量OI深采60秒、基础300秒为目标档位，按权重与实际时效验收。CMC默认30分钟并受共享额度控制；ByKaranteli使用§6.9.3的独立月预算和全局复用，不能套用原生秒级轮询。
- 全部合格资产可轮转；单批/深采容量不限制支持名单。每任务显示planned_at、last_attempt、last_success、next_refresh及queue_reason；未扫描、未返回、过期、限流、额度耗尽可区分。
- 新目录自动登记能力候选，身份和业务字段通过核验后参与计算；退市与支持范围变化按版本保存，活动计划保留必要保护监控。目录被截断必须显示不完整，不以第一批数据冒充全量。
- K线收盘触发评估，闭合柱到达后90秒目标；行情到达、采集完成、引擎完成和前端显示时间分别测量。浏览器刷新不等于外部源已更新。
- 每平台REST/WS权重与限流跨任务共享；基础并发4不等于遵守所有权重。429/418退避、熔断、恢复与补数有指标；按月实际用量、其他消费者和缓存命中对账。
- 背景队列保留轮转份额并按最长未刷新排序；额度紧张优先保留原生保护及关键行情，其余显示排队/过期。必需行情不足时暂停该路径，辅助层不足不冻结所有信号。
- 暂停新扫描仍保留已有计划保护监控；明确选择停止全部采集时展示保护监控也将不可用。
- Task租约、checkpoint、重领、幂等、outbox同事务启用；行情缺口、盘口失序、源更正及断线恢复可回放。数据恢复只触发重新评估，按现有冷却去重通知，不因恢复自动产生建议参与。

### 11.3 TG必须完成P0文本提醒

沿用官方Bot API与PD1的绑定、订阅、TTL、冷却、retry_after、delivery_unknown、去重和审计要求。绑定具体收件目标后，发送内容与同一Snapshot一致，新增主交易观点、主目标与最高条件目标美元价/涨幅/倍数/激活条件、关键反证、辅助缺口及统计状态；不得把未验证百分比写入提醒。

新建议/升级/撤销/保护退出各自遵守时效与发送前复核。未配置可访问PUBLIC_APP_URL时发完整文本并隐藏看图按钮。Token仅后端引用，测试发送须明确目标；编写本文不会触发消息发送。

### 11.4 正式运行与可恢复性

W00完成前不宣称D盘已同步。核验目录manifest、备份、进程树、端口、API来源、数据库schema与历史迁移；启动脚本需停止完整已识别进程树，避免旧worker重复运行。

部署保持Linux单机Compose目标，实际构建、迁移、volume、重启和恢复都要验证。本机Origin/Header限制不能代替服务端登录/session/CSRF与用户隔离。每日备份与7日/4周留存、原始压缩归档、重要事件证据保存、容量告警按PD1落地。

任何“已完成”必须有对应代码版本、配置版本、实际数据/fixture、测试证据与剩余缺口。单次HTTP200、空表、页面占位或框架构建不等于产品能力验收。
