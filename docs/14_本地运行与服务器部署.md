# ERJI 本地运行与服务器部署

## 运行结构

一个仓库，Next.js页面、FastAPI查询与设置、实时采集worker、后台任务worker、通知worker、PostgreSQL分进程。前端只透传SSE，业务均在Python。事件写入使用事务级advisory lock串行分配序号，避免并发提交顺序造成重连漏事件。

当前 jobs / notify 进程仅发送未启用的心跳，不领取执行任务。完整调度租约、回补、通知投递需下一阶段实现。

## Windows 本地

- 本机有Node24、Python3.14，PostgreSQL程序位于 D:/PostgreSQL/bin。
- 使用项目 .venv 和 npm workspace，版本见 requirements.lock / package-lock.json。
- tools/local_db.py 初始化独立目录 .runtime/postgres，随机密码仅保存于忽略文件 .env；端口55432，仅loopback。原系统服务不变。
- tools/start-local.ps1 启动 API18771 / 页面18770 / 三个worker角色，隐藏窗口，日志与PID写入 .runtime。
- tools/stop-local.ps1 检查启动时间后只终止登记进程树，默认保留数据库；另调用local_db.py stop可停库。

设置变化在下一采集轮次生效；一次采集约10余秒，加60秒间隔。页面15秒轮询兜底，SSE在数据落库时通知；图表5秒读取数据库当前柱。这不等于交易所每5秒采集，下一阶段接WS降低时延。

## Linux / Docker Compose

准备具有Docker Engine及Compose插件的服务器，上传源码和完整 charting_library 资源目录，或构建前运行固定版本下载脚本。无需上传 .runtime、.venv、node_modules、个人 .env 或CMC Key。

创建服务器专用 .env：

```text
ERJI_DB_PASSWORD=<随机生成的URL安全密码>
ERJI_WEB_ORIGIN=http://127.0.0.1:18770
```

运行：

```sh
docker compose config --quiet
docker compose build
docker compose up -d
docker compose ps
docker compose logs --tail=80 api worker-live
```

数据库使用持久卷，迁移作为一次性服务先执行，API健康后启动其他组件。数据库/API不映射宿主端口，网页仅绑定127.0.0.1:18770。个人测试通过SSH隧道：

```sh
ssh -L 18770:127.0.0.1:18770 user@server
```

本机浏览器访问 http://127.0.0.1:18770。当前没有公网用户认证；正式公开域名时增加登录、HTTPS和owner权限，再调整TrustedHost和Origin。

Nginx等代理需关闭SSE路径proxy_buffering、配置读取超时并转发Last-Event-ID。Next的/v1/stream只做流式代理，设置no-transform，避免普通rewrite压缩缓冲。

备份保存数据库dump、迁移版本、依赖锁和图表资源清单。不要执行 docker compose down -v 清空持久卷。定时备份/恢复演练和冷热归档待T21实现。
