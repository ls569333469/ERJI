## 1. 产品目标、范围与用户流程

### 1.1 产品要回答的问题

1. 哪些币现在出现值得参与的行情，当前是否建议参与？
2. 建议在哪个市场、什么价格区间参与，采用提前跟进还是回踩确认？
3. 是什么结构、哪个周期，哪根K线完成触发？
4. 合约持仓是在积累、扩张、解除还是重新积累？压力在哪个平台？
5. 日线与周线分别看什么目标，达到后继续持有还是调整？
6. 什么条件建议退出，数据失效和价格失效分别是什么？
7. 从首次发现到现在经历了什么，原建议是否实际可执行？

完整流程：目录与身份 → 候选池 → 采集/质量检查 → 各市场计算 → 同资产证据汇总 → 技术与合约分类 → 行动计划 → 总览/图表/TG同快照展示 → 持续更新 → 失效/结束 → 完整样本复盘。

不做自动交易、钱包签名、会员计费、交易所返佣和全网钱包枚举。建议持有/减仓/退出面向已持仓者或纸上计划；系统不假定每个收到提醒的人都实际买入。首版提供“新参与”和“已有仓位”两种阅读口径，不必连接账户。

### 1.2 资产池与容量

| 资产池 | 目录 | 首轮正式扫描预算 | 深度跟踪 |
|---|---|---|---|
| Binance Spot/Futures | 活动目录全量，区分现货/永续/交割及合约规格 | 150–200资产，包含仅现货资产 | 共享80资产预算中的优先部分 |
| Binance Alpha | 官方token list，保存chain与CA | 最多100合格资产 | 与其他池去重后分配 |
| 链上Meme/FOMO | Binance Wallet Rising；初始最多200候选 | 50–100质量合格资产 | 优先活跃事件、收藏与新触发 |

去重前为300–400扫描名额，实际数量按Asset并集显示；一个Asset的多个合约/池各自消耗接口预算。低于合格数不补无效币，超预算者排队或低频。目录数、扫描数、深度数、信号数分别显示。退榜不终止已有趋势追踪；退出由事件规则、下架或明确的数据终止决定。

链上正式扫描默认可信流通市值≥$1M，主池流动性参考门槛$100K；二者为待验证初始参数。流动性总额不等于指定金额可成交深度，仍检查实际报价/滑点和可卖出性。未知供应不得用FDV顶替；未核实安全/可交易性保留技术发现，但暂停新参与建议。Rising只负责发现，K线来自明确Instrument/Pool，不能拿热榜价拼OHLCV。

Alpha属于Binance生态池，Rising为链上发现主入口。GMGN/FOMO/Surf等不是必须串联的发现依赖。外部热度作为候选线索，不作为成交/流通事实。多链支持以发现源、身份与行情adapter真实覆盖为准，设置页只提供已验收链。

### 1.3 资产身份与市场范围

Asset、Instrument、Pool、Venue分开；同ticker不同CA不合并。封装币、桥接币、1000倍合约、反向/线性合约记录显式映射和规格。Hyperliquid是平台、HYPE是资产，Aster和ASTER同理。保存挂牌/下架、身份映射、namespace和来源的已知时间。当前目录无匹配不代表历史没有合约。

P0先把线性USDT/USDC永续按规格验收；交割和币本位反向合约可入目录，未通过换算验收前不混入数量变化。UI分别显示永续OI与扩展衍生品口径，不静默把交割合约加进原来的分母。稳定币计价转换USD保留汇率时间，脱锚不可默认1。

## 3. 信号、追踪与行动模型

### 3.1 三层状态分别保存

- **事实/解释：** 箱体突破、数量OI增加、费用偏负、已观测清算等。事实与机制推断分别存储。
- **行情阶段：** 异常关注、结构待突破、早期上行触发、结构确认、趋势持续、结构转弱、已失效、已结束，分组规则见§4.3。阶段可跳过或改变，不要求机械依序经过；它描述市场，不等于购买评级。
- **行动建议：** 建议参与、建议试仓、等待到价参与、不建议追入、暂不参与；已有仓位另给继续持有/减仓/退出计划。

同一行可显示“已有仓位建议持有；新参与不建议追入”。“已观测空头清算”是附加事实，不自动升为最高参与优先级。缺少OI不取消独立技术计划；但不能给它附加已确认合约压力标签。

### 3.2 四个P0策略模板

| 策略ID | 触发与确认 | 输出 | 主要退出依据 |
|---|---|---|---|
| `early_breakout` | 1H收盘越过事先冻结的4H结构上沿及缓冲，成交增强；显示4H待确认 | 建议试仓，若位置合适 | 该策略固定保护退出线、早期触发撤销及有效期 |
| `confirmed_breakout` | 4H收盘满足其结构突破与成交规则 | 建议参与：突破跟进 | 冻结突破撤销条件与独立盘中保护线 |
| `retest_entry` | 已确认突破后实际发生回踩，随后1H收回指定边界且成交符合规则 | 建议参与：回踩确认 | 回踩结构失效与保护线 |
| `trend_restart` | 趋势中形成新的有效整理结构并再次触发，不重复拿旧箱体追价 | 建议参与第二段/建议试仓，按确认周期 | 新episode的结构与保护线 |

仅盘中触碰为“待触发”，不能伪装收盘确认。early_breakout允许提前参与，不必等4H；独立标记其确认级别、统计失败率和收益分布。只有结构/价格规则的计划使用technical路径；满足合约组合时加上pressure路径。高OI或深负费率本身不触发买入建议。

### 3.3 行动判定顺序与可执行性

按以下顺序确定当前行动，前面的条件具有优先权：

1. 已触发保护退出/事件失效：新参与停止；已有/纸上仓位显示退出计划，记录原因。
2. 必需行情过期、身份不明或链上可卖出性未核实：暂停新的参与建议，保留事件和已知保护位，不把数据故障说成价格失效。
3. 策略未触发：显示等待到价参与，列价格区及具体确认条件；只有背景异常时为暂不参与/异常关注。
4. 策略已触发但现价超出允许追价带、成本过高或第一有效目标空间不足：不建议追入，不修改旧建议价格。
5. 策略触发、现价在参与带、深度/成本合格、规则需要的证据齐全：early为建议试仓，确认/回踩/再启动为建议参与。

初始盈亏空间门槛作为研究参数：试仓策略净R≥1.5，确认策略净R≥1.8。对做多使用入场带上沿E、盘中保护价S、第一可用目标区下沿T：`R=(T−E−盈利路径费用)/(E−S+止损路径费用)`；费用均换成每币价格单位，含手续费、预计滑点及计划持有情景资金费。T≤E、S≥E或成本未知时不能生成R。远处周线目标不能替代更近的有效阻力使R虚高。

无历史上方阻力时允许预先规定的测算目标，但显式标“测算”，不填“历史阻力”。连测算前提也不足时保留触发事实，暂停依赖目标R的入场模板；已有趋势仍可按保护线跟踪。计划不保证成交：接口延迟、跳空与滑点单独报告。

每次建议包括：执行市场、方向、策略、入场带、保护位、盘中/收盘触发方式、失效规则、目标区/依据、报价时间、有效期和下一次评估时间。到价尚未满足确认时不能显示“现在可参与”。现价超参与带后即时降为“不建议追入/等待回踩”，不能等下一根4H才改变。

风险预算是用户配置的模拟风险，不是默认读取真实资产。默认不填写账户本金；可选研究预设为试仓每计划净值风险0.25%、确认0.5%，总开放风险上限2%，均可关闭/调整。数量按止损距离和成本计算，受可成交量上限约束；这不是拿总资产25%/50%买入，也不建议默认杠杆。

### 3.4 长期追踪、首报与episode

`Campaign`代表一轮资产趋势追踪；`Episode`代表一个具体结构/策略事件；`Snapshot`是某次证据与行动版本。一个campaign可有多个独立episode；不同执行市场的计划并列而不混价。

- 首次发现价格与时间在系统实际首次识别时写入，之后不可被升级、排序、重新加载改写。
- 首次确认价格、首次建议参与价分别保存，不混称“首报”。收盘信号保存bar_close_time和detected_at，K线标记可定位开盘时间，但通知不得提前到开盘。
- 首报后涨幅始终用同一参考市场：`当前同市场价/首次发现价−1`。主市场切换后旧参考停止更新就显示缺失；不能把新市场价接上旧首报收益。
- 箱体失效后该episode永不复活；新结构创建新episode，若仍属未结束的campaign则保留campaign首报，显示“新一段”。
- P0一个Asset默认一个活动主campaign，可包含多周期/多策略事件。整体结束条件：无活动episode且没有独立确认的1D趋势，连续48小时（研究参数）无新触发后结束；身份终止/下架按数据终止单列。新campaign保留旧历史链接，不能重启以隐藏亏损。
- 同一资产多策略竞争展示优先级由第4节决定；展示主计划不会删除其他计划。

已有仓位路径可按预设目标管理：默认到第一目标区提示“建议减仓至计划初始规模的50%，剩余按确认4H低点保护”（研究预设，可关闭）；趋势持续为继续持有，保护位触发为退出。没有用户录入/纸上成交记录时标“持仓参考计划”，不显示虚构真实仓位盈亏。目标已经被首次触发前价格走过则标“已穿越”，不能事后记为计划止盈。

## 4. 信号总览设计、序号与排序

### 4.1 默认行与列

浅色全宽，单币单行，建议行高44–52px；内容不折成多行。左固定序号/代币/行动，右固定图表入口；中间横向滚动，支持列显隐、拖动宽度与恢复默认。小屏保留少量固定列，其余表内滚动，不挤成不可读的小字。

| 顺序 | 默认列 | 表达方式 |
|---|---|---|
| 1 | 序号 | 当前筛选及排序下的1、2、3…；跨页连续 |
| 2 | 代币/市场标签 | ticker + 可区分市场小标签，收藏独立按钮；悬浮显示CA/身份 |
| 3 | 当前行动 | 建议参与/试仓/等待到价/不建议追入/暂停，颜色与文字共同表达 |
| 4 | 首报 | 首报价 · 首报后% · 跟踪时长，同单元格单行；点击看首次确认 |
| 5 | 当前价 | 执行/参考市场明确，过期有标记 |
| 6 | 多周期阶段 | 如“1H触发 · 4H确认 · 日线展开”；悬浮完整状态 |
| 7 | 持仓OI/流通市值 | 如“$136M · 3.58%”，同格显示两值；没有可靠分母则“占比未知” |
| 8 | 数量OI变化 | 默认同格单行“4H +8.2% · 1D +14.6%”（格式示例）；可切1H/4H/1D，窄屏可选单周期。1D=近24小时，复用原24H字段，未知写“1D不足”；不是美元变化 |
| 9 | 主市场费率 | 平台 + 最新已结算费率/实际周期；有异常平台显示短提示 |
| 10 | 参与区 | 明确区间、当前是否在区内，不能写空泛“关注回踩” |
| 11 | 日线目标 | 价格区间 + 距离%，标历史压力/测算/已穿越/不足 |
| 12 | 周线目标 | 价格区间 + 前置条件入口；不表示本周一定到达 |
| 13 | 保护/失效 | 默认保护退出价与盘中/收盘标签；悬浮区分突破撤销和箱底失守 |
| 14 | 证据/图表 | 重要异常图标 + 图表按钮，直接定位对应事件 |

默认不展示账户多空比、神秘总分、多套重复涨幅或所有原始指标。可选列包含数量OI1H/1D（原24H）、美元变化、名义密度分位、合约量、主动成交差额、已观测清算及覆盖。页面提供“阶段总览”“建议参与”“建议试仓”“全部信号”“合约证据”入口，切换不改变事件/筛选/收藏；全部信号与合约证据采用平铺表格。

顶部将“建议参与(N)”与“建议试仓(N)”做成常驻独立入口；默认打开阶段总览，各阶段有自己的分组标题、计数和表格。另提供技术/合约/交叉、市场池、平台、时间周期、收藏、数据质量和搜索筛选。重要风险有独立常驻通知条，不能因为默认行动排序靠后而看不到。筛选显示实际条数与暂停/缺失数量。

### 4.2 排序是确定规则，不是上涨概率

默认主计划选择及排序：有效“建议参与” → “建议试仓” → “等待到价” → “不建议追入” → 暂停/结束；组内先必需数据合格，再按净R降序、距参与区距离升序、触发更新时间降序，最后asset_id/plan_id稳定打破并列。R缺失排序到底；不以极端OI或负费率绝对值单独决定推荐次序。

已有仓位模式按“需退出 → 需减仓 → 持有”的管理紧急性排序。用户自选排序支持首报时间、首报后涨幅、现价变化、OI金额/占比/数量变化、成交增强、净R、目标距离、更新时间。负费率排序明确升/降序；不是按字符串或绝对值偷换含义。

序号是视图行号，不是asset_id、历史排名或风险等级；平铺/建议列表跨页连续，阶段总览在每组内从1开始且组内跨页连续，组别折叠不重新编号。收藏/置顶为独立状态，置顶区单列，不能暗中提升策略建议；导出保留当时筛选、排序、快照时间。隐藏按稳定Asset/chain+CA持久保存，同名其他资产不误隐藏。

实时行情允许更新数字，列表位置默认不自动跳动；出现改变排序或阶段的新信号显示“有N条更新”，用户刷新排序/分组。安全状态即时覆盖此冻结规则：退出、失效、超出参与带或必需数据过期，必须立即更新行动，并从建议参与/试仓列表移出，不能为避免跳行继续显示有效买入；阶段页可原位标“状态已变”直到用户重排，计数标注快照时间。详情打开时保持滚动、筛选与选中行。服务端分页/游标绑定`list_snapshot_id`与排序版本，避免页间重复、漏行；页码切换后的序号连续，不伪装永久名次。

**默认阶段总览：** 每个阶段独立显示“阶段名 · 资产数 · 阶段含义”，下方是相同列结构的紧凑表格，可折叠/展开，列宽、表头和横向滚动保持一致。空组默认折叠，支持隐藏空组；展开偏好持久化。每币仍只占一行，不改成卡片。阶段跳转条可直接定位某组。

| 1 | 异常关注 / anomaly_watch | 通过质量检查的数量OI或费用异常等已触发，但尚无有效可交易结构 | 显示暂不参与；不把增仓叫庄家建仓 |

这是同一数据集的不同视图：某币可在“建议参与”页看到，也可在“阶段总览”的结构确认组看到，但只有一个资产记录与同一snapshot；两个入口的计数不能相加声称总信号数。顶部风险条独立于买入筛选，用户已有仓位的退出提醒不因买入页过滤而消失。

收藏/隐藏/筛选、主计划、首报、图表和TG均引用同一事件快照。阶段变化保存from_phase、to_phase、reason、changed_at；首次价格不重置，纯页面换组不生成新信号或重复TG提醒。所有“建议参与”表示规则合格的人工交易参考，不触发自动买单。

## 5. 图表与多周期目标设计

### 5.1 默认布局与图层

点击行打开大图表抽屉/弹窗，支持进入独立页面；左侧主图和副图、右侧行动计划与证据，下方平台明细与事件时间线。图表区域优先可见，OI明细不能挤压K线到无法识别。首次进入自动选择原事件周期并定位完整结构及触发柱。

必须绘制并可独立开关：

1. 明显填充的箱体/通道，标周期、起止时间、上下沿。已确认箱体与普通N根高低区间使用不同名称。
2. 指向具体K线的“首次发现”“1H提前触发”“4H确认”标记；点击标记显示收盘价、确认时间、成交倍数和规则版本。
3. 入场区/回踩带，盘中保护位、突破撤销线、结构下沿分别标注，不能叠成一条含糊失效线。
4. 日线目标区、周线目标区及来源；重叠时合并视觉区域但保留两种来源。历史压力实线、测算目标虚线。
5. 已观测清算标记与估算清算区独立图层；没有来源时不生成假热力图。
6. 触发/升级/减仓/退出的时间线；手工绘图使用独立命名空间，不改变正式信号。

成交量默认独立副图，不遮挡箱体。数量OI、美元OI、资金费/累计成本、已观测清算可切换副图；默认数量OI与费率，金额选看。副图单位、来源、采样间隔清楚，时间缺口断线显示。P0允许独立同步面板，但必须时间轴/光标联动；原生custom study可后续替换，不用伪造价格OHLC充当OI。

提供“看首次突破”“看当前趋势”“看全部追踪”三个定位；多周期按钮1H/4H/1D/1W（SDK编码60/240/1D/1W，周线适配须实测）。切换只改变查看尺度，不重写事件。价格跨度大时可切对数轴，图层价格仍是原始数值。所有标记在更大周期聚合柱上需保留精确原始时间。

### 5.2 结构识别和目标推导

基础指标：已闭合K线、价格区间/已确认拐点、相对报价成交额、ATR14（Wilder）、EMA20/50。RSI/MACD/ADX/布林带/锚定VWAP/Fibonacci/VPVR保留人工研究，不默认叠加成评分。圆弧底、双底与三角形先实验模板，未验证不冒充主策略准确识别。

P0两种结构必须区分：

- N根高点突破：使用触发前20/60根高低边界即可，名称明确为“区间高点突破”。
- 箱体：在上述候选窗口中，用已确认摆动高/低点的重复价格簇估计上下沿，分别取有效簇中位价；不用全窗口最高最低价让“内部收盘比例”永远自动通过。每边至少2次相隔≥2柱的触及，触及容差0.5ATR，至少80%收盘在候选边界内，窗口前后半段收盘中位价漂移不超过箱体高度50%，均为可配置研究起点。上下沿必须有序，候选过窄导致容差带重叠时拒绝箱体标签；未通过只能称区间，不能为了画框硬叫箱体。

拐点默认左右各2根确认，识别时间延后2根；锚点不能在当时尚未确认时进入回测特征。箱体边界在触发时冻结。突破确认缓冲默认0.25ATR14，相对报价成交额默认前20根中位数的1.5倍，强成交标签2倍；参数待验证。

| 层次 | 目标计算 | 使用限制 |
|---|---|---|
| 日线T1 | 最近已确认且仍在价格上方的日线阻力/前高簇 | 形成价格带；标样本范围、触及与最后确认时间 |
| 周线T2 | 独立周线阻力/前高簇 | 明确先突破哪一日线关口，不预测到达日期 |
| 测算扩展 | 预先固定的箱体高度投射，上沿+1倍箱体高度为首个研究目标 | 只在相应模板使用，注明测算；不能把4H投射叫周线目标 |
| 价格发现 | 已突破可用历史高点或没有上方有效阻力 | 显示历史范围；无可靠目标则给趋势保护而非编顶部 |

同周期阻力簇默认距离在0.5ATR内归并；目标区宽度至少覆盖实际拐点簇，可用该周期0.25ATR最小缓冲。目标构建仅用截至当时已确认的数据，与当前参与市场一致；平台现货高点不能直接作为另平台合约可成交目标。

1D/1W独立状态与历史长度分别显示。周K按UTC周一00:00聚合，仅用完整周；展示Asia/Shanghai时间不改变边界。初始获取尽可能多的已发布日线、上限730日；20周结构至少需要20个已闭合周，EMA50另需其预热。新币不足时不生成虚构周线，不影响已有短周期信号。

第一阻力不是涨幅上限。突破后目标状态由pending→tested→passed/failed，继续跟踪现货接力、确认低点抬升或新一轮合约压力；旧目标与当时建议保留，不能改成新目标掩盖原结论。日线趋势仍在也不能复活已失效4H计划。

## 6. OI、费用与妖币证据口径

### 6.1 五类字段、六种状态

字段层：规模（美元/市值比）、数量变化（1H/4H/1D，1D=原24H）、跨场分布、持仓成本、仓位解除证据。输出状态：持仓积累方向待定、上涨伴随持仓扩张、空头成本压力升高、上涨伴随持仓解除、高位再积累持仓、多头拥挤风险。下跌/多头清算对称保留，不能把所有场景解释成做多。

TUT校验趋势扩张路径，MYX校验数量/金额分离，LAB校验持续费用和主动套保退出，RAVE校验启动与后期挤压分段、负费率仍可崩跌。其余COAI跨市场价格分歧、SIREN多episode及事后调查、GENIUS挂牌先后、PIPPIN未知因果、AKE未证实插针/清算说法均进入研究反例。

### 6.2 数量、估值、聚合与覆盖

原始张数/单位、base数量、合约乘数、线性/反向、USD名义值、转换价格及mark/index种类全部保存。每份合约只计一次，不双算多空。原生和CMC对应同一instrument选择一个主版本，不重复相加；保留其他版本用于差异检查。

供应商内部也必须去重。本轮CMC单页BTC结果中，同一exchange_id+market_id出现两条不同价格/OI的记录；身份无法进一步消歧前，整个冲突组退出可用合计，不随意取第一条、最新一条或较大值。完全相同重复可折叠，原始证据全部保留。不同报价币或namespace的市场不能只按ticker去重。

线性合约`N=Q×P`。同集合两端的数量变化和美元变化分别算；分解可用`Σ[(Q1−Q0)P0]`数量贡献与`Σ[Q1(P1−P0)]`估值贡献，两者之和是名义变化，不是流入资金。反向合约按原始张数/固定参考敞口单列，不能以当前USD/价格的变化误称新开仓。

页面叫“已覆盖市场OI”，列included/excluded与原因、as_of、合约类别。当前金额允许汇总合格可用源；变化窗口要求起止市场集合及价格口径兼容。新增/丢失覆盖时该窗口显示“暂停比较”，不能把覆盖改变算增仓；其他单平台可比变化仍可显示。保存1H/4H/24H窗口起止与最大对齐误差；24H在数量OI界面统一显示为1D（近24小时）。

缺失状态分别为fresh/stale/missing/unmapped/no_market_in_scope/coverage_changed/insufficient_history。空响应和未匹配不自动等于零。必需OI缺失只暂停依赖OI的解释/策略，纯技术链路仍可运行。

### 6.2.1 数量OI周期命名：1D就是原有24H

原方案已包含24H数量变化，本次统一前端名称为**1H / 4H / 1D（近24小时）**。1D在本字段中就是滚动24H：截至当前合格as_of的数量，与24小时前可比较数量相比。内部窗口保留24H/86400秒，不新增一套日界线指标、不重复请求、不重复计分。

计算为`(Q_as_of / Q_24h_ago - 1) × 100%`，只对单位兼容、两端一致的已覆盖市场集合计算，起点必须大于0。任一端缺失、过期、单位未知或覆盖改变返回null+reason，不用USD变化顶替数量变化。端点采样时间和对齐误差继续使用现有窗口契约。

数量OI的“1D（近24小时）”随原生OI采样滚动更新，无须等待日K收盘。图表周期按钮的1D仍表示日K；两者通过列名、tooltip和实际起止时间区分，不把滚动OI称为“日线收盘已确认”。技术策略的日K收盘规则不受此次改名影响。

默认主表在同格单行显示4H和1D，1H可切换查看；建议参与列表、阶段组表、图表证据和TG使用相同snapshot里的24H字段。统计分位仍使用原来的按日独立样本要求，不将每分钟重叠24H窗口当独立日样本。CMC只有USD OI的样本不能生成数量变化。

### 6.3 OI比例与异常分级

OI/同期流通市值显示在默认行；分母包含circulating_supply、价格、来源、时间与known_at，FDV不可代替。不能推导实际保证金、杠杆、空头比例、控盘程度或轧空概率。不使用3%/10%/25%通用危险档。自由流通量仅允许有依据的情景，不做“总量减Top10”。数量/供给与美元OI/市值相关，不能重复加分。

历史分位按同币、同窗口、同覆盖取触发前样本。初始基线90日，1H/4H使用非重叠锚点样本，至少300个有效样本才给分位；1D（即原滚动24H）仅做背景，至少60个日样本且注明分辨率，不以短样本P97.5制造精度。期间主要覆盖改变需重建可比基线，历史不足只显示幅度，不能阻断短历史技术计划。

初始研究标签：数量增长为正且≥P90为异常，≥P97.5为强增长；数量变化为负且≤P5为快速解除；24H已结算费率和为负且≤自身P10为费用异常。单平台与可比聚合分别计算。强度只提高检查优先级，不自动改变参与方向。防抖可要求3次相隔5分钟的合格快照（至少10分钟）；真实清算事件及保护退出不等防抖。

### 6.4 主市场费率与异常平台

参考现货和参考永续独立选择。使用相同测试金额的买入/卖出预计滑点、价差、±1%盘口深度及稳定性，成交额/OI作辅助，不仅看成交额。初始测试金额$1,000、可设$100–$100,000；薄池还需可成交报价和可卖出检查。

选择合格数据中两侧较差预计滑点最低者，再以价差/持续深度打破并列。每15分钟评估；候选滑点优于当前20%并连续3次成立才切换，减少抖动。当前源失效可立即换参考，但必须标来源变更并暂停不可比指标；已发交易计划绑定原执行市场，不迁移点位与首报价。

总览显示所选主永续最新已结算费率/实际周期，预测值另列。详情展示各所费率、1H/4H/24H实际结算累计、负费率连续时长与结算次数、净成本/支付项。没有结算记录显示未结算/历史不足，不以最新费率乘次数补齐。

跨场可选24H综合费率只在同窗口/覆盖足够时，用各时点OI权重明确计算并命名“参考综合”，不是任何平台实际收费；默认不启用，不能掩盖Aster等异动。异常平台独立提示，包括其OI份额、费用异常与质量，不要求它是主市场。

负费率支付项`max(-r,0)`、正费率收入项`max(r,0)`；固定美元名义本金的空头净成本为`-Σr`。固定币数实际费用还须逐次用数量×settlement mark×费率。费用挤压、主动平空、套保退出、强平分别描述。

### 6.5 成交、清算、供给与一致性

现货与永续主动买卖差额/CVD分别计算。K线`2×taker_buy_quote−quote_volume`表示成交主动性差额，不等于净流入；记录窗口、重置与覆盖。OI/成交额是存量对期间换手，OI/深度是流动性敏感性；薄盘口也放大下跌，不能当必涨条件。

perp_last、spot_last、mark、index分开，合约/index基差默认`perp_last/index−1`，必须同时间口径；mark溢价另命名。成交价插针不自动等于mark清算触发。多空账户比是账户数，大户仓位比是特定样本，不等同全场资金方向。

清算记录position_side、native_side、订单/成交/快照、金额/数量、时间/窗口、事件ID、去重及采样限制。Binance/Aster快照不能当全量逐笔；上涨减仓仅能确认解除，OI净增也可能伴随清算。CMC清算汇总单独来源显示，不能与其包含的原生金额相加；空列表不判断0，需能力与覆盖说明。

清算区P1：最近区、给定价格范围内最大区、到某价累计潜在规模，必须带覆盖地址集/模型、mark基准、分箱、as_of和过期条件。Hyperliquid已知地址不等全地址；Aster私密仓位不能当可公开枚举。追加保证金、资金费和全仓其他盈亏会改变清算价。永续清算区不是期权Max Pain，也不是最高价；缺数据不画假区。

集中度证据独立处理，标交易所/托管/LP/桥/销毁/锁仓及实体归因局限。转入所不等卖出，解锁不等即时抛售；标签公开时间不可回填起涨前。持仓巨大但清算少、成交额远大于OI、平台OI相近均先检查单位/重复/延迟/采样，不能计算“刷OI比例”。

### 7.3 新交易所接入规范

每个adapter声明capability：目录/规格、K线周期与历史、trades/depth、OI单位与历史、funding结算/预测、mark/index、清算语义、分页/限频/时间精度。业务规则调用统一模型，不写`if venue == ...`阈值散落各处；少数源特有语义放转换层。

流程：注册禁用源 → 公共探针/官方契约快照 → 身份映射 → 原始/统一字段对照 → 缺口和限频测试 → 影子采集 → 与基准对照 → 设置页启用。新增源不自动改历史信号或跨场数量基线；启用时产生coverage_revision，相关窗口暂停/重建。来源失败隔离，重连使用去重与补数，盘口增量失序则重拉快照，不拿断层簿算滑点。

必须可支持后续追加交易所，而不改总览字段、信号策略和TG模板。CMC仅USD OI且无法可靠还原base时，可补当前美元广度，但不能进入数量变化比较集合；两种覆盖分母分别显示。

| `source.cmc_monthly_credits` | 15,000文档参考 | 用户实际套餐与usage覆盖默认 | 预算 |

| `source.switch_advantage` | 滑点改善20%，持续3次 | 0–80%，1–6次 | 切换防抖 |
| `ui.default_view/sort` | 阶段总览/第4节规则 | 可选建议参与、建议试仓、全部信号、合约证据 | 即时UI |

| `ui.stage_terminal_days` | 7日 | 1–30；完整记录在历史页 | 终态组范围 |

入场带：突破模板从触发门槛起至门槛+max_extension_atr×触发周期ATR；现价必须处于带内。回踩模板用被冻结的上下沿缓冲带，且已发生回踩收回确认。保护价必须来自该模板的已确认低点/固定ATR退出规则并冻结，不能为了提高R移动；具体规则与版本在发布时选定，不由页面临时输入目标后反算。

初版保护规则固定为：early取触发前最近已确认1H摆动低点减0.25ATR1H；不存在可用摆动低点时采用触发收盘价减1.5ATR1H并标ATR保护。confirmed取突破撤销边界下方0.25ATR4H作为盘中保护；retest取已发生回踩段最低价减0.25ATR1H；restart沿用对应提前/确认模板。盘中保护用于交易计划；原4H收盘撤销和箱底失守仍独立记录。

初始事件规则补齐：记冻结上沿U、下沿L，1次完整4H收盘低于U撤销本次已确认突破，低于L另记箱体失守；early在4H确认前，1次完整1H收盘低于U撤销早期触发。撤销边界默认U，不能事后挪到L。有效参与提醒至触发后一个触发周期收盘（early/retest为1H，confirmed为4H），期间持续检查现价；到期只停止该入场机会，campaign与持有计划仍可延续。回踩搜寻窗口为确认后6根4H，回踩带为U±0.25ATR4H；实际触及后1H收盘收回U、成交达到基线1.5倍才确认，新计划需重新通过净R/成本条件。上述周期数及保护ATR系数进入设置schema，变更只影响新episode；不可把回踩最低点提前用于尚未发生的交易。

### 8.3 发布、权限与历史一致性

普通列宽/排序偏好即时生效。策略/阈值编辑先存草稿，服务端校验单位、范围、依赖和免费配额，模拟显示影响资产数、刷新预算、哪些规则将重置。发布产生不可变`config_version`和`rule_version`，返回生效点；新事件使用新版本，已有计划保留原版本直到结束。

停止某策略时停止新入场提醒，已有计划保护与结束提醒继续；用户显式结束跟踪才终止。必须修改现有计划时创建有原因的plan_revision并发变更提示，不能静默改止损/首报。回滚创建新发布版本引用旧配置，不改历史。

凭证采用后端密钥引用：CMC环境变量/受限文件或本地密钥库，前端只见“已配置、验证时间、权限状态”，不回显原值。测试连接按钮只执行只读样本并显示字段覆盖/credit，禁打印Authorization或Key。配置导出不含凭证；Telegram Bot Token同样处理，日志脱敏。

## 9. 技术架构与数据契约

### 9.1 模块化单体，先控制复杂度

前端Next.js + React + TypeScript；API采用FastAPI/Pydantic；Python asyncio/httpx/WebSocket适配器；PostgreSQL保存业务、时序与任务/通知outbox；SQLAlchemy + Alembic管理迁移；TA-Lib负责基础指标，本地规则负责结构、目标和策略。正式版本在开发启动时选当时维护的稳定版本并提交lock文件，不把2024教程版本当2026最新，也不在运行时浮动升级。

首版一个代码库，API和worker分进程；worker按模块调度采集、回补、特征、规则、通知。数据库任务表用租约、心跳、超时重领和唯一键防重复；PostgreSQL outbox与业务事件同事务。Redis/Celery/Kafka不作为首版硬依赖，只有实测队列/缓存压力需要才增加。前端REST取快照，SSE收事件/新版本通知，上游WS由worker集中连接，不让每个浏览器直连交易所。

```text
交易所 / CMC / Wallet发现
           ↓ 只读adapter + 每源限流
原始响应归档 → 标准化/身份/质量 → PostgreSQL
                                  ↓
                         特征 → 规则 → 行动计划
                                  ↓ 同事务
                           快照 + 事件 + outbox
                           ↙               ↘
                    FastAPI/SSE        TG通知worker
                       ↓                    ↓
               Next.js / TradingView    已绑定收件目标
```

开发默认本机服务，部署目标Linux单机容器；Docker Compose提供web/api/worker/db，密钥与持久卷独立。没有Docker时可原生启动web/api/worker并连接本地PostgreSQL，不强制为写文档安装运行环境。服务端口配置化，保留当前18766预览服务作设计对照，正式应用另端口起步。

建议目录：`apps/web`、`services/api`、`services/worker`、`packages/contracts`、`engine/adapters`、`engine/features`、`engine/strategies`、`engine/backtest`、`migrations`、`infra`、`tests/fixtures`、`docs`。已有preview为参考，不把单HTML堆叠脚本直接充当正式后端。

## 10. Telegram Bot提醒

### 10.1 绑定与运行方式

采用官方Bot API。开发/本机默认long polling `getUpdates`，无需公网；与webhook互斥，单一消费进程保存update_id/offset。部署已有HTTPS公网后可选择webhook，校验`X-Telegram-Bot-Api-Secret-Token`，去重并快速落库后返回。接口版本变化在官方文档快照中追踪，不硬编码过时限额。

用户通过BotFather准备Token，在设置页后端保存引用并用getMe测试身份。生成一次性10分钟绑定码，用户在Telegram主动`/start <code>`绑定本人会话；群/频道需操作者具备相应管理权限并确认目标，验证机器人可发送。无绑定授权的chat_id不发送；改目标/停用有审计。Token不显示在浏览器URL、日志或导出文件中。

基本命令：`/start`、`/status`、`/pause`、`/resume`、`/watch <明确资产>`、`/unwatch`、`/help`。同名币让用户选链/CA，不直接按ticker猜。命令与网页使用同一订阅配置，callback权限绑定chat/user，按钮仅看图、收藏、静音，不执行交易。

### 10.2 默认发送规则与内容

订阅默认发送新“建议参与”、新“建议试仓”、已订阅计划的升级/失效/退出、重要来源故障。普通背景异动默认只进网页，可单独订阅。支持市场池、资产、交易所、策略、时间周期、行动类别、收藏限定、数据质量和静音时段。同一campaign多个策略同时触发可合并主计划摘要，保留子事件链接。

消息模板必须包含：

```text
[研究信号] ABC · 建议试仓 · 1H提前突破
市场：指定现货/永续；首次发现：时间 / 价格；首报后：百分比
现价：价格（数据时间）；参与区：下沿–上沿；有效至：时间
保护退出：价格 / 盘中触发；结构撤销：周期+收盘条件
日线目标：区间 / 依据；周线目标：区间 / 前置条件
合约：已覆盖OI金额 / 流通市值占比；数量4H变化 / 1D变化（近24小时）
费率：主平台 / 已结算费率 / 周期；其他平台异常
理由：价格和成交确认、合约状态；缺口或反向证据
计划ID / 快照时间；[打开计划] [收藏] [静音该币]
```

字段未知写未知，不填0；不带虚构准确率。demo/replay消息强制显著前缀，与真实研究信号独立目标/开关。文本控制在官方sendMessage解析后4096字符内，模板使用HTML转义，完整证据放详情链接。超长拆分必须关联同一delivery组，退出价/行动不能被截掉。

用户手机不能打开开发机`127.0.0.1`链接。默认未配置可访问`PUBLIC_APP_URL`时发送完整文本并隐藏“打开计划”按钮，标明本机模式；有经用户配置的私有网络或正式HTTPS地址后才生成深链接，不能擅自公开服务。

### 10.3 去重、更新、重试与时效

业务事件与outbox同数据库事务；去重键`destination_id + event_id + transition_type + plan_revision`唯一。持续普通更新冷却30分钟；新增参与、升级、保护退出、结构失效越过普通冷却但每个事件只生成一条。已发消息可编辑补充“已失效”，需要重新提醒的重大变更另发短消息；静默编辑不能代替紧急提醒。

发送前重新检查：订阅仍启用、事件未被更新撤销、当前价格仍支持该建议、消息未过期。过期参与信号不补发为“现在可买”，只写历史记录。队列默认参与TTL15分钟、风险TTL60分钟；下游恢复时只推最新有效状态，避免积压刷屏。

成功保存Telegram message_id；429按`retry_after`等待，5xx/网络失败指数退避加抖动，403等权限故障停该目标并在设置页提示。单chat与全局发送队列独立限速，默认全局10条/秒、单chat1条/秒作为保守调度上限，仍以官方返回限制为准；群聊可能更严，遇429自动收紧。达到重试上限进入dead-letter，可人工重试。

网络超时可能发生“Telegram已收到但本机未拿到message_id”，Bot API sendMessage没有本产品可用的任意幂等键，不能承诺端到端exactly-once。此类标delivery_unknown，禁止无脑重复发同一参与建议；重试策略要结合TTL和最新状态，显示可能重复的审计原因。

通知页必须区分：规则产生、用户过滤、冷却抑制、排队、发送成功、失败、未知、过期。TG故障不阻断网页和行情。保护提醒也是软件通知，不保证替代交易所止损单；自动下单不在本期。

## 11. 历史研究、回放与策略验证

复盘数据已有9币价格/OI、8币Aster K线/费率及官方校验记录；不把赢家选样当准确率。输入记录raw/as_of/known_at、身份和当时覆盖；按时间顺序、真实确认延迟运行同一规则代码，禁止用未来拐点、后来公布地址调查或当前流通量回填过去。

加入失败突破、深负费率持续下跌、现货独立上涨、仅单平台异动、低流动性、退市、缺数据及长周期横盘样本。训练/验证按时间和资产分离，同一campaign不跨集合泄漏。比较仅价格、+数量OI、+资金费/基差、+现货主动成交的增量效果，低增量指标可从默认信号撤下。

报告全部事件分母、提前量、误报/漏报、建议覆盖率、1H/4H/24H及固定持有窗口的MFE/MAE、最大回撤、费用滑点资金费后的纸上收益分布、可成交容量。明确未成熟/数据缺失/未成交；同根K线触及目标与止损用更细数据，否则顺序未知并保守处理。

发行到峰值、首次可监测到峰值、首报后价格表现、按策略真实可成交模拟收益分别展示。首次确认以前的涨幅不能宣传为信号收益。策略可在research_live中给明确建议并跟踪，但“盈利已验证”只能在独立验证后标注；不凭短期100%胜率加认证徽章。

## 12. 运行目标、存储、权限与故障处理

### 12.1 调度与性能目标

闭合K线正常到达后90秒内完成评估；新有效参与/退出事件落库到通知出队目标P95≤10秒；列表缓存读取P95≤1秒，以上均为目标待测，不含上游延迟和Telegram网络延迟。展示provider_age、received_age、engine_lag、notification_lag分别归因。

深度资产盘口/成交优先WS，OI60秒、基础资产OI300秒，目录/候选低频更新，CMC预算控制默认30分钟。费率按结算事件和下一结算时点调度，不对所有币每秒轮询。每源权重预算、并发、退避、熔断、重连/补数独立；达到免费配额降频并展示覆盖变化。用户暂停扫描可选保留已有计划保护监测，默认保留。

5分钟深度/价格聚合、K线、OI采样与事件数据按时间分区。数据库容量超限预警，不能删除原事件所需证据后仍宣称可复算。

### 12.2 保存周期与备份

原始盘口增量默认不全量长期保存：保留诊断最近7天与事件前后窗口；规则必要的聚合深度样本90天。原始采集响应30天压缩归档，事件引用片段和哈希至少1年；标准K线/OI/funding至少1年，重要campaign/plan/notification/config历史至少2年。参数可缩短，但必须显示对回放能力的影响。

PostgreSQL每日备份、保留7日+4周；版本迁移前备份并做恢复演练。大历史文件用本地压缩Parquet/JSONL分区，数据库留引用，未来可接对象存储。市场数据归档与用户凭证分开；不把密钥写入原始响应、错误堆栈或日志URL。

### 12.3 身份与运行边界

本机开发默认loopback，不隐式公网暴露。正式多人部署需登录、session、CSRF/权限隔离，设置/源启停/订阅修改需管理员或对应owner；公开只读行情与私有收藏分开缓存。密钥仅后端读取，API返回脱敏状态。没有账户交易权限、私钥、签名或下单端点。

停电/worker崩溃恢复从数据库checkpoint补数，sequence去重后重算必要窗口；不能重复发首次信号。源更正数据产生revision，通知解释更正，不删除旧结果。上游和CMC不一致时保留两份及差异，暂停依赖冲突字段的组合标签，纯技术数据正常时仍可继续。

当前授权是完成方案及准备实现；本文不是已完成代码或自动部署记录。下一步依此实施，不需要重新讨论已确认的市场范围、图表版本和单行布局；真实能力缺口用降级状态与测试结果处理。
