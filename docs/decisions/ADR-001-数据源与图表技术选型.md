# ADR-001：数据源与图表技术选型

- 状态：已接受（首版）
- 日期：2026-09-23
- 范围：公开市场数据、图表、指标和研究补充

## 决定

1. 首版实时核心为 Binance Spot/Futures、Hyperliquid Info API/WebSocket、Aster Futures API V3/WebSocket。
2. OKX 用于跨场复核；Gate、Bitget 在第二阶段按覆盖增量接入。
3. CMC、CoinGecko、DexScreener、Surf 不作为唯一的实时衍生品来源，只提供身份、市值、链上池子、标签和地址级研究补充。
4. 前端使用 `TradingView Lightweight Charts`；不依赖 TradingView Advanced Charts/Charting Library 的公开副本。
5. 标准技术指标使用 `TA-Lib`；复杂形态使用版本化本地规则，先输出候选与确认状态。
6. 核心数据层使用自建 source adapter；CCXT 只作为未来长尾现货适配器。

## 原因

- 原生 API 能保留 OI、funding、mark/index、清算、盘口和限频等交易所特有字段。
- Hyperliquid 和 Aster 是用户明确要求的 Perp DEX，且其公共市场接口可以不依赖交易账户。
- Lightweight Charts 的开源许可和职责清晰，能满足 K 线显示而不引入 Advanced Charts 的授权不确定性。
- TA-Lib 适合验证标准指标；形态识别需要结合本项目的 K 线闭合、成交量基线、颈线和失效条件，直接照搬第三方形态库会带来许可证或质量问题。
- 付费数据商用于补充而非核心，核心链路在没有 key 时仍能运行。

## 后果

- 需要自行维护资产映射、限频、WebSocket 重连、历史存储、字段归一和质量监控。
- Surf/CMC 等来源的覆盖和配额变化不会直接阻断实时市场雷达，但会使地址或市值字段变为 `unknown`。
- 不能用一个总分掩盖不同来源的口径差异；页面必须展示来源、时间、单位和缺失。
- 首版可以做 S1/S2 规则研究，无法宣称全市场地址仓位覆盖或预测必然逼空。

## 拒绝的替代方案

- 不把 CCXT 作为全部市场数据的唯一抽象层，因为它会隐藏衍生品特有字段和交易所差异。
- 不把 TradingView 网页产品或 GitHub 公开副本当成免费行情/形态 API。
- 不把 CMC、DexScreener 或 Surf 的聚合字段直接当作 Binance、Hyperliquid 或 Aster 的原始 OI/清算事实。
