# 多源加密市场雷达产品需求文档

版本 v0.5 指标与信号研究稿　原编制日期 2026年9月23日（Asia/Shanghai）　用途 产品评审与研发拆解

本产品帮助交易者从大量加密资产中筛选价格、成交量、持仓量和资金结构发生异常的标的，查看可追溯的信号依据，并持续跟踪信号出现后的表现。首版覆盖 CEX 与 Perp DEX，把 Hyperliquid 和 Aster 纳入核心范围，重点建立“筹码集中与流通约束 → 空头拥挤与流动性脆弱 → 启动及持续逼空”的证据链。提供 K 线、分级告警、观察池和历史复盘，底层数据源可替换，不绑定单一交易所或 AI 服务。

已确认的市场范围分两部分：Binance Spot/Futures/Alpha 资产，以及由 Binance Wallet Rising 发现的链上 Meme/FOMO 候选，后者优先筛选市值至少 100 万美元。Hyperliquid、Aster 是合约证据来源，HYPE、ASTER 代币与各自平台分别建模。免费 API 优先；流通市值、持仓、清算等缺失时明确降级。具体策略参数与预测有效性尚未验证。

v0.5 采用“可观测事实 → 明确规则 → 组合假设 → 独立验证”的设计。标签直接描述价格结构、成交、持仓和清算，不沿用竞品代号。VPVR 是可选图表研究工具；固定 OI 比例风险分档和未经验证的综合权重已撤下。本版确定的是可测试的第一版设计，不是已验证盈利策略。

本文定义产品行为和验收要求。具体数据商、接口可用性、开源组件和成熟产品的借鉴方式，见配套《工具与API选型 v0.4》。文中的信号阈值属于待验证的产品初始参数，不是原站算法，也不代表已验证收益。

## 1 产品目标与默认边界

目标用户是希望快速发现异动、核对资金行为并自行做交易决策的个人交易者和小型研究团队。典型路径为“发现异常 → 检查依据 → 查看 K 线与其他市场 → 加入观察池 → 接收变化提醒 → 回看结果”。

首版交付一个持续运行的网页应用，支持桌面和手机浏览。默认只读取公开行情，用户不需要提交交易所交易权限或钱包私钥。自动下单、账户资产管理、跟单、收费会员和返佣体系不在首版范围内；是否开发这些功能在产品验证后另立需求。

成功标准首先是数据可信、告警及时和操作省时。不得以“必涨”“胜率保证”作为功能承诺。使用率、告警后查看率、收藏率可以衡量产品价值；信号有效性必须另用完整样本和明确基准评估。

## 2 参考产品与差异

参考杰尼君妖币雷达的分级信号列表、首次告警价格、OI 与成交量联动、风险标签、历史告警和 K 线分析。当前公开证据表明，其 K 线形态匹配样本与 Binance 现货 K 线一致，部分雷达指标与 Binance 合约接口一致。我们借鉴用户工作流，不复制其未公开的评分公式、视觉素材或后台代码。

本产品增加四项能力：同一资产跨交易所核对；每个指标可查看来源与时间；告警生命周期与持久去重；把规则信号与 AI 解释分开显示。交易所已上市资产和链上早期资产采用不同的候选范围、风险条件和评分基线。

## 4 用户流程与页面

### 4.1 雷达首页

进入页面首先看到当前数据状态、候选数、最近更新和筛选条件。可按交易所、现货或永续、资产类别、报价成交额、上市时间、信号类别、风险和关注状态筛选。默认按信号等级、数据质量和触发时间排序；用户可切换涨跌幅、OI 变化或成交量倍数排序。

首页提供“技术形态”“资金与逼空”“交叉筛选”视图。技术形态视图可以筛选“1D 收盘突破”“4H 回踩观察”“圆弧底候选”“圆弧底颈线突破”，并显示数据市场、周期、压力位、放量倍数、距突破位幅度、确认状态和首次发现时间。交叉筛选允许同时要求技术突破与衍生品证据，分别展示各自理由，不将相关指标重复累加成上涨概率。

列表包含资产名称、交易所和市场类型、信号等级、主要触发理由、首次告警时间及价格、现价、告警后涨跌幅、1h/4h/24h 涨跌幅、对应 OI 变化、成交量倍数、资金费率、主动买卖比、多空比例及其统计口径。合约列还显示 OI(USD)、OI/流通市值、OI/有效流通估值、OI/现货成交额、空头/多头清算、基差和数据覆盖状态。链上列显示市值、流动性、持币地址、Top10 集中度和币安钱包 Rising 来源。手机默认展示关键列，其余在详情展开。

逼空视图增加：所处阶段、流通约束证据、空头拥挤证据、买侧冲击成本、已观测空头清算、跨场确认数、证据完整度。避免在首页堆满指标，点击理由可展开原始数值与反向证据。示例标签应是“集中度上升，标签覆盖有限”，不能自动显示“庄家已控盘”。

点击一行进入详情；收藏操作不修改信号等级；隐藏某资产后，以稳定资产 ID 持久保存，刷新和同名新记录不会重新弹出。全链同名代币不得一起隐藏，除非用户明确选择范围。

### 4.2 资产详情和 K 线

详情页显示资产身份、价格所属市场和计价币。主图默认只有 K 线、成交量、支撑阻力区、区间边界和信号标记；EMA 可切换。副图按信号需要展开 OI、资金费率、主动成交和已观测清算，明确是否来自其他市场。VPVR、锚定 VWAP、Fibonacci 等为可选研究叠加，未验证可用性前不承诺内置支持。图表绑定触发、确认、失效时间及当时保存的点位。切换市场不会拼接不同市场 K 线，也不会把合约点位直接当作链上现货可成交价格。

信号解释采用“发生了什么、数据证据、成立条件、风险和缺失数据”结构。例如：过去 1h 报价成交额较过去 20 根已闭合 1h K 线中位数放大 3.2 倍；同交易所 OI 增长 8%；价格上涨 2%。这些内容来自规则和数据快照，AI 只能补充解释。

### 4.3 观察池和告警中心

观察池保存收藏、备注、加入时价格和当时信号版本，可设置特定来源或任一来源触发提醒。告警中心区分首次触发、持续中、升级、风险加剧、恢复和结束，展示触发次数和首次触发位置。

推送至少包含资产、市场、来源、触发时间、关键数值、数据是否延迟及详情链接。通知授权由用户在产品内主动开启；Telegram、邮件或 Web Push 选一条先实现。静音与隐藏状态跨刷新保留，传输失败应重试并记录，不重复生成新的信号事件。

### 4.4 历史复盘

历史页可按触发日期、规则版本和交易所检索，默认展示所有已经产生的信号，不只展示盈利案例。展示首次信号后 15m、1h、4h、24h 的价格变化、最大有利偏移和最大不利偏移；到期、未到期、缺失和下架分别计数。

只有在展示的是实际或严格模拟交易时才使用“收益率”“胜率”字样。纯价格跟踪标注为“告警后价格表现”，不计入未发生的成交，也不把样本最高价视作可实现卖出价。

### 4.5 信号与 K 线联动

信号由后台规则服务根据指定市场的已闭合 K 线和其他证据生成，图表前端只负责读取快照并展示。每个事件至少绑定 `asset_id`、`instrument_id` 或 `pool_id`、`timeframe`、`source`、`event_time`、首次触发 K 线时间、规则版本、触发值、确认条件和失效条件。

联动流程固定为：

1. **采集：** Binance Spot/Futures/Alpha 使用各自原生 REST/WebSocket；链上代币使用指定 `chain_id + pool_address` 的池子 OHLCV、交易和流动性数据。不同市场不拼接 K 线。
2. **计算：** 后台只用当时已经闭合的 K 线计算区间、相对成交额、ATR、EMA 和形态状态；OI、Funding、清算、持币集中度等作为独立证据输入。
3. **生成事件：** 规则服务写入信号快照和图表点位。盘中越过边界可以先产生可撤回观察，收盘后才生成收盘确认；历史事件不因当前数据变化而重算。
4. **打开图表：** 用户点击信号卡时，前端按 `instrument_id + timeframe + event_id` 请求 K 线和叠加层，自动跳转到首次触发 K 线，并突出显示触发、确认、回踩和失效位置。
5. **反向查看：** 用户点击图表标记时打开同一个信号卡，看到支持证据、反向证据、数据覆盖和缺失项。图表上画出的线不能单独升级信号等级。

Binance 已上市资产的价格图使用对应的 Spot 或 Futures K 线；合约 OI、Funding 和清算只叠加到对应合约市场，不能把合约点位当作现货成交点。链上 Meme 图使用具体池子的价格和交易数据，没有可验证的永续 OI 时显示 `not_available`，不能借用 Binance 或其他市场的 OI 填充。

本项目使用 `TradingView Lightweight Charts` 作为渲染层，具体由我们提供自定义 Datafeed（REST + WebSocket）：

- `CandlestickSeries`：显示指定市场的 OHLCV 和闭合状态；
- `LineSeries`/面积或价格线：显示 EMA、支撑阻力带、箱体边界、VWAP 等后台已计算结果；
- `SeriesMarker`：标记候选、确认、回踩、失效、清算和数据质量事件；
- 自定义 overlay：绘制箱体、支撑/阻力区域和斐波那契锚点；
- 独立 pane：显示成交额、OI、Funding、主动成交、已观测清算和数据质量；
- 交互契约：卡片与标记使用同一 `event_id`，缩放或拖动不会改变已保存的信号点位。

`Lightweight Charts` 不提供行情、OI、指标、Pine Script 或 Strategy Tester。指标由后台确定性计算，策略由本地回测服务执行；TradingView Advanced Charts/Charting Library 只有在取得合法授权后才作为可选替换，GitHub 公开副本不作为依赖。

## 5 数据字段和统一口径

### 5.1 资产身份

Asset 为经济资产，Instrument 为具体市场，Pool 为链上流动性池。交易所 Instrument ID 至少包含 exchange、market_type、原生 symbol、base、quote、settle、contract_size、linear_or_inverse。链上资产 ID 至少包含 chain_id 与完整合约地址；池子还需 dex 和 pool_address。

CMC ID、CoinGecko ID 可辅助映射，不能仅凭 ticker 合并资产。1000 倍面值合约、封装币、桥接币、币本位合约、指数和贵金属标的须显式标记。人工审核映射变化，并保存变更历史。

### 5.2 原始记录必备元数据

每条行情、K 线和统计记录都保存 source、native_instrument_id、event_time、received_at、period、unit、quality_status 和原始响应引用或校验值。UTC 为存储基准，界面可切本地时区。用户能够区别数据发生时间与网站抓取时间。

Perp DEX 还保存 network、dex_namespace、product_version、visibility_scope、address_sample_size、coverage_basis；Hyperliquid 原生市场与 HIP-3 市场不混用。持币快照保存 block_number、supply_denominator、标签提供者与版本；推断聚类保存依据和置信度。清算记录保存 actual_or_estimated、snapshot_or_complete、side_semantics、notional_method，避免将清算订单方向直接当作被清算仓位方向。

### 5.3 指标定义

| 指标 | 产品定义 | 必须处理的差异 |
|---|---|---|
| K 线 | 同一市场同周期的 OHLCV | 开盘时间、闭合标记、基础币量与报价量、补发与修订 |
| 涨跌幅 | 目标时点价格相对同口径基准价 | 滚动 24h 与自然日分开，现货与合约分开 |
| 成交量倍数 | 最近一根已收盘K线的报价币成交额 ÷ 此前同周期历史基线；例如日K的USDT成交额 | 分子和基线同来源、同周期、同单位；当前周期不进入基线，基线不足显示不可计算 |
| OI | 先保留原始数量和单位，再归一为基础币及名义价值 | 张数、币数、USD 价值和合约乘数，币本位换算 |
| OI 增幅 | 同来源同口径数量变化 | 价格上涨本身会抬高 USD OI，数量增长与名义价值增长分开 |
| OI/流通市值 | `OI_USD ÷ circulating_market_cap`；有效流通估值比作为独立情景 | 流通量/有效流通量必须带时间、来源和区间；分母不可靠则不可计算；这是相对压力指标，不是操盘证明 |
| OI/现货成交额 | `OI_USD ÷ rolling_spot_quote_volume` | 说明窗口、现货来源和是否跨场聚合；用于衡量持仓相对承接能力 |
| OI/价带深度 | `OI_USD ÷ visible_sell_depth_in_band` 或指定名义金额冲击成本 | 深度不足不能填零；盘口、AMM 和交易所深度不可直接混合 |
| 价格与OI联合状态 | 同窗口价格变化与OI数量变化分别呈现，另附费率和成交解释 | 不使用OI增幅/价格增幅，也不把二者相减定义为标准指标；OI增加不识别新多或新空 |
| 成交量分布（可选） | 指定范围内按价格分桶，输出POC及价值区 | 显示范围、分桶、量的单位和数据覆盖；低周期OHLCV估计不能当作真实持仓分布 |
| 资金费率 | 原始费率加原结算周期 | 1h/4h/8h 及动态周期，换算值必须标明方法 |
| 多空比 | 来源明示的账户或持仓统计 | 全市场与大户、账户数与持仓量不可混用或直接平均 |
| 主动买卖比 | 主动买量 ÷ 主动卖量 | 明确交易所、周期和量的单位；零分母不显示无穷大评分 |
| 市值和 FDV | 数据商提供的可解释估值 | 流通量、总量、时间和币种映射；不以 FDV 代替市值 |
| 调整后集中度 | 排除明确托管及协议容器的误导后，观察已识别实体的份额 | 同时保留原始钱包集中度；交易所、桥、池子、销毁、锁仓分别分类，不能一刀切 |
| 有效流通估计 | 特定时点可交易供应的情景区间 | 锁仓/解锁、做市借币、交易所库存、跨链映射和不可观测持有人影响估算 |
| 流动性脆弱度 | 指定名义金额的买入/卖出冲击成本、可见价带深度 | 盘口层数不足、撤单、隐藏订单、AMM曲线、跨场资产能否转移 |
| 已观测清算 | 来源实际推送的清算订单或成交事件 | 快照会漏报；委托量不等于成交量；没有推送不代表没有清算 |
| 预计清算区域 | 根据可见仓位或第三方模型估计的价格区域 | 追加保证金、交叉保证金、标记价及账户模式会改变估算；不是确定清算价格 |

跨交易所价格可使用排除异常值后的代表价格，但原始来源始终可展开。聚合 OI 仅对已校验的同资产、同单位市场求和，并标注纳入交易所及覆盖变化；不对多空账户比做简单平均。

## 6 信号规则和生命周期

### 6.1 候选范围及质量门槛

首版采用“目录全量、正式扫描、深度跟踪”三层数量，数量是免费 API 和首版容量的起始假设，不是收益筛选结论：

| 资产池 | 目录层 | 正式实时扫描 | 深度跟踪 |
|---|---|---|---|
| Binance Spot/Futures | 全量读取活动交易对和合约规格；现货与永续分别建模 | 150–200 个 USDT/USDC 线性永续，并跟踪其对应现货；按成交额、流动性和数据质量动态替换 | 30–50 个资产，增加盘口、OI、Funding、清算和跨场复核 |
| Binance Alpha | 全量保存官方 token list 的身份和状态 | 约 100 个新发现或高热度候选；其中达到质量门槛者进入正式信号 | 20–30 个候选，增加交易、池深度和合约风险观察 |
| Meme/FOMO 链上 | 每次榜单/发现快照最多保留约 200 个候选，按 `chain_id + contract_address` 去重 | 50–100 个达到市值、池流动性、真实交易和安全检查门槛的候选 | 20–30 个重点池，增加 15–60 秒级成交/盘口或池深度刷新（受来源限频约束） |

Alpha 候选和 Meme/FOMO 候选可能是同一个链上资产，必须按完整链和合约地址合并，不能重复计数。合并后首版预计约 200–300 个 Asset/Instrument 进入正式规则，约 50–80 个进入深度跟踪；实际数量根据 API 限频、延迟和数据缺失率调整。目录层不等于高频采集，观察池也不等于已确认信号。

流动性按档位分组，薄流动性是研究因素，但低于可评估门槛的资产只能显示观察或数据不足。上市时间不足、K 线缺失、价格源冲突或 OI 口径不明时，不生成依赖相关字段的高等级告警。

规则不要求每个交易所都具备所有字段。OI 缺失时可生成明确标记“价格与成交量信号”的观察记录，不能把缺失当成 0，不能升级为资金结构确认信号。

### 6.2 首版规则与参数原则

先定义指标口径，再选择阈值。首版技术事件是区间收盘突破、突破量能确认、回踩保持和结构失效；合约事件是持仓数量扩张/收缩、费率异常与已观测清算变化。组合事件通过第6.5节解释，独立技术事件不依赖OI数据。

20/60根历史区间、ATR14、EMA20/50和20根相对成交额基线是便于复现的起始研究配置，并非已证明最优。第7.4节的ATR缓冲与放量门槛只用于展示候选规则；发布前需固定配置并做历史及前向评估。所有“异常”“收缩”“保持”标签必须具有可复算的数值定义、窗口与失效条件。

同资产历史分位用于表达“相对自己是否异常”，相似流动性和市值分组用于比较“相对同类是否异常”。它们不是收益概率。价格使用已收盘数据，历史基线排除当前评估柱；横截面和供应数据也必须使用当时可见版本。没有充分历史时，输出原始数值和“历史不足”。

### 6.3 分数与风险

第一版展示事实标签、已满足/未满足条件、反向证据和数据覆盖，不输出未经验证的机会总分。此前讨论中的技术40%/合约35%/链上25%不作为产品权重。EMA、RSI、MACD等来自相近价格信息，不因同时出现而当成多条独立证据。若后续输出概率，必须先明确预测事件和期限，再提供独立测试样本、校准误差和置信区间。条件符合度不能称上涨概率。

### 6.4 状态机和去重

事件状态为观察、盘中预警、收盘确认、持续跟踪、结束、已失效；数据暂停评估单列，不能用断档代替市场失效。状态描述规则进度，风险标签可并存。所有阈值、有效期限、连续确认次数和失效条件随规则版本保存。

去重键为 asset_id、instrument_id、signal_family、rule_version、episode_id。持续事件不重置首次告警价与首次告警时间；次数与最新值另行更新。默认普通重复通知冷却 30 分钟，等级升级或显著风险变化可越过冷却，但仍在同一事件下记录。旧事件结束后重新触发建立新 episode，历史记录不可覆盖。

### 6.5 连续逼空模型：本轮重点讨论

产品假设是：供应约束、衍生品拥挤与流动性不足同时存在时，小幅买压可能引发空头回补和清算反馈。该假设需要数据验证。我们识别结构和阶段，不把“庄家操盘”作为已证实标签，也不把“几十倍”作为预测输出。

| 阶段 | 需要观察的组合证据 | 输出与失效条件 |
|---|---|---|
| S1 结构观察 | 持币或实体集中、潜在流通约束；OI 对有效流通估值偏高；负费率/合约贴水等拥挤代理；卖盘薄或买入冲击较大 | 输出候选与缺失项；高集中可保留很久，不能给出启动倒计时 |
| S2 启动确认 | 价格走强与真实成交配合，现货买压或跨场跟随；公开空头仓位减少/清算事件出现；盘口被实际成交消耗而非仅撤单 | 至少两类独立证据共同支持；只有合约跳价或单一市场异常则不确认 |
| S3 持续与退潮 | 连续拉升中的费率、OI数量、回补及新仓、现货承接；大额转入交易所、集中实体减持、盘口恢复、价差和流动性变化 | 区分持续逼空、一般动量和退潮风险；OI下降、费率翻正、交易所入金都不是单独退出条件 |

首版显示五组证据：供应集中与可流通性、衍生品拥挤、流动性脆弱、启动行为、反向与质量证据。先做规则标签和证据完整度，不急于把五组压缩成一个“妖币概率”。“确认”指证据条件达到，不代表未来必涨。

**关键口径：**

1. 一份未平仓合约同时有多方和空方，总多空名义量在匹配口径下相等。需要研究的是空方杠杆、保证金、成本、持仓集中和流动性脆弱性；不能声称 OI 增长证明“空头总量超过多头”。大户账户多空比也不是全市场仓位占比。
2. 负费率通常表示空方向多方付费，是拥挤代理而非充分条件。现货多头加合约空头的套保也会造成相似结构。持续逼空中费率也可能转正，因此不把“必须负费率”写成所有阶段的硬门槛。
3. Top10 地址份额高不等于同一人控制。交易所托管可能代表众多用户，桥与池子是容器，一个实体也可能拆成很多地址。共同资金来源、转账关系和同步行为只提高关联置信度，不自动认定同一控制人。
4. 原始钱包集中度、标签调整后集中度和实体聚类集中度分别展示。剔除托管容器不是把其中代币从流通量中全部扣掉；跨链供应需要防止重复计算。有效流通量不能直接等同“总量减Top10”。
5. `OI_USD / 有效流通估值` 与 `OI_USD / 指定价带卖盘深度` 仅作同组资产的相对压力指标。有效流通量用区间，深度不足就标记不可计算。Hyperliquid 公共 L2 最多20档，不能保证覆盖 +1% 或 +2% 价带，不能把档外未知深度视为0。
6. Hyperliquid 可查询已知地址，但完整市场仓位分布需要地址发现、索引、去重与持续补数。样本覆盖率仅在单边/双边 OI 分母已校验且快照同步时计算，否则只显示样本量。不能把排行榜样本当全市场。
7. Aster 当前公开市场总量与账户权限分开。自身仓位以及特定 builder 范围的仓位接口有认证和范围限制，不能据此承诺“任意地址仓位扫描”。

### 6.5.1 OI 相对市值：观察名义持仓密度

主指标为 `已覆盖市场的单边OI名义金额合计 / 可核实流通市值`。例如已覆盖OI为2000万美元、同期流通市值为1亿美元，比例为20%。它不是20%的流通币被做空，不是保证金比例，也不代表已知杠杆倍数。衍生品敞口可以大于现货市值；即使超过100%也不能单凭比例认定操盘。

- 每份匹配的合约只计一次；先统一合约乘数、币本位/线性合约和币种身份，不能把多空两侧重复相加，也不能将聚合商与原生交易所重复计入。
- OI数量变化和USD名义变化分别显示；价格上涨会机械地抬高USD OI。比较历史时固定市场覆盖，新增来源单独标注，不能制造持仓增长。
- 主分母使用可核实流通量与同步价格；有效流通量是更不确定的独立情景区间，不能悄悄替换主分母。只有提供方marketCap、口径未知时另列“估值代理比”，不冒充流通市值比；FDV不得替代。
- 交易所托管、桥、池子不等同锁仓；不得用总量减Top10持币量计算有效流通。供应数据过期、映射不明或分母为零时停止比例类判断。
- 可补充同范围OI/现货成交额、盘口价带深度、模拟成交冲击，但盘口不足或交易量疑似刷量时降级。高OI本身并不证明现货承接弱或高杠杆。

撤下此前3%/10%/25%的统一分档：目前没有验证结果支撑这些界线。首版展示实际比值、纳入市场、分母来源及时间；数据充分时另显示历史分位和同组分位。窗口长度、采样频率、同组定义和最少有效样本要作为研究参数固化，不能针对单币事后挑选最有利结果。未完成验证前，分位只用于描述和排序，不用于声称轧空概率。

### 6.5.2 自有标签体系：事实、解释与事件分开

用“周期/范围 + 可观测变化 + 确认状态”命名，可同时附多个事实标签。涨跌方向、机会、风险、数据质量各自展示，不把它们压成一个数字。

| 标签 | 可观测依据与计算要求 | 含义边界 |
|---|---|---|
| 波动收缩 | ATR/价格或已定义区间宽度相对过去降低，记录窗口及分位 | 只说明波动变小，没有突破方向或倒计时 |
| 区间收盘突破 / 跌破 | 已收盘价越过此前冻结的区间边界及缓冲 | 说明规则成立，不承诺后续趋势 |
| 成交额放大 | 已收盘报价成交额相对先前同周期基线增加 | 不能单靠成交量推断买入或建仓 |
| 回踩保持 | 首次突破后触及冻结的边界带，收盘保持且未触发失效 | 必须等待回踩发生，禁止回填历史确认 |
| 结构失效 | 收盘跌回预定失效线或规则规定的结构被破坏 | 展示具体失效规则，数据断档不归此类 |
| 持仓扩张 / 收缩 | 同来源同窗口的OI基础数量变化，超过采样噪声并满足版本化规则 | 不能推断资金净流入、同一庄家或开仓方向 |
| 名义持仓相对估值偏高 | 可靠OI/流通市值相对自身或同组偏高，展示实际值和比较基线 | 不能从比例推算杠杆或操盘主体 |
| 费率偏负 / 偏正 | 原始结算周期下的费率及历史偏离；已结算与预测分开 | 套保、做市和利率基准均可能影响，非空多持仓百分比 |
| 空头 / 多头清算增加 | 来源明确的被清算仓位方向、金额、窗口和同口径基线 | 只称已观测事件，非全市场全量清算 |
| 可见流动性下降 | 固定价带/交易规模的深度或冲击成本恶化 | 撤单和实际成交分别处理，深度未覆盖不填零 |
| 持币集中度偏高 / 上升 | 可追溯持币快照、标签调整和变化 | 不等于一个实体控盘，不直接参与买入确认 |

“异常”和“偏高”的启用门槛须通过第7.9节验证；此前可以显示连续原始值及分位，研究标签明确标为未验证。首次信号价、相对首次信号涨跌幅和触发次数均是事件记录，不表示首次建仓成本或预期倍数。截图中OI/价的算法未知，不将其当作OI/市值或复用其数值。

组合解释独立于上述事实标签：

1. **价格突破伴随持仓扩张**：价格收盘突破、报价成交额放大且OI数量上升。三项分别保存；不自动称为空头燃料增加。
2. **空头挤压条件积累（观察）**：名义持仓相对估值偏高、可靠流动性约束、空方压力代理（如持续负费率与合约贴水）组合成立，价格未持续走弱。只描述脆弱结构，允许长期不触发；账户多空比不作必需条件，多空套保可形成反例。
3. **上涨伴随空头清算（已观测）**：价格/现货成交走强且有同窗口可靠空头清算增加；OI数量下降是支持项而非必需项，新仓补入时总OI也可能上升。可附“存在轧空迹象”的解释，不认定操盘因果。
4. **上涨伴随持仓收缩（原因待核）**：只有价格上涨和OI下降，缺清算/仓位证据时使用此标签；不得升级为清算已经发生。
5. **下跌伴随多头清算（已观测）**：价格下跌并伴随同窗口可靠多头清算。正费率和相对持仓密度仅为背景，按同样标准处理覆盖和反例。

观察阶段、已观测事件和未来概率是不同输出。资金费率转正不自动终止已观测轧空，也不要求所有平台都有清算接口才能显示独立的技术或持仓标签。

### 6.5.3 信号卡与点位契约

卡片标题使用事实组合，例如“1H 区间突破｜4H 持仓扩张｜空头清算数据不足”。第一行用自然语言说明最值得关注的变化，然后按需展开以下字段：

- 身份与事件：代币、链/地址、价格市场、合约市场、规则版本、首次时间/价格、当前状态及数据时效。
- 技术证据：突破对象和周期、冻结的区间边界、收盘价、成交额倍数及基线、ATR；趋势背景独立展示。
- 合约证据：OI数量及美元值、1H/4H/24H变化、OI/流通市值及分母、费率周期/类型、基差、主动买卖与已观测清算；缺失和无合约分开。
- 链上与风险：市值口径、流动性/冲击、持币集中度与标签范围、合约风险、相反信号及缺失项。
- 图表与有效性：触发标记、确认标记、支撑阻力区、失效条件、有效期限。下一阻力是观察位置，不自动叫止盈或预期收益；没有可靠阻力就显示未知。

单个信号有“哪些条件成立、哪些未满足、什么会使它失效”。某来源缺字段不清空其他证据，也不计算一个虚假的完整度胜率。点位应与相应市场和当时可见K线绑定，不能用当前图表重算值覆盖旧事件。

**用于避免误判的四个情形：**

| 同时观察到 | 合理解释范围 | 还需什么证据 |
|---|---|---|
| 价格升、OI数量降 | 空头回补、去杠杆或其他平仓混合 | 清算方向、公开仓位变化、现货买压；可能处于逼空中段而非结束 |
| 价格升、OI数量升 | 新仓增加，可能新多、接力空单或套保 | 费率、成交方向与仓位样本；不能直接称“空头燃料增加” |
| 集中度高、费率负、价格不动 | 潜在结构，也可能长期做市/套保 | 解锁、借贷与现货头寸、持续观察；不得重复催促启动 |
| 合约先暴涨、现货不跟随 | 单场薄流动性、价格/预言机问题或短期失衡 | 跨场真实成交、标记价/指数价及来源状态；标记异常而非直接升级 |

**回放与前向验证：** 收集用户关注的历史案例，同时纳入“高集中但不涨”“负费率长期下跌”“一般牛市普涨”和失败启动的反例。按发生时的上市目录、供应与标签版本重放，避免用今天的持有人名单解释过去。历史 OI、盘口和仓位无法从 K 线恢复；买不到可信历史时，先持续保存快照，明确哪些特征尚不能回测。

指标至少包含：指定期限与涨幅事件的召回率、候选命中率、领先时间、误报/日、最大不利价格偏移、数据完整度及分资产/市场状态表现。事件定义和期限须先定，再评价；训练、调参和测试按时间分开。2倍/5倍/10倍等长尾结果可以事后分组研究，不能据此输出实时“几十倍概率”。

### 6.6 刷新频率与依赖建议

全市场基础指标建议30至60秒更新，重点池盘口与成交订阅 WebSocket，5至15秒聚合评估；持币与实体标签5至30分钟或事件触发更新，公开仓位按限额分层采样。频率是待压测目标，各来源独立计时；不把较慢的筹码快照伪装成秒级实时数据。

数据不足保留已能支持的信号：无持币数据可输出“衍生品拥挤”，无实际清算覆盖可输出“疑似回补”，不得升级成“高控盘确认”或“全市场空头已爆仓”。

## 7 技术指标、突破与形态扫描

### 7.1 指标取舍与工具

选型以数据可得、定义明确、非重复信息、无未来信息和可验证增量价值为标准。常用指标和漂亮图形不等于具有预测优势，确定第一版研究配置后仍要验证。

| 层次 | 第一版决定 | 作用及原因 |
|---|---|---|
| 价格结构 | 历史20/60根区间、已确认拐点和突破/回踩状态；平台另验证宽度和触及 | 直接回答突破哪里、哪里失效；参数是候选配置 |
| 量能 | 相对报价成交额：当前已收盘柱 / 前20根中位数 | 直接解释参与规模；保持同市场、周期、单位，基线为零则不可计算；明确区别采用均值的常见RVOL实现 |
| 波动尺度 | ATR14及ATR/价格 | 对不同币种比较波动，确定候选缓冲与事件评估尺度；不用于断言方向 |
| 趋势背景 | EMA20/50，可切换显示 | 辅助区分顺势与反弹；先不作为所有信号的硬门槛，EMA200仅在历史充足且验证有价值时扩展 |
| 合约状态 | OI基础数量变化、Funding/基差、可得清算和成交方向 | 解释持仓及支付压力；与技术事实独立，缺失则降级相应解释 |
| 相对持仓与承接 | 有来源的OI/流通市值、盘口/AMM可执行冲击、链上持币快照 | 为挤压假设提供背景，不从高比值直接推断操盘 |
| 候选扩展 | RSI14、ADX14、MACD、布林带、锚定VWAP、VPVR、Fibonacci | 初期可用于人工研究或实验；只有加入后显示独立增量价值才进入正式自动规则 |

RSI与MACD大都从同一价格序列派生；不把两者与EMA同时亮灯当作三份独立验证。ADX有滞后，锚定VWAP对锚点敏感，Fibonacci依赖拐点选择，都不因名称常见而列为必选。

标准数值优先复用Python + TA-Lib；市场结构和状态机采用明确规则，现成形态库先评估许可证、延迟与误识别。图表依靠Datafeed接入行情，后台保存统一信号快照，不依赖Pine脚本商店或图表当前视窗计算正式告警。既有Lightweight Charts方案与Charting Library运行验证记录分别保留；本次不把未验证的内置指标能力视为已实现。

**VPVR 的定位：可选人工分析工具。** 它描述当前可见时间范围内各价位的成交量。POC是最大成交价带，VAH/VAL为设定价值区边界；它不代表当前所有人的持仓成本，也不能辨认庄家。Up/Down颜色常基于K线方向估算，并非必然是主动买卖成交。

VPVR 会随缩放和拖动改变，不能直接拿用户可见区作为后台扫描规则。若以后验证成交量分布能改善信号，应定义固定或按既定事件锚定的计算区间，冻结分桶、价值区算法和触发时边界，用当时可见数据回放。较低周期OHLCV分配成交量属于估计，逐笔数据也仅覆盖所选市场；记录误差与缺失，不宣称全市场精确筹码图。截图的24行、70%只代表一组设置，不作为我们的默认科学参数。

### 7.2 K线口径、预热与扫描周期

P0扫描周期建议 1D、4H、1H，图表同时保留5m/15m。日K默认使用 UTC 00:00 开盘口径，UTC日线收盘对应北京时间次日08:00。1D代表一根自然日K线，不是滚动24小时。保留源端时间边界；不兼容来源需用同市场完整小周期数据重采样，或者明确标示不可比较。

现货日线用于现货结构，永续日线用于该合约结构，默认参考市场可切换。不同市场不拼成一条K线；CMC的聚合币价不能代替“某交易所某交易对的日线”。只能聚合同市场连续小周期K线，缺口不能填造OHLCV。

基础配置预热ATR14、EMA20/50和20根成交额基线；候选扩展另保存参数。递推指标需额外预热并验证收敛，不以刚达到指标周期长度视作稳定。扫描同一规则时固定数据起点策略、缺口处理和库版本；历史不足显示不可计算。

收盘型规则只使用截止评估时已经收盘且已收到的数据。跨周期信号也必须满足各自收盘时间，不能将当日尚未收盘的日线确认状态用于4H历史回放。每天扫描不需全天反复拉取完整历史，闭合时增量计算即可。

### 7.3 首版技术扫描清单

| 信号 | 判断要点 | 输出 |
|---|---|---|
| 20/60日区间突破 | 日线收盘超过此前N根最高价，加可选ATR缓冲 | 1D区间突破、压力价、缓冲与放量状态 |
| 横盘平台突破 | 先验证历史区间宽度、持续时间和多次触及，再判收盘越过平台上沿 | 平台突破；单纯创N日新高不自动称平台突破 |
| 趋势背景 | EMA20/50位置与斜率；独立于事件确认展示 | 描述方向，不把均线交叉自动当成交易机会 |
| 波动状态 | ATR/价格及既定区间宽度的历史变化 | 收缩或扩张事实，无方向；布林带为候选替代特征 |
| 突破后回踩 | 沿用首次突破时保存的压力区，观察随后K线回踩、收回或跌破 | 回踩观察、守住/失效；后续发生才更新 |
| 圆弧底 | 下行逐渐放缓、宽底、右侧修复、颈线压力及量能 | 圆弧底候选、接近颈线、颈线突破、失效 |

首版基础突破 P0；圆弧底以实验候选先交付，经案例验证后开启稳定告警。双底、头肩底、三角形/楔形、杯柄等后续逐种定义，不能把社区函数或库名当作验证完成。

### 7.4 “某代币1D突破”的具体规则示例

“1D突破”必须说明突破对象。首版先提供“20日高点”“60日高点”和“经识别的平台上沿”三种，可选放量过滤。

以20日高点为例，令 t 为最新已收盘日K：

```text
R_t = max(high[t-20], ..., high[t-1])
buffer_t = 0.25 × ATR14[t-1]
日线突破 = close[t] > R_t + buffer_t
放量倍数 = quote_volume[t] / median(quote_volume[t-20:t])
放量突破 = 日线突破 且 放量倍数 >= 1.5
```

20、0.25、14、1.5 均为演示配置，需回测与前向验证；历史20根必须已闭合且不包含 t。若量能缺失，可输出价格突破，但不能输出放量确认。可将“在均线上方”“跨市场跟随”作为可选筛选；OI不作为技术突破的必需字段。

示例：此前20日最高1.00 USDT、ATR14为0.08，确认门槛1.02；最新日K收1.04且成交额为历史中位数的1.8倍，则命中这条演示规则。盘中最高到1.08、最终收0.99，只能保留盘中预警及其撤销记录，不能确认日线突破。

生命周期：盘中预警（可选，允许撤回）→ 收盘确认 → 持续/回踩观察 → 失效/结束。确认后保存当时突破位、区间与缓冲，不能每日移动压力位来重写旧信号。新高持续期间不重复发送首次突破通知；重新形成独立区间或旧事件结束后才生成新事件。

### 7.5 圆弧底的识别方法

圆弧底是多根K线形成的结构，不能仅凭一条均线向上、一个二次函数拟合良好或MACD金叉判定。建议先在1D/4H上扫描40至120根已闭合K线的多个窗口，窗口长度仅作起始研究范围。

1. **形状候选：** 对数价格归一化后，检查左侧下行、底部变平、右侧上行；底部需要持续宽度，排除单根极端插针和V形急反弹。用稳健拟合及分段斜率辅助，保留拟合残差与原始图形。
2. **结构约束：** 底部深度、左右两侧持续时间、修复比例和中间反弹幅度需要在明确范围内；不强求完美左右对称。下跌中短暂反弹也可能呈U形，要用后续颈线状态区分。
3. **颈线/压力区：** 由截至发现时已经确认的左侧高点、历史密集阻力或箱体上沿定义；展示实际使用的边界和算法版本，禁止根据后续最高价倒推颈线。
4. **量能证据：** 左侧衰减、底部低量、右侧回升和突破放量分别标记，作为支持条件；缺量不能解释为已满足典型量价关系。
5. **状态更新：** 右侧尚未越过压力区只称“候选”；收盘越过颈线与缓冲后才标“圆弧底颈线突破”；随后跌破结构低点或满足预设失效条件时结束。

平滑、极值和支撑压力算法不得偷看未来。若高低点需要右侧k根确认，发现时间必须延迟k根；禁止用居中平滑或会回填历史转折的ZigZag结果冒充当时可见信号。保存 shape_start、shape_end、detected_at、confirmed_at、neckline、rule_version 和证据快照；回放中只能从 detected_at 起计告警表现。

形态候选可随新K线调整，但已发出的历史事件不覆盖。人工标注多种圆弧底和相似反例，分别评估“形状是否符合定义”和“突破后的价格表现”；形态匹配度不是上涨概率。

### 7.6 技术与资金信号结合

用户可选“技术独立”或“技术与资金交叉”。例如“1D平台突破 + 4H回踩守住”属于跨周期技术组合；“圆弧底颈线突破 + OI数量异常 + 持续负费率”属于技术与资金组合。每一项保留自己的状态、时间与来源，资金缺失不取消已满足的技术信号。

图表显示原始K线、已识别区间、水平压力区、突破K线、首次发现位置和失效位置，帮助用户判断误识别。圆弧轮廓可作辅助线，但必须同时显示真实价格，避免用平滑曲线掩盖不符合形态的波动。

### 7.7 历史相似形态：独立P1功能

历史相似区间搜索可先支持 BTC 和 ETH 的1h/4h/1D，再扩展其他币种；不限制前述技术扫描的币种范围。用户选择回看20或40根、观察后续10或20根，输入可包含归一化路径、波动、量能和指标，返回相似区间、相似度定义及后续分布。

候选的完整匹配窗口与后续窗口必须早于当时决策时间，并设置间隔避免与查询窗口重叠。训练、调参和测试按时间切分，处理下架与幸存者偏差。不把相似度直接称上涨概率；如提供统计概率，需注明样本数、统计方法和验证区间。

### 7.8 指标与正式信号的边界

指标是数值；标签是规则对数值的描述；信号是带时间、条件、点位和失效逻辑的事件；策略还需定义仓位、执行、费用和退出。四者不得混为一谈。“规则已确认”只表示可复算条件满足，不等于收益已经确认。

### 7.9 科学验证与启用门槛

1. 先写事件定义和评价期限。例如比较未来固定根数内是否先达到预定ATR目标还是失效线，同时报告最大有利/不利偏移。具体倍数和期限在实验前登记，不能在结果出来后换定义；同根K线同时触及目标和失效线时，用更细数据或保守记为顺序未知。
2. 建立最简基线：仅价格区间突破。逐次加入量能、趋势、OI、费率/清算、流动性及候选指标，对照相同资产、相同可见数据和相同事件期限，报告加入后误报、漏报、提前量和不利波动的变化。
3. 按时间做训练/调参/留出测试，重叠事件做隔离；覆盖震荡、涨跌、不同流动性及下架样本。不能用本轮Rising赢家的现有名单回测过去全市场，也不能用现在供应量解释过去OI比值。
4. 报告全样本数量、数据缺失、结果区间及所尝试配置数；检查是否只在少数币上有效。提高筛选后命中率的同时要报告覆盖和漏报，多个相关指标不得当作独立样本。
5. 独立测试后做连续前向观察，并保留失败样本；OI、盘口和清算没有历史就从现在记录，不能由K线编造历史。数据不足的扩展先停留在研究状态。
6. 决定是否保留指标看预先约定的增量价值及稳定性，不按指标数量或漂亮分数决定。未完成以上步骤前，所有组合均称研究规则；若输出模拟策略收益，还要计入滑点、手续费、资金费率及实际可成交性。

## 8 AI 与研究工具

Surf 需分成 Data API 与 Chat API 两种用途。Data API 可提供结构化持有人、地址标签、Hyperliquid 仓位和行情候选；Chat API 用于项目介绍、催化和解释。CMC、CoinGecko 等补充身份与供应数据。所有供应商进入相同质量检查，不能因为挂着 AI 名称就把结构化数据降为纯叙述，也不能把模型解释当作行情源。研究调用按需或事件触发，不对全市场每分钟调用大模型；输出附来源 URL 与时间，合约地址和官方账号先核验。

数值计算、阈值判断、去重、数据质量和权限控制由确定性代码完成。AI 服务故障时仍可查看雷达、K 线和历史告警。服务选择需核实官方 API 或 MCP、认证、配额、成本、商业展示权及结果保留规则。

## 9 架构与内部接口

建议采用 Next.js 前端，Python 异步采集和规则服务，PostgreSQL 保存归一行情、信号和审计记录；Redis 在有队列、缓存或限流协调需求时加入。时间序列扩展在数据量证明需要后再启用。前端 K 线采用成熟组件，避免首版自研图表引擎。

数据链路为“交易所与数据商适配器 → 原始数据缓存 → 身份与单位标准化 → 质量检查 → 特征计算 → 信号事件 → REST 与推送 → 网页”。原始指标与衍生特征保留来源血缘。单个来源故障不使整个列表停摆，切源后不能延续不可比较的增幅曲线。

| 内部接口示例 | 用途 |
|---|---|
| GET /v1/assets | 资产目录、身份和可用市场 |
| GET /v1/instruments | 交易对和合约规格 |
| GET /v1/radar | 信号列表及分页筛选 |
| GET /v1/candles | 指定来源、市场、周期和时间范围的 OHLCV |
| GET /v1/metrics | OI、资金费率、多空及主动买卖统计 |
| GET /v1/technicals | 指定市场和周期的标准指标、参数、有效历史长度 |

## 10 非功能要求和成本控制

新鲜度目标为：K 线收盘后 90 秒内完成正常来源的信号评估；网页读取缓存的 P95 响应在目标部署环境下小于 1 秒。目标须通过真实部署测量，接口限流和来源中断期间展示降级状态，不假装满足 SLA。

价格与成交量优先批量或 WebSocket，按字段单独调度 OI、资金费率、身份元数据和 AI。采用每来源独立的权重预算、指数退避、抖动、失败隔离与恢复补数。先为观察池和高流动性标的分配刷新预算，不能为追求速度绕过上游限额。

敏感 API Key 仅在服务端管理，日志和浏览器响应不得包含密钥。读取公开行情与交易执行权限分离。用户可导出或删除自己的收藏、备注和通知设置。公开提供服务前核实行情再分发、缓存和商业展示许可。

预算模型至少包含行情请求与订阅、历史存储、计算服务、AI 查询、通知及运维。免费优先方案先使用 Binance/OKX/Gate/Bitget、Hyperliquid、Aster 的公共接口并自建历史快照，CMC Keyless、Coinalyze、Surf 免费额度只做低频补充和研究验证。每源按“标的数 × 端点数 × 刷新次数 × 权重”估算，不能用一个固定调用数覆盖所有接口。付费服务先做小额度试用和月度上限，再扩大覆盖；免费接口也必须记录共享配额、限流和再分发条款。

## 11 验收条件

| 场景 | 通过条件 |
|---|---|
| 同名资产及合约乘数 | 同名不同合约不合并，1000 倍面值合约能正确换算并展示原单位 |
| K 线来源 | 抽检至少 3 资产、2 来源、3 周期的已闭合 K 线，与对应原始来源一致 |
| 未闭合 K 线 | 实时柱变动不会重写已确认历史告警，收盘型规则不会提前确认 |
| OI 和资金费率 | 张数、币数和名义价值转换有样例；不同结算周期明确标注 |
| OI 相对流通价值 | 流通市值、有效流通估值、OI/市值、历史分位数的分母和来源可追溯；高比例但无方向证据只能提示杠杆压力 |
| 可选成交量分布 | 缩放视窗不改变已保存信号；固定范围、估计方法及市场覆盖可复算，未启用该工具不阻断基础雷达 |
| 数据缺失和断线 | 停止依赖缺失字段的确认，保留历史；恢复后按时间补齐并去重 |
| 跨源切换 | 价格和 K 线来源同时切换，不能把不同市场的价格差当作异动 |
| 告警持久化 | 刷新、进程重启和重复输入不重复发送首次告警；首次价格保持不变 |
| 冷却和升级 | 普通重复被冷却，升级或风险变化仅生成一条对应通知 |
| 历史统计 | 全部信号进入分母，未到期与缺失单列，禁止展示只选赢家的结果 |
| AI 降级 | AI 失败不影响行情、评分、K 线和告警；摘要有可打开的来源 |
| 成本与负载 | 目标标的池运行 7 天，无持续超限，来源覆盖及延迟可审计 |
| Perp DEX 范围 | Hyperliquid dex namespace 与 Aster 产品/API 版本正确，未覆盖市场明确显示 |
| 仓位可见性 | 已知地址样本不冒充全市场；Aster私密/授权数据不展示成公开数据 |
| 筹码证据 | 用交易所托管、桥接、锁仓及地址拆分案例检查集中度误判；原始值与调整值均可追溯 |
| 深度与清算 | 不足价带深度不填0；快照清算不称全量成交；估算清算与真实事件分开显示 |
| 逼空误报 | 负费率套保、上涨OI下降、单场异常等反例均有明确降级或解释 |
| 技术突破口径 | 当前K线不进入历史压力位/量能基线，日线时间边界可追溯，插针后收回不确认为收盘突破 |
| 指标可复现 | 固定OHLCV、参数、库版本和预热长度可复算；基础指标及每个已启用扩展有数值对照与容差 |
| 标签与验证 | 标签能映射到数值、窗口、规则版本和失效条件；没有数据支撑的因果、概率和统一OI危险阈值不发布 |
| 增量效果 | 基线和新增指标在同一留出样本上比较，报告命中/漏报、覆盖、提前量、不利波动与成本；未验证规则明确标记 |
| 形态无未来信息 | 时间回放只用当时可见K线，极值确认延迟计入告警时间，旧信号不因新数据被重写 |
| 技术独立性 | 仅有合格K线但无OI/持币数据的资产，仍能产生技术突破信号 |
| 形态误识别 | V形反弹、单根插针、下跌中继和真实圆弧底样本分别评估，候选与突破确认分开计数 |

M2 告警与复盘完成：持久去重、首次价格、推送、事件历史和成熟样本统计通过验收；对照随机基准、流动性基准和市场状态分组评估。

M3 扩展完成：根据用户价值、覆盖增量和实际账单，扩大交易所与链上候选池、仓位索引、历史形态匹配和研究工具。每次扩展都独立验证数据口径和许可证。
